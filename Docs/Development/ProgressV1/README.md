# 全体進捗監査V1

`index.html` は `progress.json` と基本設計60枠から生成する全体進捗表。接続状態は製品完成度ではない。各行の根拠は実装・検証記録を手動照合した一次監査であり、全機能の今回の再試験ではない。

## 完成条件

1. 基本設計60枠・15分野・受入計画170ケースの対応が欠けない。
2. 各行に現在・残り・実在する根拠がある。
3. 元の設計とゲーム入力のハッシュが一致し、ゲームを変更しない。
4. HTMLの絞込みと大小画面を実ブラウザで確認する。

## 更新規則

機能実装の完了時は対応するBD行の現在・残り・根拠を更新する。小修正を新しい大項目として追加しない。通常入口への接続・独立試作・関連基盤・設計のみを分ける。製品受入完了は別途根拠が必要。件数を工数割合や完成率として表示しない。

ゲーム入力変更後は監査の証拠を取り直す。既存SupplyWorkV1の全面ハッシュ検査は当時の管理文書も固定しているため、今回の管理文書追記後にその全面一致を主張しない。本監査は実行入力の部分集合を別検証する。Core/GPU再実行は今回行わず、直前工程の限定された証拠と明示する。

次の優先作業は地域一巡の3枠。全国の製品範囲を縮小しない。主要な未実装14枠の全体残件も毎回この表へ戻して管理する。
