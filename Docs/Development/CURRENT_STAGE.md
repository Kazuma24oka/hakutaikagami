# 現在段階：委任配送の再送基盤

## 完成条件（実装前固定）

1. 共通MessageFlow.Retryを使い、本人が物理的な不達報告を受領した直近試行だけを再送する。本文/業務ID/3回上限を保持し、未知の真の所在地は参照しない。
2. 再送試行にも実経路・発送元・宛先を結び、同じ失敗試行の再操作は二重送信しない。成功した試行の発送元を返書先に用いる。
3. 失敗報告自体の不達、上限、重複、途中保存・復旧・続行をCoreで検査し、既存のGodot表示・保存比較を再検証する。UI照会は次の小工程と区別する。
4. 検証をソース/実行物へ結び、同じブランチへcommit/pushする。

## 次の五段階

1. 再送の実経路と返書先（今回）。
2. 指定先への物理照会・返報不達回復・中断理由申告。
3. 継続的な仕官/解任と人生継続。
4. 一人分プレイの通し検査と操作整理。
5. 史実開始/全国人物・権限の段階採録。

## 検証結果

完成条件4/4。全1159件、49実GPU、196保存比較+3素材寿命比較は差分0。再送追加15件。検査手順の通常保存ボタン漏れを修正し、失敗原記録をharness-correction.jsonへ分離。照会・返報側再送・中断理由は未実装。
