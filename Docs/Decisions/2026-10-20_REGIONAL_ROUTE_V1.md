# 尾張の実在拠点と移動・保存復旧 V1

ユーザー指示：一地域の実在拠点と経路を移動につなぎ、保存復旧後も位置と3D表示が一致することを実行確認。同じprototype/godot-foundationへコミット・プッシュ。

## 地理・歴史・係数の境界

愛知県「あいち歴史観光・善照寺砦」https://rekishi-kanko.pref.aichi.jp/place/place5.html で清須城→熱田神宮→善照寺砦の通過順を確認。名古屋市「中区で辿る織田信長」https://www.city.nagoya.jp/naka/miryoku/1021146/1033230/1049391.html で熱田社との関係を照合した。

Wikidata CC0のQ1357421／Q482065／Q11418956のP625と改訂・元精度を固定。座標は現代代表点であり当時の城域・参道端点ではない。カタログはCore/Data/owari-route-v1.json。原取得スナップショットはruntime-local/sources、SHAはsource-manifest.json。Scripts/build_regional_catalog.pyからオフライン再抽出できる。

道路の細かな線形は未確認のため、実在拠点を直線で結ぶ概略経路として明示。川・橋・高低差・当時の海岸を復元したものではない。R6371000mのhaversineによる拠点間大円距離11,654.560m＋6,683.132mは道路実長の下限参考値。表示用投影から距離を流用しない。

徒歩1m/s・使者2m/sは試作係数。区間ごと秒を切上げ、徒歩18,339秒、配送1秒、出発1秒→到着18,340秒、返報9,170秒→受領27,510秒。史実の行軍時間を主張しない。書役の委任は別任務で同時進行。人物・主家・権限・資源は検証設定であり、1560年の史実所属の採用ではない。

## Coreと保存

新ruleset owari-geographic-corridor-v1、world schema1。旧RouteContractの静的な120m経路は維持し、シナリオに応じた形状・距離・版を渡す。共通時計・配送・任務・効果台帳・世代保存を再利用。DefinitionPackにカタログ全内容と投影名のハッシュを固定し、別シナリオ・旧保存・変更座標を自動移行しない。

site:castle＝清洲城、site:atsuta＝熱田神宮、site:village＝善照寺砦はこの新シナリオだけの明示的なID束縛。旧世界を読み替えない。熱田はこの一連移動の通過点。任意の目的地・逆方向移動・帰路は未実装。到着後の新しい出発命令を、原点へ瞬間移動して再開する入力として受理しない。

描画は本人向けRouteActorViewと公開経路から生成。他人の生位置は渡さない。主君視点は主君本人の所在と届いた報告だけを表示。カメラは全国・尾張・本人近景を同じワールドで見る。原点を本人位置へ移し、長区間は倍精度で可視範囲へ切ってからfloat化。区間全体を近景で描いた際の端の画素差と、線による人物の遮蔽を修正した。

保存は既存SavePresentationの小数秒位相・速度を含む。復旧直後停止。カメラの回転・ズーム自体のセーブは対象外。画素比較は同一の12m視点。通常Mainは置換しない。

## 実測

Windows / Godot4.5.2.NET / .NET SDK10.0.302 / RTX4060Ti/OpenGL互換描画 / 1400×1000。ビルド警告0・エラー0。Core506件（既存488＋新18）。経路長と全国座標の一致、曲がり角の秒丸め、偽造入力・版変更拒否、主君への秘密位置非開示、返報遅延、重複リプレイの二重効果防止を含む。

実Godot26検査、2プロセス、27画像。前半1001秒／熱田通過11656秒／後半12656秒／到着18340秒を保存。同一プロセス4復旧、別プロセス4復旧と4続行、合計12比較で3D領域差分0画素。6連続描画フレームと自動時計の1秒コミットも確認。

コード・DLL・カタログ・モデル・画像SHAと自己画像レビューを検査。画像とモデルは権利整理までruntime-localのみ。過去のbindingを新コードへ転用しない。自己確認はユーザーの画面採用ではない。
