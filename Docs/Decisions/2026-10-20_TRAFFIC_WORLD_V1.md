# 通行止め・運休と本人判断の競合 V1

## 採用した操作規則

全国の本人移動に通行条件の競合処理を追加。入口Scripts/Show-TrafficWorld.ps1。-Case road / detour / port / sailedを選べる。条件の発生・解除は試作の合成日程であり、史実の通行止めや実在の船便ではない。

通行止めは区間へ入るときに現地確認し、本人が知る封鎖だけで迂回を探す。迂回できれば通過済み区間を保持して続行。出口がすべて塞がっていれば、その拠点にAtSiteで移動を中止する。歩き始めた区間が後から閉じても、その区間の完歩を巻き戻さない。橋の崩壊など移動中の災害は今回対象外。

運休は港への到達から出航時刻ちょうどまで確認し、運休なら港で移動を中止する。出航後は洋上で停止・転送せず、現在の海上区間の到着港まで進む。出航1秒前の本人の取りやめは従来どおり可能で、その後の運休で同じ任務を二重停止しない。

同じ世界秒では、通行条件の更新→本人の行先変更の効力→現地の進入・出航確認→既存の配送・完了処理の順。新行先を確定した直後にその道が閉じても、本人の判断履歴を巻き戻さず、迂回またはその拠点で停止する。

再開しても自動で動き出さない。「この拠点の道・便を確認」で再開を知り、行先を選び直して出発する。再開を知らない間は古い封鎖情報を勝手に消さない。新しい旅では乗船準備300秒＋次の毎時便という既存の試作規則を新たに計算する。元の任務は中止履歴として保存する。

## 配送・秘匿・保存

使者も出航前なら運休を受けて港で配送失敗となり、失敗報告を物理的に返す。返し先は原発送地点の既知住所で、移動した差出人の現在位置を追跡しない。乗船済みの使者と途中の部分海路は巻き戻さない。遠隔地の主君が失敗や封鎖を知るのは報告の受領後。本人の計画・表示には未来の条件や未観測の閉鎖を直接渡さない。

独立ruleset national-traffic-conflicts-v1 / world:national-traffic-conflicts-v1。schema2へTrafficStopsを任意拡張し、この新規則だけ必須、他規則では存在を拒否し省略する。既存CouriersのRoadCondition履歴を陸路の閉鎖・海路の運休として共用し、別時計や配送シミュレータを作らない。停止任務・本人・区間・拠点・世界秒・理由を保存し、停止時の真実・現地目撃・境界時刻・中止状態・現在地点・次の旅の出発地と照合する。旧保存は読み替えない。

通常Main・main・design/foundation・Confirmedは変更しない。既存の未追跡2D素材も保持。共通ソース変更により旧試作のbindingは再検証まで失効する。
