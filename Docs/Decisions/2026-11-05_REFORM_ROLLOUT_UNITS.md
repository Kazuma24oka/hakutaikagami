- 採用日：2026-11-05（日本時間）。
- 根拠：ユーザーが「一部の国衆が改革を拒んでも、条件が整った地域から進める」A案を明示採用。
- 管理先：既存 G-H3（改革の案件）、BD-50。組織決定は BD-49、権限は BD-10、違反は BD-42、実行・認識・NPCは既存の共通原則へ接続する。

- 状態：設計採用済み、ゲーム実装は未完了。基本設計の60枠・受入計画170件・見積り・現在工程を変更しない。

## 1 採用内容

同じ改革案件でも、既存の権限・組織規則・契約に照らして必要な手続きと条件が整い、他の部分から独立して成立・実施できる範囲から進める。未成立の家・地域・条項は交渉・判断待ちとして残し、別の範囲を一律に停止させない。

この既定値よりも、明示された一括成立条件や切り離せない交換条件を優先する。家ごとの賛否を単純に数えて、全国・勢力全体を一斉に変更する方式にはしない。

### 守る境界

1. **成立単位は権限と条件で定める。** 対象の家・地域・条項を区分できるが、同じ法の既存の適用範囲や組織規則を、分割の操作だけで書き換えない。
2. **毎回全員の個別同意は要らない。** 権限内の決裁や適正に成立した合議で足りる場合は、その手続きに従う。反対した人物を、それだけで有効な家法の対象から除外しない。
3. **自治を縮めるには該当する改定が必要。** 甲家との合意で乙家の契約や留保された自治を変更しない。乙家が改定案を拒んでも、旧契約違反に自動変換しない。
4. **交換条件は束で扱う。** 「城を壊す代わりに代替地を渡す」などは、関連する条件を同じ合意に残す。一方だけを切り離した別案として有利な権利を取得できたことにしない。実物の引渡しや城割りを瞬間・同時完了にはせず、合意した履行順序と未履行の義務を保持する。
5. **成立・発効・通知・実施・完了確認を分ける。** 発効時点は対象の制度・条項・手続きに従い、今回一律に「全員への通知後」などへ変更しない。承諾の発送だけを成立、命令の発送だけを実施完了にしない。
6. **既存の負担と実物を維持する。** 未改定の範囲には既存の有効な条件が残る。役人・兵・米・予算を複数の実施単位へ二重に割り当てず、移動と実作業の時間を通す。
7. **拒否と処遇は別の判断。** 交渉継続・条件変更・延期・権限に基づく解任・越権の試行や実力行使は区別し、自動処罰・離反・開戦にしない。合法性と物理的な実行可能性を混同しない。
8. **原本・版を残す。** 対象や条件を変更した案は新しい版として扱い、以前の承諾を内容の違う案へ無断で流用しない。成立済みの範囲と、交渉中の範囲の版・原本を区別する。

## 2 遊べる一巡の具体例

検地を進めたい当主に、直轄領と二つの従属家があるとする。これは動作を確認するための架空の例であり、毛利家の特定の検地事例の再現ではない。

| 対象 | 条件 | 扱い |
|---|---|---|
| 直轄領 | 当主に検地の権限があり、必要な決裁が済んだ | 実施を手配できる。役人の配置・移動・現地作業は別に進む |
| 甲家 | 自治の変更を含む条件について、必要な契約改定が成立した | その改定の発効条件を満たしてから手配できる |
| 乙家 | 検地権限を自治として留保しており、改定交渉が不成立 | 既存条件を維持し、交渉継続・延期・案の変更などを選ぶ。甲家の承諾で乙家を変更しない |

当主は本人が受け取った返答を基に、直轄領と甲家の検地を役人へ任せる。現地の作業と返報を経て結果を知り、乙家への条件を考え直す。乙家が後で合意しても、実施済みの直轄領・甲家へ同じ費用と処理を二重に発生させない。

家中の様子（H1）には、土地・契約・調査済みの範囲の違いとして結果が残る。「集権度」の独立した点数や、研究完了による一斉効果を追加しない。

## 3 実装へ渡す情報の境界

型名や保存形式をここで固定せず、既存の契約原本・版・任務・配送・権限・本人認識を再利用する。

| 情報 | 必要な内容 |
|---|---|
| 改革案件 | 提案者、目的、対象範囲、提案の版、既存の関連案件・原本 |
| 成立・実施単位 | 家・地域・条項の範囲、権限根拠、必要な決裁・当事者合意、既存の自治留保 |
| 切り離せない条件 | 対応する交換条件、他単位との関係、明示された一括条件、履行順序 |
| 制度上の状態 | 各単位の交渉・成立・発効の記録。全体が成立したかと、各単位が成立したかを別にする |
| 実作業 | 担当者、実在資源の引当、移動、着手、途中結果、完了・中断。制度上の成立とは別 |
| 本人の認識 | 受領した返答・報告とその時点。未受領の返答・報告は「未確認」として扱い、隠れた承諾や拒否を漏らさない |

全体表示は各単位の状態から導き、部分的な成立・実施を案件全体の完了にしない。NPCも同じ権限・知識・資源の条件で、先行実施・交渉継続・延期を判断できることを対応工程の完成条件に含める。

### 対応工程へ割り当てる確認例

以下は既存の受入計画に割り当てる仕様確認例であり、170件への無断追加ではない。

1. **通常の一巡**：直轄領・甲家で手配から現地検地と返報まで進み、乙家は旧条件のまま交渉を続けられる。全部を完了扱いにしない。
2. **適用範囲と合議**：必要な合議で成立した家法の対象者を、反対票だけで除外しない。別家の自治縮小には、その家に必要な改定を確認する。
3. **交換条件**：代替地と城割りの条件を保持し、片方の合意だけで交換全体を成立させない。現実の履行途中・未履行は消さない。
4. **代表例外2件**：返答不達では当主に未確認の合意を表示しない。改定中の当主交代では、成立済み部分と未成立案、代表権、継続する家法を区別する。
5. **保存と再現**：一部実施・一部交渉中から保存再開して同じ未来になり、旧保存を無断で新規則へ読み替えない。再送・再開で効果や支出を二重化しない。

## 4 動画研究との関係と管理

- 問題意識の入口は、しかかく【戦国武将解説】の第十九話「井上衆誅殺事件」。出典・確認範囲・時刻の確度は [毛利元就動画研究台帳](../References/MORI_MOTONARI_RESEARCH.md) の M19 を参照する。
- **家・地域・条項ごとの段階導入は、動画の直接の説明として確認した事項ではなく、動画研究と既存仕様を接続したゲーム設計上の翻案である。** ユーザーのA案採用を仕様の根拠とする。
- 比較用のB案（一式で必要手続きをそろえることを標準とする案）は採用しない。ただし明示的な一括条件や交換条件を尊重することはA案の一部である。
- G-H3、統合案 H3、BD-50の残件へ追記し、重複する新機能IDや実装済みの記録を作らない。
- 資料のみの変更。コード・保存データ・素材・基本設計の原本・現在工程・進捗率は変更しない。Core全件・保存実動作・GUIの検査は未再実行。
