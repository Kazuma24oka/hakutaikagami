ユーザーは前段報告の次工程を「すすめて」と承認。分岐・通行条件・未知封鎖・迂回と途中保存復旧の実行検証を行う。同じprototype/godot-foundationへコミット・プッシュ。main／design/foundation／既存Confirmed／通常Mainを変更しない。

## 実装契約

新ruleset owari-geographic-branches-v1、world schema2。Core/Data/owari-branches-v1.jsonの座標・区間長・速度・出典・帰属・投影名をDefinitionPackの依存版へ固定。Branchesの既存旅程・閉鎖状態・証拠・MessageFlow・世代保存を使用。旧架空グラフと新地域を明示的に分け、旧保存を自動変換しない。

BranchRoutesは計画と配送に本人の証拠だけを使い、閉鎖の真実は区間入口での物理的目撃だけに使う。本人の予定経路・ETA・3Dへ事前に漏らさない。熱田11,656秒で目撃し、位置を変えずに笠寺・丹下へ計画変更。主君への封鎖報告は17,484秒、到着18,343秒、完了報告27,515秒。観測時刻と受領時刻を別々に保持。

両出口が閉じていた場合は、その時点の到達位置を確定して安全停止する。共通BranchRoutesで失敗直前の位置が前秒のまま残る不具合を修正。旧MovementControlの地形版は従来のBranchRoutes.Versionを維持し、型の一般化で暗黙に変えない。

描画はBranchViewと公開の地形・経路のみ。主君視点は主君本人の位置。黄色＝本人の計画、赤＝本人が知る封鎖、灰＝その他公開経路。重なる線は深度と縮尺に応じた高さを分けてちらつきを抑え、近景の武将を線が覆わないようにする。UIは地点名を表示する。

## 実測

Windows / Godot4.5.2.NET / .NET SDK10.0.302 / RTX4060Ti / OpenGL互換 / 1400×1050。ビルド警告0・エラー0。全Core525件、既存506＋新19。目撃前の全読取モデル一致・位置を保った経路変更・報告遅延・地理版拒否・重複再実行防止・全出口閉鎖時停止・旧地形版互換を検査。

実Godot25検査・4プロセス・19画像。封鎖あり／なしの目撃前を本人と主君で全画面比較し2組とも差分0。目撃前1001秒と迂回途中14656秒（表示位相.375）を同一・別プロセス復旧、各別プロセスから続行し、固定12m視点の3D6比較すべて差分0。復旧直後停止、同一ワールドを維持。4番目のプロセスは全出口閉鎖の安全停止。

Scripts/verify_regional_branches.pyでコード・カタログ・DLL・モデル・画像SHAを記録。実画像の自己確認をcheck_regional_branch_binding.pyで照合。画像・モデルはローカル限定。HTMLはPC／スマートフォン幅で検査。自己確認をユーザー採用に置換しない。
