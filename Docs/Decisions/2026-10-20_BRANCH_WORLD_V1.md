# 分岐経路・未知の封鎖・迂回V1

ユーザー指示に基づき、前段の一本道から分岐経路へ進める。同じprototype/godot-foundationで実装・実Godot検査・HTML報告・commit/pushを行う。mainとdesign/foundation、同期資料、原モデル、既存の旧検証画像は変更しない。

## 固定した契約

- `Core/Contracts/BranchRoutes.cs` が5地点・5区間の架空グラフを定義する。形状、mm距離、徒歩／使者のmm毎秒、区間ごとの切上げ、受渡し1秒、作業4秒、最短時間探索と同時間時の安定した並びを版ハッシュへ含める。数値は検証入力で、全国史実地理・製品係数ではない。
- 経路探索には、選択武将のKnowledgeに結び付くEvidenceのみを渡す。真実のBlockedEdgesを探索・予定時刻・色分け・3Dモデルに渡さない。実態を調べるのは、その区間へ物理的に入る地点に到達したときだけ。通行権等の制度的な禁止とは別の、物理的封鎖を扱う。
- 未知の峠封鎖でも、最初は平道40m＋峠80mの徒歩100秒を予定する。命令到達1秒後から歩き、21秒に分岐点へ到達して目撃した時点で東回りへ迂回。既に歩いた区間は保持し、残りの予定だけを変更する。到着予定は101秒から141秒になる。
- 分岐点での目撃は本人のEvidence／Knowledgeへ同時記録し、主君へは既存MessageFlowで配送する。観測21秒・受領31秒。主君の画面へ配下のライブ位置・到着予定は出さない。移動完了は141秒、本人の既知迂回路を使う返報配送70秒を経て、主君の完了認識は211秒。
- 世代保存には、閉鎖の実態、個人別証拠、歩いた区間と残りの経路、区間進捗、予約済み完了時刻、配送、表示小数秒を保持。新世界はSchema 2／Worldモジュール2。Schema 1ではBranchesを持たず、従来のシリアライズを維持する。旧保存を新グラフへ自動変換しない。新形式でBranches欠落・区間不整合・観測根拠なし・時刻不一致は、稼働セッションに入れる前に拒否する。
- 世界時計、命令状態、配送器、効果台帳、隔離Prepare／CommitLoadは既存のものを再利用。分岐点の時刻も同じAdvanceToの境界として処理し、大きな時間送りでも目撃を飛ばさない。新たな配送シミュレータや時計は設けない。

## 実装と検査

独立入口は `Game/Scenes/BranchWorldTrial.tscn` と `Scripts/Show-BranchWorld.ps1`。既存のOfficer3DCustomActorと同一骨格・素材・実測歩幅を使う。位置・次の表示補間位置・向き・経路・既知封鎖は、Coreが本人用BranchViewとして返し、表示側で経路判断を再実装しない。

全Core457件（前段428＋新29）、Godotの内部操作24検査、4つの独立プロセスで実行。GPU原本27枚（連続動作12枚を含む）。

- 封鎖あり／なしの20秒時点の本人画面、および封鎖報告前30秒の主君画面を全画素比較し、2比較とも差分0。
- 20秒の目撃前保存と51秒の迂回途中保存を別Godotプロセスで復旧し、認識・予定経路・位置・向き・動作位相・表示文言の一致を確認。
- 同一プロセス復旧、別プロセス復旧、目撃前から続行した迂回途中、終端の計6比較で3D描画領域の差分0。
- 迂回による期限超過は途中で停止し、原点や終点へ飛ばず、完了効果を作らない。入口自体が通れない場合も原点に留まり返報する。保存の途中経路、進捗、目撃証拠、Worldモジュール版の破損を拒否する。

根拠は `Docs/Design/BranchWorldV1/verification.json`。検査入口は `Scripts/verify_branch_world.py`、画像の自己確認後の起動条件は `Scripts/check_branch_binding.py`。入力、画像、実行DLL、元アセットが変われば失効させる。自己確認はユーザー承認ではない。画像・GLB・動画は従来方針によりruntime-localのみとし、HTMLからローカル参照する。

## 限界と次

地形は全員が既知の小規模グラフで、封鎖はこの試作の静的な実態。封鎖の解除・再発生、相反する報告の評価、通行権・天候・混雑、全国地理、大量経路探索、移動中の相手への追跡配送は未実施。通常Mainの新Core移行もまだ行っていない。旧RouteWorldV1のソースbindingは今回の共通コード更新で失効するため、以前の検証画像を新入力の確認済み画像へ読み替えない。

次の作業は移動中の命令変更・取消と安全な停止。完了条件は、配送と認識後に効力を発生させ、物理的位置を保持し、重複配送・保存復旧後も同じ結果と3D表示になること。
