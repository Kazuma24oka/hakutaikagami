# 尾張での道中取消・帰城変更 V1

ユーザーは続行を承認し、検証をHTMLにまとめる必要はないと指定。新HTMLは作成しない。同じprototype/godot-foundationへコミット・プッシュ。main／design/foundation／通常Main／同期原本は維持。

## 契約

新ruleset owari-movement-control-v1、world schema2／既存Branches・MessageFlow・世代保存を共用。地理・出典・改訂・速度・CC BYクレジットは前段のCore/Data/owari-branches-v1.jsonを保持。DefinitionPack.Versionに地理版と待合せ・効力・分岐変更規則を束縛。旧地域や架空グラフの保存を自動変換しない。

熱田での既知待合せを使用する。初期移動予定から熱田到達11656秒を算出。使者は清洲→熱田の概略距離と速度から最低5828秒が必要。配送到達は予定待合せ時刻と発送＋最低所要の大きい方。早着使者は待合せまで待つモデルであり、任意追跡や使者の3D移動を実装したものではない。

配送所要の算出に受令者の生位置・未知封鎖を使わない。到達時だけ実位置が熱田であるか照合し、相手が通過済みなら遠隔受領させない。失敗報告も5828秒の遅延で配送する。報告事務の既存書役IDを使うが、使者本人の位置・旅程は未モデル化。

例は5秒発送、11656秒受領、重要書状で全体停止。未開封本文は未知。11658秒開封でも効力は11660秒まで待つ。取消はその瞬間の現在位置に留まる。帰城変更は進行中の熱田→笠寺を15590秒まで完歩し、笠寺→熱田→清洲を通って31179秒到着。既知の通行条件で探索し、瞬間配置しない。

同時刻の取消は未確定の帰城変更・到着確定に優先。到着後に開封された命令は完了を巻き戻さない。同一命令の遅着原本と再送がともに届いても一回のみ実行する。現在地を保った停止／同一経路での帰城と、相手不在の受渡し失敗を区別する。

## 実測

Windows / Godot4.5.2.NET / .NET SDK10.0.302 / RTX4060Ti / OpenGL互換 / 1400×1100。ビルド警告0・エラー0、Core544件（既存525＋新19）。受領・開封・効力、遅着、再送重複、同時取消優先、将来の移動開始時刻、4段階保存後の経路・効果台帳・配送・物理結果の継続一致を確認。

実Godot40検査、4プロセス、26枚。取消・帰城変更それぞれ配送中1001秒／未開封11656秒／効力待ち11658秒／適用後11660秒を保存。表示位相を含め別プロセス復旧し、最後まで続行。復旧8比較＋続行8比較がすべて3D領域差分0画素。復旧直後は停止。同じワールドと公開経路を使用し、表示に渡すのは本人の知識・位置だけ。

Scripts/verify_regional_control.pyが実行・画像比較・ソース／DLL／素材SHAを記録し、check_regional_control_binding.pyで自己画像レビューと一致するか照合。自己確認はユーザー承認ではない。画像とモデルはローカルのみ。HTML報告は作成せず、最終結果は会話と機械可読記録に残す。

## 未実装と次

使者自身の所在・経路・3D、待合せ窓、任意地点への追跡配送、失敗後の受渡し再指定、任意の変更先は未実装。帰城変更は清洲に限定。地形・道路・橋は従来と同じ概略表現。

次は伝令自身の移動・待合せ失敗後の再送／再指定を地域に接続。相手の生位置を漏らさず、到達・失敗・返報と途中保存復旧が一致することを完了条件とする。
