## P0/P1の責任分界
| P0共通基盤 | P1コマンド層 | 例 |
|---|---|---|
| イベントID一意性・適用済み記録 | 要求ID・案件IDとの参照 | 徴税イベントを一度だけ確定 |
| 因果依存・同時刻競合 | 操作可否・制度固有の条件 | 解任と命令到達の境界を照合 |
| 数量整合・確定境界 | コマンドの見積・引当要求 | 木材の二重引当を防止 |
| 補償イベント・保存復旧 | 中断・再開・結果通知 | 返金補償失敗を表示 |
| 必要な乱数・未処理の復元 | 案件状態・認識の復元 | 密偵報告を再抽選しない |

## 確定済み原則・重複・矛盾
- F01/P0-A01：身分・役職・管轄・権限有効期間を分離。例：城主でも全軍指揮は無条件ではない。
- F02/P0-A02：共通時刻と因果・効力評価。例：同時刻の解任と命令を登録順だけで決めない。
- F03/P0-A04：会計・数量整合。例：米100俵を160俵引き当てない。
- F04/F07/F08/P0-A06：行動区分・本人認識・案件段階・配送・履行。例：密約成立と正式条約は別。
- 重複：3資料のID・状態・補償・保存は基本→例外→詳細という粒度差であり独立原則を増やさない。
- 直接的な基本原則矛盾なし。ただし要求IDの採番、禁止遷移、補償限度は未確定。自動進行＋任意停止も未確定。
- 新規独立基本原則は見つからないためConfirmedを変更しない。

## 依存順・残課題
1. **P0** イベント一意性・確定境界・同時刻裁定・乱数保存。例：二重徴税を防ぐ。
2. **P1** 要求・案件のID関連、権限と状態遷移表。例：援軍申請を受理しても出陣しない。
3. **P1** 費用・引当、再試行、補償失敗、通知。例：普請中断後に未使用材を返還。
4. **P1受入** 5分類×4立場、正常・異常・ロード再現性。例：再ロード後の米在庫が一致。
5. **P2候補** 高度AI・UI演出・詳細数値。例：通知表示の細部調整。
