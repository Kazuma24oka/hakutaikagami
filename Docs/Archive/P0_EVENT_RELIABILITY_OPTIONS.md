# P0イベント処理の信頼性：詳細ABC比較（5項目）

**状態：未確定（Proposals）／2026-10-17。** 5項目ともユーザーがB案を優先検討として選択済み。詳細・例外は未確定。既存F02・P0-A02/A04および[今回確定したR01〜R03](../Confirmed/P0_EVENT_RELIABILITY_PRINCIPLES.md)を前提とする。選択肢は**品質要件の実装方式**であり、A/Cには確定要件を満たさない例がある。

## ① イベントIDと同一性
- **A**：イベント種別と時刻だけで重複判定。
- **B（推奨）**：論理イベントごとに安定した一意IDを持たせ、再送と別イベントを区別。例：同じ徴税要求の再送は同じ処理と判断する。
- **C**：全イベントを毎回新規IDとして扱う。
- **保留**：ID生成・親子関係・保存範囲。

## ② 重複適用防止
- **A**：適用済みかどうかを確認せず再実行。
- **B（推奨）**：イベントIDと適用状態を記録し、再試行でも効果を一度だけ確定する。例：徴税済みの米をロード後に再徴収しない。
- **C**：重複時に後から帳簿を手作業で補正。
- **保留**：処理記録の保持期間・派生イベント・取消。

## ③ 同時刻の処理順序
- **A**：登録順だけで処理。
- **B（推奨）**：因果依存を先に解決し、独立イベントの競合は明示的な裁定規則へ委ねる。例：援軍と開城の成立条件を照合する。
- **C**：同時刻の先後を常に乱数で決める。
- **保留**：循環依存・タイブレーク・時刻精度。

## ④ 途中失敗と復旧
- **A**：途中までの状態をそのまま残す。
- **B（推奨）**：関連状態を整合する単位で確定し、失敗時は安全な再試行または補償で復旧。例：輸送中断で米が出庫元と到着先の双方に重複しない。
- **C**：失敗したイベントは無条件に成功扱い。
- **保留**：原子的更新範囲・補償の副作用・クラッシュ時点。

## ⑤ セーブ・ロード再現性
- **A**：世界時刻と武将状態だけを保存。
- **B（推奨）**：確定済み効果・未処理イベント・必要な乱数状態を保存し、再開後の進行整合性を保つ。例：同じセーブから再開して同じ確定イベントを再適用しない。
- **C**：ロード時に未処理イベントをすべて再抽選。
- **保留**：キュー形式・乱数シード・セーブ互換・分岐後の決定論。

## 横断整合性・重複・依存
- **既存Confirmed**：F02は共通世界時刻、P0-A02は因果・効力時点・依存関係、P0-A04は資源数量整合を規定。今回のR01〜R03は一意性・障害復旧・セーブ継続整合性の品質要件。基本原則の重複確定を避ける。
- **同時刻11項目**：イベントの候補収集・依存関係解決と矛盾しない。ただし循環依存と厳密な先後は未確定。
- **帰属11項目**：落城・独立・家督の複数状態更新が途中で止まっても二重移籍・二重徴収を生じさせない。
- **外交・情報**：書状の再配送と、条約締結・承認という論理イベントを区別する。再送自体は新しい配送イベントとなる場合があるが、元の締結を二重成立させない。
- **依存順**：論理イベントの同一性 → 適用状態 → 因果／競合処理 → 整合確定・失敗復旧 → セーブ再現性。
- **未決定**：イベントID生成・重複判定・トランザクション粒度・補償・循環依存・乱数管理・セーブ互換性。
- **判定**：B候補はConfirmedと基本整合。Bを選択しても詳細は正式確定しない。A/Cの一部はR01〜R03に反するため、そのまま採用するなら確定仕様変更の別途承認が必要。
