# 失敗報告の配送・遅着原本と再送分の重複到達：実測（2026-10-18）

**試作実装と検証結果。正式な配送制度・発見条件・再送方針・保存規格の確定ではない。** ユーザーの継続依頼に基づき、`prototype/godot-foundation` の `e054e3e8d223ad7fc60bc1b42cf6e2692e1898bd` から実装した。main、design/foundation、既存Confirmed、既存設計資料は変更せず、既存ファイルの削除・移動も行わない。

## 実装した動作

### 失敗報告そのものを配送

- 従来の即時認識APIを廃し、「失敗報告を発送」に変更。配送担当者が観測した失敗を発送し、到達後にだけ元の差出人へ失敗認識を登録する。
- FailureReportDeliveryに、報告ID・対象配送ID・報告者・受取人・コピー番号・発送時刻・到達予定・到達/紛失・試験用失敗予定を保持する。
- 同じ共通時刻で配送し、通常イベントと同じ適用済み集合とトランザクションで確定する。未到達の失敗報告も未処理数に含める。
- 失敗報告自身の紛失を設定できる。その場合、元の差出人は失敗を知らず、原命令の再送もできない。
- 観測済み内容の別コピーを配送担当者が明示的に再発送できる。コピーは試作用に3通まで。複数コピーが前後して到達しても、元の差出人の失敗認識は一度だけ登録する。

配送担当者による「元配送の失敗の発見」は、依然として試験入力。今回は仮武将3人目を配送担当者とする。発見AI、証拠・偽報、報告者の移動や距離、費用は未実装。報告の別コピーを送る操作は明示的な試験操作であり、失敗報告自身の紛失を全知的に判断して自動再送する処理ではない。

### 原本と再送分の到達を分離

- 紛失扱いだった原本に、将来の遅着イベントを一度だけ予約できる。履歴の初回失敗を保持したまま、遅着予定時刻と遅着済み状態を別に記録する。
- 物理的な配送試行IDとイベントIDは別々だが、要求ID・案件ID・論理メッセージIDを共有する。原本と再送分の双方を到達済みとして記録できる。
- 受領時は、同じ要求・種類の論理認識が既に存在するか判定する。2通目以降は物理的受領だけを記録し、認識・NPC判断・乱数抽選・資源引当・徴収・結果報告を新規発行しない。
- 原本が先着、同時到達、再送分が先着する条件を、命令と結果報告の両方で試験した。
- 原本が届いた後に古い失敗報告が到達しても、既に到達した命令を再送できない。取消した未確定命令については、予約済みの遅着と再送も取消す。

[情報システム](../Confirmed/INFORMATION_SYSTEM.md)の真実・配送・本人認識の分離と、[イベント信頼性](../Confirmed/P0_EVENT_RELIABILITY_PRINCIPLES.md)の安定ID・一度だけの確定・保存継続整合を維持する。

## 保存v3と互換性

- 失敗報告配送、遅着予定/完了、適用済みID、個人認識、未処理処理、乱数状態を保存。論理認識のキーと抽選記録の一意性も検査する。
- v1・v2はv3へメモリ内移行する。変更前の実コードが生成したv2固定セーブ8件（5つの通常境界、紛失、失敗認識済み、再送中）を追加した。従来のv1固定セーブ5件も保持する。
- 旧v2で既に認識済みだった失敗は、MigrationOrigin=2とLegacyImportedにより過去の記憶として維持する。存在しなかった報告配送を捏造して追加しない。新規の失敗認識は実際に到達した報告を必須とする。
- v3の保存先は `user://tax-prototype-v3.json`。v3がない場合のみv2、次いでv1を読み込み候補にする。新規保存はv3へ行い、以前の保存ファイルを削除・上書きしない。存在する新しい版の保存が破損しているときは、古い保存へ無言で巻き戻さない。
- 試験は `user://late-smoke-<GUID>.json` 等の専用ファイルを使い、通常保存に触れない。

### 描画ありGUI試験の実シナリオ

1. 時刻1：命令原本を紛失。失敗報告を発送・保存し、到達前の保存へ戻すと再送不可であることを確認。
2. 時刻2：失敗報告到達。原本を時刻6に遅着予約し、命令を再送。再送中の保存へ戻して再開。
3. 時刻3〜5：再送分が到達、NPCが判断、60俵を徴収。蔵の米160。
4. 時刻6：命令原本が遅着し、結果報告は紛失。原本到達でも命令認識は1件のまま。
5. 時刻7〜8：結果報告の失敗報告も一度紛失。差出人は未認識・再送不可。別コピーが到達後、結果報告を再送し、原本を時刻12へ遅着予約。
6. 時刻9〜12：保存地点へ戻して結果報告の再送を再開。再送分、次いで原本が到達しても、結果認識は1件。

最終実測：**物理到達4、遅着2、命令認識1、NPC判断1、徴収60を1回、結果認識1、失敗報告到達2/紛失1、保存読込3、未処理0、蔵の米160**。ログは `LATE_DUPLICATE_GUI_PASS` を出力した。
