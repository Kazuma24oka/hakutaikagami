# 武将3D試作V1：固定条件と実行結果

2026-10-19。「推奨でいい。すすめて」により、OFFICER_3D_OPTIONS.mdの全Aを採用。立ち絵は2Dイラスト、ゲーム内人物は3Dとする。以下は最初の一体の入出力・制御の技術検証であり、顔型・髪・髭の交換素材や量産対応、LODの完成ではない。

## 固定した入力と所属

`Art/Officer3D/TrialV1/contract.json`が部品所属・骨格・動作・色空間・出力条件の正本。原本v013のSHA、契約SHA、制作／実行コードSHAを`plans/export.json`、`plans/runtime.json`で固定する。`Scripts/officer3d_pipeline.py`が不一致を拒否する。制作と実行の計画を分け、実行側の修正だけで材質を再生成しない。選択、寸法一致、ファイル存在、機械試験の合格を外見承認の代わりにしない。

元.blendは保存しない。Armature一つ、73骨、274個の採用メッシュのみを対象とし、参照用リグ・旧版・床・カメラ・プレビュー用の長い動作は除外する。ゲーム用はメートル／Y上／モデル+Z前、頂点あたり4ウェイト。待機・歩行・斬撃の3クリップを30fpsで採取し、Rootの平面移動は除く。体の揺れと、表示ノード／Coreが管理する移動は区別する。攻撃映像からダメージや世界時間を進めない。

装備は面頬、刀、下衣・袴、マント、兜、胴、喉輪、肩、籠手、履物、草摺、佩楯、脛当の13区分。元の重みと骨格を使い、区分内だけを結合する。装備なしの体は元Bodyの全ポリゴンを保持して分割する。露出部分だけ残す元のMASKはゲーム用体に適用しない。被覆関係は契約と出力記録に明示する。ただし単一装備内の穴や境界の適合は、実画面でも確認し量産時に調整する。

## 色と外見保存

肌は色の近さで判別せず、元のBody/FaceのSKIN材質2つだけを明示指定する。両方へ同じ線形RGBを設定し、元テクスチャ×指定肌色÷元の基準肌色で扱う。画面のRGB指定はsRGBから線形へ変換する。目・眉・口・アイラインは保護材質、装備は別の材質。全方向は同じメッシュ・材質で描画し、方向別の画像を生成しない。

装備色は全体色×部位色の乗算。黒を白に置き換える機能ではない。元の手続き材質は結合前の座標で基本色・金属度・粗さ・接線法線を2048pxのアトラスへベイクする。Godotでは専用シェーダーから読む。元MToon／輪郭線の完全一致を宣言しない。

外見はschema/model/body/face/hairのID、肌の線形RGB、装備のsRGB、13区分の有効状態と色をJSON保存する。未対応ID・版・不正色を拒否する。現時点で顔はv013一種類、髪はnone_under_helmet。素材がない選択肢を対応済みにはしない。テスト用保存は通常保存とは別のファイルを使う。

## 再実行

ローカル素材があるこのPCでは`Scripts/Show-Officer3DTrial.ps1`で固定入力検査・ビルド・読込後に操作画面を開く。`-ValidateOnly`ではGPU検査と別Godotプロセスでの保存復旧検査を実行する。マウス・OS入力を自動操作しない。通常のMainとCoreは変更せず、独立した`Game/Scenes/Officer3DReview.tscn`を使う。

最初の出力はBlenderを`--background --disable-autoexec`で元.blendと`Scripts/export_officer3d_trial.py`に対して実行する。埋込スクリプトを実行しない。元ファイルと参照入力の場所が変わったら計画を改版し、再検査する。出力だけをコピーして旧SHAの検査結果を流用しない。

## 実測結果

- Blender 5.2.2 LTS → GLB → Godot 4.5.2 .NET。SDK10.0.302／target net8.0、実行時.NET 10.0.10。C#ビルドは警告0・エラー0。
- 出力：21メッシュ、73骨、13装備区分、待機・歩行・斬撃3クリップ、1,013,598三角形、78,482,800byte。GLB SHA256 `2112b732afee0534777f3460b3b09ef287e5a3224fe5ce31ec83547aad62a44a`。
- 185部品の加工確定で頂点位置・UV・トポロジー・重みが一致。元Bodyの10,934面は7区分の合計と一致し、全OFFでも元の体の面を欠落させない。原本.blend／動画は開始前SHAと一致。
- GPU実描画90枚をSHAで記録。装備あり／なし各4方向で、肌設定が顔と体へ作用し、描画された肌以外のRGB差分0画素。既定肌色では4方向とも全チャンネルのクリップ0画素。
- 全体装備色と胴だけの色指定で、対象外のRGB差分0画素。13部位すべての材質独立とUI着脱信号を検査。単独OFFの待機・歩行26枚、全OFFと全復帰を確認。
- 肌テクスチャ内に口線が描かれていたため、材質名による除外だけでは不足すると判明。元RGBAのSHAへ固定したUV定義と、口線の色成分／下地の分離を実装。専用GPU面で口線の不透明部分のRGB不変と、肌色の線形演算→sRGB出力を数値検査（8bit量子化を含め2/255未満）。保護対象外への色漏れは許容差なしで0画素。
- 待機・歩行・斬撃の骨変化、Root平面移動0、通常／1/4速度、斬撃完了から待機への復帰を確認。外見保存は新しい個体と別Godotプロセスで復旧一致。武将同士の材質実体も独立。
- Core既存テスト233件合格。制作ゲートの変更拒否4テスト合格。実画像確認記録がない状態の表示拒否も確認。
- マウス・OS入力・カーソル設定の操作は行っていない。Core／Confirmed／main／design/foundationを変更していない。

RTX4060Ti、1280×800、Compatibility/OpenGL3.3、VSyncとFPS制限なし、UI非表示、指向性ライトの影あり、自動LOD無効。15フレームの準備後、60フレームの区間平均。世界シミュレーションを含む製品性能ではない。

実画像比較はローカルの`Art/Officer3D/TrialV1/runtime-local/review.html`。`visual-review.json`は自己検査であり、ユーザーの外見承認ではない。全8192通りの装備組合せや足滑りの定量検証は未実施。

### 今回捕捉・修正した問題

日本語表示環境で既定ノード名による取得が失敗したため、ノード種別による取得へ変更した。また、加工前の部品を結合すると、先頭部品の細分化／厚み／ベベルが結合全体へ再適用される問題を捕捉した。各部品のレンダー相当のREST評価形状を先に固定し、位置・UV・重み一致を検査してから結合する方式へ修正した。修正後の出力全体はキャッシュ再利用で12.66秒、GLB出力部分は約3.8秒。

既存ベイクの流用は無条件に行わず、元データ・UV処理コード・設定の一致、および独立した基本色の再計算がPNG全体のSHAで完全一致した記録へ固定した。失敗／中断した出力コードと計画はhistoryに保存。キャッシュが失われた場合は、固定入力を準備して新しい出力計画で再ベイクする。

CompatibilityはsRGB出力となるため、専用シェーダーはレンダラーに応じた線形／sRGB変換を明示する。[Godot4.5 Spatial shader公式仕様](https://docs.godotengine.org/en/4.5/tutorials/shaders/shader_reference/spatial_shader.html)。Forward+での実機検証は未実施。
