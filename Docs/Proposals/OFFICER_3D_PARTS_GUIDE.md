# 3D武将部品を増やすときの固定手順

2026-10-19。第3試作の制作規則。Confirmedのゲーム仕様ではなく、実装に対応した制作・検査手順。

## 入口

契約は `Art/Officer3D/TrialV3/contract.json`、制作コードは `Scripts/build_officer3d_v3.py`、Godot側は `Officer3DCustomActor`。起動は `Scripts/Show-Officer3DV3.ps1`。既存V1/V2は比較用に残す。

画像生成AIを使わず、固定した元メッシュ・寸法・パレット・骨格からBlenderで部品を構築する。同一環境で3出力のSHAが一致する再生成試験を必須にする。異なるBlender版、GPU、OSでも必ずバイト一致するという意味ではない。

## 座標と部品

原点・単位・前方向・73本の骨名・REST姿勢・取付・元3動作は契約を継承する。元.blend/動画とV1/V2資産を上書きしない。新部品はRESTで作り、必要なBevel等を部品単位で確定してから既存骨の重みへ対応付ける。複数部品を結合した後に先頭の加工スタックを全体へ適用しない。

13スロットは面頬、刀、下衣、陣羽織、兜、胴、首、肩、腕、履物、腰、腿、脛。V3の別具足はこのうち10スロットで交換可能。刀・下衣・陣羽織は共通素材。新しい刀等を制作済みと扱わない。表示しないことと部品IDの変更は別に保存する。

顔2種、結い髪1種、短髭1種。兜を着けると髪、面頬を着けると髭を覆い、外せば元の選択へ戻す。髪は顔メッシュだけでなく、体メッシュ内の後頭部も参照する。頭皮・顔・髪・髭は接触面を共通形状に保ち、LODごとの独立簡略化をしない。今回この規則で遠LODの頭皮露出を修正した。装備の近中遠形状は切り替えても、骨格・動作時刻・外見IDを変えない。

頂点は有限値、重みは非負・合計1±0.001・最大4本・骨番号73未満。頂点グループを消すと重みも失うため、低LODメッシュの移植は名前と重みを退避・再設定し、出力を再検査する。

## 色と保護

肌は顔・体・耳・手で共通の線形RGB。目・眉・口・髪・装備は肌の変更から保護する。元のSKIN材質に含まれる口線はUV・色成分の保護を継承し、材質名だけで判断しない。

布・漆・金属は意味のある材質IDで分離する。元銀具足はV2マスク、新赤具足は部品ごとの明示したカテゴリを使う。新形状へ元法線マップを無条件に流用しない。新素材の基本色は契約のHEXから線形変換し、UIは元色に対するsRGB乗算色。UIの白は「基本色を保持」。肌の色指定は乗算ではなく共通肌色を指定する。

新しい武将を増やす場合も、メッシュは共有し、変更するShaderMaterialは個体ごとに分離する。他個体のJSONが不変だけでなく、実際の材質の色パラメーターも変わらないことを検査する。

## 変更から確認まで

1. 資料を実画像で確認し、元資料・契約・制作コードのSHAをexport-planへ固定する。既存の計画だけを書き換えて古い結果を使い回さない。
2. 制作コードを実行し、近中遠を出力。元動作のsamplerを骨名で移し、長さ・姿勢をGodotで比較する。
3. `Scripts/test_officer3d_v3_repro.py <repo>` で別出力先への再生成を比較する。
4. 既存Godotプレビューを終了し、`Scripts/validate_officer3d_v3.py <repo> --bind`。ビルド、再取込、実GPU、全周・LOD・3動作・着脱・色領域外変化0・保存復旧・混成1/10/50体を実行する。試験は専用保存先で行う。
5. `Scripts/review_officer3d_v3.py <repo>`。原本SHAを確認した画像だけから比較表と動作GIFを作り、原本・派生を区別して実画像を点検する。画像確認結果を `visual-review.json` に現行計画と証拠SHA付きで記録する。スクリプトは外見の合否を自動承認しない。
6. Core回帰・依存変更時の失効試験を通し、数値・画像上の限界・未検査の組合せを報告する。自己点検とユーザー採用を混同しない。

## 保存とゲームとの境界

通常は `user://officer3d-v3-roster.json` に1〜64人の名前・ID・外見を一括保存。試験は `officer3d-v3-test-*` に分離。未知の顔・装備ID、スキーマ、重複ID等を受け入れず、全件の検証後に一覧を置き換える。原子的保存と別プロセスでの復旧を実測する。

この一覧は外見作成用。既存Coreの武将3人への外見割当、セーブ移行、能力・所属を持つ新武将生成は次の統合作業。3Dのアニメーション時計は世界時間の所有者にならない。内応工作の会話画面制作は引き続き保留。
