# 毛利元就研究 中央への取次と和睦の実履行

2026-11-05。既存採用仕様の接続を具体化する資料。新しい根本方針の採用、将軍の一律の強制権の新設、ゲーム実装の完了を意味しない。

軍事で勝ち切れない相手との和睦を中央へ働きかけ、一方面の負担を減らして別の戦線へ力を回す。ただし、取次を得ること、中央が働きかけること、相手と約束を結ぶこと、現地の兵が実際に動くことは別である。この一巡を、人物・書状・時間・兵糧・既存の約束を使う政治の遊びとして具体化する。

## 2 誰が何を決めるか

| 主体 | 決められること・必要な根拠 | 自動では起こらないこと |
|---|---|---|
| 依頼人 | 目的、希望条件、費用、使者、取次への依頼。家を拘束する提案には必要な代表権が要る | 贈り物の支払いだけで仲介・発給・相手の承諾が確定する |
| 取次人・使者 | 依頼を引き受けるか、誰に持ち込むか、委任範囲内で何を伝え・交渉するか | 仲介しただけで自分が条約当事者・保証人・援軍の提供者になる |
| 将軍等の上位主体 | 知っている事情、関係、管轄と権限に基づき、働きかけや案の発給を判断する | 御内書を発給しただけで全勢力が停戦し、所領・兵・支援が移る |
| 交渉当事者の正当な代表 | 同じ版の条件を受ける、修正を求める、保留する、拒否する | 家中の全員が個別に同意しないと、正当な代表の合意まで成立しない |
| 現地の指揮官・担当者 | 到達した命令、権限、既存の義務、実行条件を照合し、軍の移動や引渡しを行う | 外交上の成立と同時に、未着の命令を知り、現地の履行が完了する |

この資料の御内書は和平への働きかけとして扱う。官位・任官・安堵など、別の制度的効果を持つ文書まで、すべて相手の任意同意が必要な「提案」に変更しない。それぞれの既存権限・手続・効力に従い、制度上の効果と実支配・実履行を分ける。

既に有効な命令や服従義務を、新しい和睦案への任意の同意と混同しない。仲裁を受ける義務が別の有効な取り決めに含まれる場合も、その根拠・範囲・条件を独立して確認する。本資料から、その義務や将軍の一般的な強制権を新設しない。

## 3 仲裁案の拒否と、約束成立後の不履行を分ける

| 状況 | 記録・判断 |
|---|---|
| 案がまだ届いていない、返信が確認できない | 不達・遅延・返答待ちを、明示的な拒否として記録しない。相手の内部状態はプレイヤーへ漏らさない |
| 未成立の案への保留・修正要求・拒否 | 新しい条約は未成立。この条約を破ったことにはしない。別に有効な義務との抵触や、拒否を知った関係者の政治的評価は別に扱う |
| 必要な合意・到達条件が整い、発効条件を満たす | その範囲の義務が有効になる。受領通知や仲介者の賛成だけを、権限ある当事者の承諾の代わりにしない |
| 発効済みの義務について実行が不足する | 条項・期限・通知条件・例外・実際の行為を照合する。未履行、違反の主張、判断者が把握した証拠を分ける |
| 局地的な攻撃や、配下が動いたとの訴えが届く | 実際の行為、命令系統、約束の対象、訴えの出所を照合する。当事者の説明を世界の確定した違反認定に上書きしない |

BD-56の失敗例にある「一方が拒否すれば仲裁不履行」は、成立前の拒否と成立済み義務の不履行が混ざらないよう、上の区別で読む。基本設計の原文は維持し、この具体化資料と統合案§15の補足から辿れるようにする。

D8の「将軍の仲裁を蹴った」ことによる不利は、拒否を知った将軍・取次・他家等が、その理由・関係・利害も踏まえて大義名分や支援を判断する際に扱う。情報が届く前から全国共通の信用値を下げたり、自動で処罰・離反・参戦させたりしない。期限後の無回答も、内心を読んだ明示的拒否とは別の既知事実として扱う。

## 4 最低限遊べる一巡

| 段階 | プレイヤー・NPCの判断 | 残す情報 |
|---|---|---|
| 争点と依頼先の整理 | どの相手・戦線を、どんな条件で止めたいか。直接交渉か、取次を頼むか | 当事者、戦線、既存条約、希望条件、本人が知る戦況・兵糧・人脈 |
| 取次と申請 | 誰に頼み、どの条件まで交渉を任せ、何を差し出すか | 依頼の受諾、委任範囲、費用の根拠・実支出、使者と書状 |
| 中央での判断・発給 | 知っている事情から、案を出す、補足を求める、引き受けない等を判断する | 判断主体・根拠、対象と条件、文書の版、宛先、発送・到達 |
| 当事者の返答と成立 | 受諾、修正、保留、拒否。相手の承諾が届いた内容と自分の条件を照合する | 必要当事者、正当な窓口、同じ版の承諾、成立・発効時刻。別案の返答を流用しない |
| 現地への実行指示 | 休戦、退兵、定めた城や物の引渡し等を、権限ある担当へ手配する | 指示と到達、実際の移動・引渡し・資源、未履行の項目 |
| 返報と次の交渉 | 実行の報告、異議、違反の訴えを受け、照会・条件変更・履行要求等を判断する | 実際の履行と各人の認識、証拠の出所、次の案件。申立てだけで制裁は実行しない |

### 遊びの具体例：二方面のうち一方を止める

甲家は乙家・丙家とそれぞれ交戦しており、長陣で兵糧が減っている。知っている取次人を介し、乙家との一定期間の停戦と境の扱いを相談できる。乙家は戦況が有利だと見ている一方、中央との関係や甲家の譲歩にも関心がある。これは検証用の架空設定で、毛利・大友・尼子間の実際の条件を転記したものではない。

- **乙家との個別和睦を先にまとめる**：甲乙間の案が独立していれば、その必要な合意・到達・発効条件が整った範囲から成立させる。甲丙間の戦争や別の条約を、まとめて終わらせない。退兵や補給の再手配を行えれば、別戦線に使える人・物の見通しが変わる。
- **三者一体の和睦を求める**：「三者すべての合意」を成立・発効の条件にしている案は、一部の受諾だけを抜き出して個別和睦にしない。全条件を揃える間の兵糧・戦況・使者の遅れを負担する。個別案に変えるなら別の版として必要な相手へ提示する。
- **条件を引き下げて早期成立を狙うか、交渉を続ける**：境の扱い、退兵や引渡しの期限等を交渉する。ただし、自分に処分権のない土地や他家の財産を、自由な譲歩として確約できることにはしない。

既存の盟約に「単独で和睦しない」があれば、乙家との合意とは別に、その盟約の義務・通知・違反条件を確認する。新しい和平が成立したから古い義務を消すことも、抵触の可能性があるだけで新しい合意を自動消去することもしない。

交渉中も世界の時間と現地の行動は進む。未成立の仲裁案だけでは戦争を停止させず、既に有効な停戦がある場合にはその範囲を維持する。成立後も、兵や兵糧を瞬間移動させたり、未着の命令を現場へ即時共有したりしない。「中央の権威を得た」という報酬だけでなく、その権威をどの条件・時機に使うかが判断になる。

## 5 実装へ渡す情報・画面・既存コードとの境界

以下は既存情報を結ぶ対応表で、新しい保存形式や独立した外交エンジンを指定するものではない。

| 情報 | 必要な参照・区別 |
|---|---|
| 仲裁案件 | 依頼人、取次、中央の判断者、関連する提案・条約・争点。案件全体の終了と個別条約の成立を分ける |
| 役割と権限 | 申請、伝達、交渉、承諾、支出、実行の範囲。仲介・当事者・保証人を区別する |
| 条件と版 | 当事者、戦線、対象と期間、各条項、発効条件、返信期限、前の版。個別案か全体条件付きかを明示する |
| 文書と返答 | 発給・発送・到達・開封・返信の記録。受領、承諾、修正、保留、拒否を区別する |
| 実履行 | 任務・命令、担当、権限、移動・引渡し、資源の所有と実受領、元の義務・取引ID |
| 訴えと政治的評価 | 行為、訴えの内容、証拠・出所、観測と取得時刻、評価者が知る理由。真の状態と認識を混同しない |
| 継続と保存 | 案件・条約・配送・任務の参照、期限、既読と認識、既存の決定性・再処理防止 |

画面は既存の「会う・書く・任せる・動く」と受信箱へつなぐ。例えば「乙家の承諾書を開封し、同一版の承諾を確認／確認できた甲乙の停戦条件は発効済み／前線への指示は到達未確認（返報待ち）／城の引渡し報告は未受領／丙家との案は返答待ち」と、本人に確認できた範囲だけを分けて示す。「返答待ち」を相手の内心や確定した不達として表示しない。これは表示の根拠を明確にするもので、開封を成立・発効の条件へ一律に追加する変更ではない。

照合時点で次を読んだが、今回は編集・実行していない。

- [TruceNegotiations.cs](../../Core/Contracts/TruceNegotiations.cs)：停戦の条件・版、文書、成立、履行を分ける既存の接続先。二者間の処理があることを、中央仲裁や多者案の完成と数えない。
- [TreatyNegotiations.Operations.cs](../../Core/Contracts/TreatyNegotiations.Operations.cs)：受領、正式な返答、義務の実行、終期の認識を分ける既存の接続先。受領通知を履行完了や新条項への承諾へ変換しない。
- [共通契約](../Design/CommonContractV1/common-contract-v1.json)のCC-06・09・11：代表・実行権限、物理的な配送、成立と実行・報告の境界を再利用する。

## 6 実装時の確認用シナリオ

以下の5件は既存範囲の検査例。固定の受入170件へ追加したものではなく、未実施である。通常の一巡と代表例外を対応工程で検査し、例外の全組合せはPROCESS_V2に従って後段へ回す。

| ケース | 条件と操作 | 確認する結果 |
|---|---|---|
| 取次から実履行 | 範囲を限定して取次を依頼し、中央の案に正当な代表が同じ版で合意する。必要な到達後に発効し、退兵・返報を行う | 取次の受諾、文書発給、条約成立、現地履行を分ける。取次が承諾権や保証義務を勝手に得ない。権限内の代表決定に全員の個別同意を追加しない |
| 未成立の拒否・保留・未着 | 相手が案を拒否・保留する場合と、案や返信が届かない場合を比較する | 新条約の違反にしない。別の既存義務があれば独立に照合する。政治的評価は把握した事実と理由に限定する |
| 個別和睦と全体条件 | 甲乙案と甲丙案が独立する場合、三者合意が条件の場合、別途単独和睦禁止条項がある場合を比較する | 必要な当事者・版・到達条件を守り、一部承諾で全員を拘束しない。独立案の成立を無関係な他家の返答で止めない。古い義務の抵触は別に残す |
| 成立後の現地事件 | 停戦発効後に局地攻撃の訴えと食い違う報告が届く。命令の到達状況も異なる | 事実、条項、命令系統、通知・例外、各人の認識を照合する。申立人の説明だけで世界共通の違反認定・自動制裁・開戦にしない |
| NPC・遅着・再送・途中保存 | NPCが取次・当事者・現地担当を担い、返答を遅着・再送させ、途中保存から復旧する | 未着の情報を使わず同じ入力から同じ続きとなる。旧版の承諾を新案に流用せず、費用・条約・履行を二重計上しない |

## 7 管理先と完了条件

主な管理先はG-D7／BD-53・56。BD-41・42の条約、BD-48・50・54の権利・権限、G-K13の多者条件、BD-25・26・58の認識・NPCへ接続する。新しい進捗枠や重みは増やさない。

将来の実装完了は「取次を得る→申請・発給→各当事者の返答→必要な条件で成立・発効→現地履行→本人が把握する」一巡が、通常入口とNPCの双方で既存制約の下に動き、上の代表例外を検査できること。今回完了したのは、接続と確認条件の文書化だけである。

進捗表はBD-53・56の「残り」と設計参照へ追記し、実装済みの欄・達成率・受入数は変えない。統合案§14・§15 D9の中央政治の実装順、現在のNpcPurposeV1、凍結基準を維持する。

全勢力への自動強制、多数決による未同意勢力の拘束、仲介者の自動保証・自動参戦、配下の行為に対する無条件の連帯責任は新設しない。必要になった場合だけ、既存義務・権限との関係を示し、別の根本仕様として具体例と選択肢を相談する。
