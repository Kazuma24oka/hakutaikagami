同日後続：[部隊・軍令配送・個人認識・地図の統合](MILITARY_GRID_INTEGRATION_V1.md)を追加。通常Mainの現行表示はそちらを使用する。本書の旧2部隊検証は `Show-OfficerWorld.ps1` の「旧3D接続検証」タブで維持し、過去の保存を勝手に変換しない。以下の261件・30枚は初回実装時点の記録。後続の302件と回帰結果は現行記録を参照。

## 起動と操作

入口は `Scripts/Show-OfficerWorld.ps1`。通常Mainの「3D武将・合戦検証」タブを開く。新しい独立セッションを作る表示タブではなく、「徴税・保存検証」と同じTaxPanelの同じセッションを使う。Mainの武将・城情報もその更新を受ける。既存の応答・代理試験タブは従来の独立検証用で、全国世界AIの実装を意味しない。

右側で武将を選択し、既定外見・肌・髪・布・漆・金属・13部位を変更できる。「作成済み一覧を読み込む」はV3作成画面の保存ファイルを読み、一覧から選んだ**外見だけ**を選択武将へ適用する。作成一覧の名前・IDを政治上の新しい人物として追加する機能ではない。元一覧ファイルも変更しない。

「検証用の部隊を配置」→「両部隊へ交戦指示」→手動または自動で時刻を進める。軍令到達前は部隊を勝手に動かさず、接敵時には即損害を入れず接敵段階を経る。部隊上の表示と上段に兵数・士気を表示。「選択部隊へ撤退指示」は選択武将が指揮する部隊へ1刻後の指示を送る。

1刻＝表示上1.5秒、1/2/4倍は今回の確認用。ゲーム内の1刻を何分・何時間と換算するかは未確定。タブを変えても自動進行の窓口は1つ。旧V2配送表示も独自に時刻を進めず、この時計へ委譲する。

## データと保存の契約

- `Core/Appearance/OfficerAppearance.cs`：エンジンから独立した外見schema3と部品IDカタログ。GodotのV3外見型はこれを継承し、検証・部品IDを二重定義しない。
- `TaxSnapshot.Officers`：v5通常保存の任意拡張。内部schema1。外見の武将ID対応、部隊、軍令、指揮権、損害履歴、表示位相と速度を保持する。
- `Core/Simulation/OfficerIntegration.cs`：Coreに位置・状態遷移・軍令・損害台帳を置く。Godot、壁時計、描画フレームへの依存なし。
- 既存v1〜v5で拡張がない保存は、従来の検証・移行後、通常画面で3人分の決定的な既定外見を割り当てる。部隊は自動生成しない。既存時刻・資源・乱数・配送履歴を変えない。
- 部分的な武将ID欠落、未知の部品・モデル・顔・版、NaNや範囲外色、部隊時刻不一致、重複ID、兵数・士気台帳不一致等を拒否する。未知の部品を黙って代替して読み込まない。v4以前に拡張を偽装した保存も拒否する。
- 通常の保存先は従来どおり `user://tax-prototype-v5.json`。モデルやテクスチャは保存へ埋め込まない。保存は原子的ファイル置換、読込は全検証後の状態置換。外見の変更もコピー→検証→公開を経由する。
- 表示位相と速度も通常保存時に記録する。停止中の途中姿勢から復旧できる。自動進行のON/OFFは画面操作の状態で、世界の進行・停止は保存する `Paused` に従う。
- 自動検査は `user://officer-world-test.json`、`officer-world-*-test/expected` 等の専用名を使用し、通常保存・V3のユーザー作成一覧を上書きしない。

旧版のアプリで新しい拡張付き保存を読める前方互換性は保証しない。新しい拡張を持たない過去の保存を今回のアプリで読む後方互換性を検査した。

## 合戦の検証ルールと正式仕様の境界

既存ConfirmedのF02/P0-A02は共通時刻・因果関係を、F01/P0-A01は権限の要素を、F07/P0-A06は本人認識と命令の段階を要求する。参照した未確定の優先資料は [合戦統合案](BATTLE_MILITARY_TACTICS_CONSOLIDATED.md)と[時間統合案](ACTION_TIME_SYSTEM_CONSOLIDATED.md)。数値・時間換算・戦術式をこれらの正式決定として扱わない。

今回だけの固定条件は [contract.json](../../Art/Officer3D/WorldIntegrationV1/contract.json)。赤100人・士気100、青60人・士気55。双方の交戦意思は明示した検証入力。赤青は戦術試験用の区分であり、同じ家中の既存武将を用いても政治的敵対・所属変更・反乱を発生させない。部隊位置は検証戦場の座標で、全国地理・城所在との正式な接続は未実装。

初期位置±5m、通常移動1m/刻、接敵1.6m、退避1.5m/刻、退場境界±10m。ダメージは赤が8人・青が12人、士気低下は赤8・青15。士気20以下で敗走する。兵の損害は台帳へ記録し、残兵＋損害＝初期兵数を保存復旧時にも検証する。

軍令は発送時と到達時に、行為者・対象部隊・管轄・権限根拠・有効期間 `[from,until)` を確認する。到達・権限評価・検証用の服従意思・効力を分離し、拒否・権限失効・既に行動不能等の結果を残す。正規の軍事NPC判断はまだなく、検証用の服従意思を全知AIの判断と偽らない。軍令の紛失・再送は未実装であり、既存の徴税用配送検証をそのまま軍事配送の完成としない。

同一軍令IDの同じ入力は再発送・二重実行を起こさず、別内容での再利用を拒否。同じ部隊・同じ効力時刻の相反指示は試作では拒否し、登録順で優先しない。両部隊へ送る試験入力は片方だけ公開されないよう一括で検証する。

同じ刻では、到達判定→権限・服従意思の評価→移動／接敵または同時損害、という検証順序を固定する。双方の損害は同じ損害前の状態から計算し、部隊登録順で先制攻撃を作らない。徴税・取消等の既存の因果順序は保持し、同じコピー・検証・公開トランザクションで失敗時に合戦も巻き戻す。一般的な複数合戦・兵站との資源競合の処理順までは決定していない。

敗走・撤退では部隊が移動してから退場する。退場時に3Dモデルを非表示にするが、生存兵・部隊・指揮官データは残す。兵0の戦闘不能も人物の死亡・捕縛・所属変更へ自動変換しない。

## 動作と実画面

移動表示は直前の確定位置から現在の確定位置へ補間する。Coreの未来位置や未来の損害を予測して確定しない。表示は最大1刻の補間遅延を持つ。歩行位相は累積距離÷元リグから測定した歩幅で決め、装備ごとに別時計を持たない。攻撃はCoreの損害刻から表示し、アニメの終了通知で損害を発生させない。

これは移動量と動作位相の整合検査。接地足の全フレームの滑り量ゼロ、斜面・段差・足IK、刀や手の相手への接触を保証するものではない。戦場表示はmid LODを使用し、既存far銀具足の欠けを接写で使わない。今回新しい外見・甲冑の生成は行っていない。

## 実測・再検査

Windows / Godot4.5.2 .NET / .NET SDK10.0.302・net8.0 / RTX4060Ti・GL Compatibilityで実行。ビルド警告0・エラー0。Core単体テスト261件合格（既存233＋統合28）。通常Mainの実GPU原本30枚、作成一覧の外見割当、1/2/4倍、途中位相の停止、通常保存復旧、未知外見を含む保存の全体拒否、接敵・交戦・敗走・任意撤退・退場を検査した。

合戦中の徴税は60俵を1回だけ城へ移し、城の米100→160、報告到達まで確認した。赤隊76人、青隊24人が残り、青隊は退場。別プロセスで、時刻・乱数・部品・色・軍令・損害履歴だけでなく3D位置・向き・動作時刻の一致も確認した。

実測原本は [runtime-report.json](../../Art/Officer3D/WorldIntegrationV1/runtime-report.json)、現行ソースSHAは [runtime-plan.json](../../Art/Officer3D/WorldIntegrationV1/runtime-plan.json)。実画像の比較と自己点検は `runtime-local/review.html` と `visual-review.json`。制作側の自己点検をユーザー採用へ置換しない。依存するコード・定義・素材の変更で検証を失効し、検査途中の変更も結果保存前に再確認する。

再実行は `Scripts/validate_officer_world.py <repo> --bind`、比較画面生成は `Scripts/review_officer_world.py <repo>`。既存のV3作成画面・V2比較画面の回帰結果も更新して保持する。派生画像とGPU原本を区別する。旧版の記録中の「未統合」はその時点の履歴で、現在の境界は本書を優先する。
