# 3D武将：軽量化・色・交換・ゲーム接続 第2試作

2026-10-19。ユーザーの「4まですすめて」に対する技術検証。作業ブランチprototype/godot-foundation。main/design/foundation/Confirmed、原本blend/動画、既存Coreは変更しない。マウス・ネイティブ入力・カーソル設定は使用しない。

## 実装した範囲

1. V1を保持し、近・中・遠の明示GLBを別出力。全25メッシュには非表示の交換顔・髪・髭も含む。骨格は全LODで同じ73ボーン。画面上の想定身長が180px超で近、160px未満で中、65px未満で遠、80px超で中へ戻るヒステリシス。実装式は2m/正投影サイズ×Viewport高さの概算であり、顔の占有率ではない。
2. 元材質47種を契約内でcloth/lacquer/metalへ明示分類。V1と同じUV展開と各部品のrender相当評価メッシュの材質IDから2048²の一意RGBマスクを作成。テクスチャの色から材質を推定しない。境界外8texelは未占有部分だけへ固定順で延長。色はsRGB入力を線形化した乗算であり、任意色への置換ではない。肌は顔・体・耳・手で共通。眼・眉・口と装備は保護する。
3. 基準体を再利用した交換武将プリセットveteran。angular_jaw、tied、shortのIDで顔型・結い髪・短髭を交換し、兜・面頬を外し、布・漆・金属の配色を変える。顔は同じ顔メッシュから顎幅を調整し、髪・髭は確認用の簡易メッシュを共通Headボーンへ接続。完成した別武将の美術品質、史実人物の顔、量産済みの髪型一覧を意味しない。体型と73ボーン、元の3クリップを再利用。全方向を同じ3Dモデルから描画。
4. Mainに「3D武将・配送」タブを追加。既存TaxPanelの同じTaxSimulationを参照し、同じ命令発送・一刻進行・停止・保存・読込の処理を使用。別の世界状態を3D側に作らない。使者の経路・所在は配送の表示用に導出し、到達・認識・徴収・乱数はCoreが決める。現在のCoreには一般の地理的部隊移動がないため、全国地図・進軍・合戦の規則は新設していない。管理用表示であり、主人公の認識制限を満たす正式UIではない。

## 元の動作を保持する修正

Blenderを経由した通常出力では30fpsの元動作が24fpsのサンプリングへ変わることを、実Godotの長さ照合で発見。軽量メッシュGLBへ元V1のアニメーションのsamplerバイト列をコピーし、対象ボーン名で参照を付け替える。対応するボーンのREST変換が2e-5以内で一致しなければ出力を拒否。3クリップのGodot長さは元と一致、各20時点・73ボーンの姿勢差最大0.0009765625rad、位置差最大約0.00000203m。軽量化のために動作を再生成しない。

歩行は共通クリップの足ボーンの前後振幅から計測した一周期の移動量（今回約1.501m）を使い、配送の表示上の移動距離から再生位相を算出する。足の接地滑りを全路面・全速度でゼロと実測したわけではない。試作の1刻=1.5秒や城・村の位置は正式な時間／地図仕様ではない。

## 検証

- 実GPUの原本187枚を名前リストで固定し、比較用に加工した一覧・GIFや過去の画像を原本検査へ混入しない。runtime-report.jsonは原本のみ、visual-review.jsonは自己画像確認と派生物のSHAを別に持つ。
- 同じカメラ・姿勢・約200pxの大きさで元モデルとの輪郭IoUを4方向比較。近の最低約0.969、中約0.950、遠約0.850。遠の細部欠けはこの大きさでは見えるため、通常は小さな表示に制限。輪郭一致と質感の一致を混同しない。
- 布・漆・金属の単独変更を4方向で実GPU比較。各方向で変化した画素あり、対応マスク外のRGB差分0px。裸の基準体による肌4方向の比較も範囲外変化0px。
- 13部位×3LODの個別着脱を歩行姿勢で撮影。全8192組合せや全フレームの貫通を検査したと扱わない。
- 交換武将の3LOD×4方向×3動作を撮影。3クリップの通常再生、攻撃終了後の待機復帰、Rootの平面移動0、LODで骨格オブジェクト・再生位置・外見保存値が不変、切替のヒステリシスを検査。
- 顔・髪・髭・装備・素材色・肌色をschema2で保存。未知ID／schemaを拒否し、拒否前後で現在の外見が変わらない。部品／色の往復と、別Godotプロセスで外見復旧を実施。
- 表示30フレームでCoreの保存JSON・乱数・時刻が不変。停止時は時刻と表示位相が不変。命令到達は1刻目のReceived、判断・引当は2刻目、徴収は3刻目、報告は4刻目という既存処理を維持。保存→継続→読込→再継続のJSONが一致し、徴収は一度だけ。
- 独立したGodotプロセスで世界の保存ファイルを読み、4刻進めた結果が元の実行と一致。試験専用user://officer3d-v2-test-*を使い、通常の徴税保存を試験で上書きしない。
- Core既存単体テスト233件合格、旧V1ゲート4件・V2の入力改変拒否テスト合格。新しい本番ゲーム仕様のテストではない。
- 通常Mainの3Dタブを内部操作で選択し、既存の3人と描画を確認。マウス入力なし。小さいウィンドウで操作欄が切れたため、幅に追従する構成へ修正して実画像で再確認。

## 固定入力と再実行

export-plan.json / runtime-plan.jsonに元データ・契約・使用コード・出力のSHAを記録。変更時はGPU結果・自己確認を失効。`Scripts/validate_officer3d_v2.py <repo>`がビルド・import・実GPU・別プロセス復旧を実行。実行計画の更新は`--bind`を明示し、その後に全検査。`Scripts/Show-Officer3DV2.ps1`は現行検査と自己画像確認を通ったものだけ表示。Gitで追跡する対応コードは固定バイトで保管。

ローカルでの作成順：Blender `--background --disable-autoexec <元blend> --python Scripts/build_officer3d_v2.py -- <repo>` → validator → review_officer3d_v2.py → 実画像確認・visual-review.json。元blendは保存しない。通常の材質EMITベイクは重かったため中断し、評価済み三角形の材質IDをUVへ描く方式へ置換した。最終のLOD出力ではメッシュ検証・修復を実施し、対象をexport-manifest.jsonに記録。Blenderの複数Textureノードのsampler警告や終了時の微小メモリ警告はあり、全ツールで警告0とは記載しない。C#ビルドは警告0・エラー0。

GLB・テクスチャ・実描画画像は元資産の利用条件整理前のためローカルのみ。Gitにはコード・契約・出力ハッシュ・測定結果・この文書を記録する。別PCでは元データとローカル資産の用意、および新しい計画・再検査が必要。V1の元GLBも変更していない。

## 内応工作の方向性だけを保持

ユーザーが確認した案：左手前に自分側の背中〜横顔、右奥に相手側の顔が見える3Dの対面構図。テキストと共通会話動作で表現する候補。会話デモ・内応ロジック・交渉用姿勢・表情制作は保留。立ち絵全般を廃止した決定ではない。
