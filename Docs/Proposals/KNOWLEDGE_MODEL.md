# 未確定：勢力・家臣団・個人の3段階情報認識モデル

状態：検討中。全項目は提案であり、確定仕様ではない。

## 基本案
情報認識を「勢力・家臣団・個人」の3階層で扱う。ただし、階層が上がっただけで全員に自動共有されるわけではない。情報の保有、閲覧権限、実際に知っている状態を区別する。

| 階層 | 対象情報例 | 共有の制約 |
|---|---|---|
| 勢力 | 外交、軍事、敵勢力の動向 | 役職・任務・機密度により制限 |
| 家臣団 | 所領、内部事情、配下の動向 | 所属と権限によって制限 |
| 個人 | 人脈、秘密、目撃、噂 | 本人が他者に伝達しない限り非共有 |

## 情報伝達例
1. 密偵が敵軍の集結を目撃し、本人の認識に登録。
2. 使者・書状などで直属の上司に報告（到達遅延と伝達失敗の可能性）。
3. 家臣団が受領し、共有対象と機密度を判断。
4. 大名・軍議へ上申し、勢力の意思決定に利用。
5. 商人や寺社から大名へ直接伝わるなど、階層を飛ばす経路も許容する案。

## データ構造の候補
- EventTruth: 事件の実際の内容。プレイヤーには原則非公開。
- Report: 情報源、内容、生成・到達時刻、確度、改変・誤認の履歴。
- KnowledgeRecord: 対象（個人／家臣団／勢力）、情報ID、認識日時、信頼度、認識状態。
- AccessPolicy: 機密度、閲覧権限、役職・任務・所属に基づく共有条件。
- Transmission: 送信元、受信先、経路、所要時間、成否。

同一の報告を全武将へ丸ごと複製せず、参照IDと個別の認識状態を持つ設計を検討する。ただし、共有情報を参照できることと、本人が実際に知っていることは区別する。

## イベント停止との関係
- 主人公に情報が到達した時点で、主人公との関係性を踏まえて通知・停止を判定する。
- 同じ事件の複数報告は統合し、重要な訂正のみ再通知する案。
- 主人公が現場に居合わせる場合は情報伝達を待たずに直接認識する。

## 未決定事項
1. 「家臣団」の境界（主君直属、城主配下、与力など）と兼属・移籍の扱い。
2. 勢力／家臣団共有情報を、個人がいつ認識したと見なすか。
3. 機密度・役職権限の段階と、漏洩・虚報・情報隠蔽の仕組み。
4. 離反・独立・家督相続時に持ち出せる知識と、共有権限の失効。
5. 噂の伝播範囲、確度更新、矛盾する報告の扱い。
6. 全国規模でのデータ量、更新頻度、保存・再現性。

明示的な承認まで Confirmed には移動しない。
