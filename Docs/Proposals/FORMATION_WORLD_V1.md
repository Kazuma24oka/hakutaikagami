# 作戦線・3部隊の展開・連続ズーム試作

2026-10-19。ユーザー指定「線を引いて命令が届いたら複数の部隊が並ぶ」「全国から拡大して同じ場所を見る」を実装。Confirmedの変更ではなく、選択された操作方針の技術検証。

## 起動・操作

現行入口は `Scripts/Show-FormationWorld.ps1`。通常Mainの「作戦線・連続地図」タブでTaxPanelと同じセッション・世界時計を使う。

1. 「演習を配置」。中央は太郎、左翼は次郎、右翼は三郎の3部隊。
2. 「全国」「地域」「布陣を見る」で同じ川・橋へ拡大。ホイールでも連続拡縮。
3. 「線を引く」を選び、近景の地面で左ドラッグ。両端と中間の3担当位置を確認。初期案は橋の東 `(8,1)–(8,5)`。
4. 「布陣命令を発送」。1刻進めるか自動進行する。伝令到達は演習入力として左翼1刻・中央3刻・右翼5刻。配送後も実移動時間が必要。
5. 各部隊が担当位置へ展開。停止・倍速・通常保存・通常復旧も共通時計を使う。

今回は一つの作戦線を検証する。発送後の編集・再配置は初期化後。既存の旧演習をロードした場合は保持し、自動変換・消去しない。視点切替は認識検査用で、製品のプレイヤー権限選択機能ではない。

## 全国と近景

海岸線は架空の概略形状で、日本の実測地形ではない。従来の11×7の川・橋・道路・森・岩を、広いGodotワールドの同じ座標に置く。正投影カメラのSize180/40/14を補間し、全国・地域・近景でシーンや戦場を交換しない。

全国では選択武将の位置を軍勢の印で表示し、近景では本人・目撃の部隊を既存3Dモデルで描く。過去の情報は日付付きの印。拡大によって未知の現在位置を開示しない。広域の枠は演習地点を探す表示で、別マップへの入口・戦場境界ではない。

全国の進軍・経路探索・他地域の軍事シミュレーションは未実装。実際に歩ける軍事地域は11×7のみ。全国完成・地理スケール確定とは扱わない。

## 命令・権限・認識

`MilitaryFlow.CreateFormation` が同一軍勢の3部隊を作る。組織・軍勢指揮官・現地指揮官・指揮委任を分離。太郎に3部隊へのMove/Cancelを明示的に委任し、所属・役職から権限を自動生成しない。政治的敵対・多部隊の損害計算は今回追加しない。旧2部隊交戦は旧入口で保持。

`FormationPlan` に線の両端、発送者・時刻、3担当位置、部隊、軍令ID、配送遅延を保持。線を等分した点を区画へスナップする。地域外、短すぎる線、川・岩の担当位置、到達不能、対象の指揮権不足は全体を拒否し、部分発送を残さない。同一IDの同一内容だけ再入力を許し、別内容は拒否。

線を描く行為は下書き。発送すると既存 `MilitaryFlow.Dispatch` → `MessageFlow` に3通の不変なMove軍令を渡す。受領・本人の認識・権限再確認・服従判断・履行開始は既存処理。瞬間配置や全部隊の同時開始はしない。

履行開始の返書と配置完了を区別。担当位置への到着後、本人のOwn観測を既存の軍事情報報告で発送する。画面は `MilitaryViewFor(observer)` と発送者のみの `FormationPlansFor(observer)` を使用し、真実スナップショットを描画へ読ませない。遅延報告を現在の座標へ更新しない。

今回のUIは軍勢指揮官の下書き・発送。左翼プレイヤーの独断移動、軍議の合意、命令違反の評価・責任、NPCの戦況判断UIは未実装。服従拒否・取消は既存Coreで検査。

## 経路・合流

既存MilitaryMapの地形と速度コストを使用。他部隊の最終担当位置を通過経路から除き、先に到着した中央が後続を塞ぐ問題を避ける。予約は発送済みの不変計画から導き、未知の敵位置で経路を変えない。

同じ合流地点を同時に要求した場合、停留中の占有者を優先し、移動候補間は部隊IDの序順で一隊ずつ通す。移動先の部隊が停止した場合は後続も待つ。交換移動は禁止。3部隊の実測で重なりなし。一般的な対向交通のデッドロック解消、多数部隊の幅・隊列・兵站は未実装。

## 保存と実測

通常v5 `Officers.Military` schema1 に既定空配列 `FormationPlans` / `FormationArrivals` を追加。旧保存の欠落フィールドは空で復旧。不変の個別配送本文と計画、担当位置、到着報告の本人観測・時刻・出典をロード時に照合する。別時計・別配送エンジンを増やさない。下書き・カメラ倍率は一時表示設定。テストは専用 `user://formation-world-test*` と期待値ファイルのみ。

Godot4.5.2.NET、.NET SDK10.0.302、net8.0、Windows、RTX4060Ti、OpenGL Compatibility。契約・Core・描画・資産・試験コードをruntime-planのSHAで固定し、変更時は再検査する。

- Core **317件合格**：既存302＋布陣15。時間差、同時合流、権限と無効線の原子性、同一ID、拒否、取消、紛失・再送・遅着、各刻保存復旧、改竄拒否、旧保存互換。
- 実GPU原本 **28枚**。地図GuiInputの内部イベントで線を引き、射影往復、下書き中の未発送、1/3/5刻到達、橋通過、整列を検査。マウス操作ツール・OS入力は不使用。
- 初期線で**第20刻**に3部隊が `(8,1)/(8,3)/(8,5)` へ到着。第22刻の完成画面では中央から全隊を直接目撃・3体描画。
- 停止、通常保存復旧、5刻の復旧後継続一致、**別プロセスで全状態と描画位置・クリップ復旧**に成功。
- 全国・地域・近景と12枚の連続ズーム中、同じワールドノード・状態・座標・時刻・乱数を保持。
- 既存2部隊地図25枚、旧接続30枚、V3作成283枚、V2比較187枚を別途回帰検査。資産原本・GLBは変更しない。

`runtime-report.json` に原本28枚のSHA。`runtime-local/review.html` の連続ズームGIFは実描画フレーム、展開GIFは異なる刻の抜粋。等時間隔の動画とは区別する。自己点検はユーザー採用とは別。
