## 提示ファイルを実際に確認した範囲

Blender5.2.2 LTSのバックグラウンドで.blendを読み、埋込みPythonは実行せず、構造・材質・アクションと説明文を調査。元.blendは保存していない。動画は640×800、30fps、341フレーム、約11.37秒。5箇所をPNGへ取り出し、待機／歩行姿勢等の見た目を目視した。動画の全フレーム確認やゲーム用アクションの動作検証とは区別する。

ファイル全体に1,084オブジェクト（メッシュ1,069、リグ5）、材質105、アクション19。主Armatureは73ボーン。他の4リグは各65ボーンで参照名を持つ。主リグを参照するメッシュは1,067個、hide_renderがfalseのものだけでも274個・626,801三角形。これはデータ上の集計であり、コレクション非表示や評価後モディファイアを反映した最終描画負荷ではない。過去版・参照・衣装の切替候補を含むため、この総数をそのままゲーム1体の確定ポリゴン数とはしない。

装備コントローラーには部位表示・全体色・個別色があり、顔と体の肌色を共通変更するコントローラーもある。説明文には、これらはBlender内用でゲーム出力には別途対応が必要と明記されている。装備の色は全体色×個別色による乗算で、黒素材を白へ置換する機能とは異なる。肌コントローラーは顔／体を連動し目・眉・口を保護する意図。実際にゲーム側で成立するかは未検証。

## 見直す仕様

| 項目 | 変更・検証内容 |
|---|---|
| 表示とカメラ | 64×96固定キャンバス／1倍／方向別画像を3Dの規格に流用しない。見下ろし角、正投影／透視、ズーム、会話時アップ、画面内の人物サイズを実画面で比較。6頭身立ち絵と4頭身駒を別制作する前提も再評価し、同じモデルを別カメラで見せる案を先に試す。 |
| 人物定義 | 顔輪郭・体型・髪・装備・材質の共通IDを人物一式として保持。方向ごとに別の顔や色を作らない。輪郭変更は共通の頭部形状／表情shape keyを通し、照明差と素材色差を分ける。 |
| 素体・骨格 | 単位・前方向・原点・基準姿勢・骨名・変形用ボーン・ウェイトを固定。同じ骨格へ装備と動作を対応させる。現状73ボーンと参照用65ボーンを混ぜて正式規格にしない。 |
| 着脱・接続 | 胴／肩／腕／腰／脚／兜等を意味的スロットで管理。曲がる布と硬い甲冑を分け、スキニング／骨への剛体取付／刀の握り・鞘の取付を決める。隠れた素体をどう消すか、体型変更でどうフィットさせるかも仕様化。 |
| 肌と装備の色 | 顔・体・耳・手を同一肌設定で変更し、目・眉・口・髪・甲冑は不変。基準色／乗算／置換の意味を区別し、マテリアルID・必要なテクスチャマスクを共通化。光源で見た色が変わることと、設定値がぶれることを区別して検査。 |
| 材質・出力 | Cyclesの見た目、MToon系ノード、プロシージャル模様、カスタムプロパティ／ドライバーがそのままゲームへ移ると考えない。必要な模様のベイクとGodot材質の再構築、テクスチャの色空間、肌色制御の移植を実測する。 |
| 動作・時間 | 待機／歩行／攻撃を個別クリップ化し、参照／プレビュー用アクションを除外。ループ、遷移、剣を持つ手、足接地、移動速度、in-place／root motionを契約化。攻撃の見た目の接触とCoreの命中・ダメージ時点を分離する。 |
| 性能 | 部品の数だけ描画負荷を増やさないよう、交換単位を守って結合・材質共有・遠景LOD等を検討。1体の成功後、10体／50体等の試験条件を決め、CPU/GPU・描画呼出・メモリを測って上限を決める。現在の大きな制作データを直接量産表示しない。 |
| 保存・資産管理 | 人物ID、体型／顔パラメータ、髪・装備ID、肌／素材色、定義版を保存。Blender原本とゲーム用出力を分け、素材・素体・外部モーションの出典と利用条件も保持する。元.blendや購入テクスチャを無条件に公開Gitへ入れない。 |
| 合格条件 | 同一人物の全周、肌色変更、各装備着脱、歩行／攻撃、体型変更、Godotへの再出力を実画像で確認。共有要件が欠けたまま個別素材の出来だけで先へ進めない。3D用の自動ゲート・検査はこれから実装する。 |

Godot4.5はglTF2.0を推奨し、.blend直接読込も内部でglTF出力を利用する。提案は原本.blendを保持し、ゲーム用の明示GLBを作って採用物を管理すること。公式：[対応形式](https://docs.godotengine.org/en/4.5/tutorials/assets_pipeline/importing_3d_scenes/available_formats.html)、[AnimationTree](https://docs.godotengine.org/en/4.5/tutorials/animation/animation_tree.html)、[3D性能](https://docs.godotengine.org/en/4.5/tutorials/performance/optimizing_3d_performance.html)。
