# P0イベント処理の残課題：循環解除・確定境界・再試行・セーブ復旧（ABC比較）

**状態：未確定（Proposals）／2026-10-17。** 6項目は未選択。Bは推奨。既存のF02・P0-A02/A04・P0-R01〜R04に整合する詳細の比較。**既存の基本原則で要件は充足しているため、新規Confirmed確定は行わない。**

## ① 循環依存の保留解除
- **A**：一定時間経過で全て強制成功。例：援軍と開城が相互依存なら時間切れで両方成立。
- **B（推奨）**：依存条件の変化・外部事象・制度別裁定・安全な失敗で解除し、無期限待機を防ぐ。例：援軍が撤退したら開城交渉の条件を再評価。
- **C**：循環がある限り永久に待機。例：開城と援軍が互いを待って全国の進行が止まる。
- **保留**：検出単位・保留期限・解除イベント・通知。

## ② 競合の確定境界
- **A**：先に登録したイベントを無条件に優先。例：二重徴税の先着登録者が米を全て取得。
- **B（推奨）**：共通基盤が整合性・権限・効力を検証し、勝敗や配分は制度別規則で裁定。例：米100俵の残量は共通で守り、どちらに何俵渡すかは徴税規則で決める。
- **C**：同時刻の競合を乱数だけで裁定。例：同じ開城・援軍がロードごとに別の勝敗。
- **保留**：制度別裁定の優先順位・同値時タイブレーク。

## ③ ロールバックと補償の境界
- **A**：確定済みイベントも履歴ごと消去。例：書状到達後に取消してNPCの認識も消す。
- **B（推奨）**：未確定の状態変更は取消し、確定済みの影響は新しい補償イベントで調整。例：兵糧出庫前は取消、出庫確定後は返還や損失を別記録。
- **C**：失敗しても途中変更を全て維持。例：輸送失敗で米が二重に存在。
- **保留**：確定単位・不可逆な認識・補償不能時。

## ④ 補償処理の失敗と再試行
- **A**：補償失敗でも完了扱い。例：米が戻っていないのに返還済み。
- **B（推奨）**：補償に一意性・適用記録を持たせ、失敗原因に応じて再試行・保留・中止へ分岐。例：返還処理を再試行しても米が二度戻らない。
- **C**：補償は無制限即時再実行。例：返還不能でも永久に再試行し進行が停止。
- **保留**：再試行上限・間隔・失敗時責任・手動介入。

## ⑤ 再試行時の権限・期限再評価
- **A**：初回判定だけを使い再試行。例：失効した使者が再試行で条約締結。
- **B（推奨）**：失敗の種類と処理段階に応じ、再試行時点で必要な権限・期限・在庫・因果前提を再評価。例：権限取消後の徴税命令は再検証し、確定済み徴税は二重実行しない。
- **C**：失敗は全て恒久的に破棄。例：一時的な配送障害で書状が消える。
- **保留**：効力時点と再試行時点の関係・追認・期限境界。

## ⑥ セーブ・ロード時の復旧境界
- **A**：未完了の途中状態を全て確定。例：落城処理途中のセーブで二重移籍。
- **B（推奨）**：確定済み更新・未処理キュー・補償待ち・乱数状態を整合したスナップショットとして保存し再開判定。例：輸送の途中でセーブしても米の二重計上がない。
- **C**：ロード時に未完了イベントを新規作成。例：同じ徴税要求が別IDで再発行。
- **保留**：スナップショット単位・保存失敗・バージョン移行。

## 整合性・重複・依存関係
- **確定済み**：共通世界時刻と因果・効力・依存評価（F02/P0-A02）、資源数量整合（P0-A04）、一意性・整合復旧・セーブ継続と適用状態（P0-R01〜R04）。
- **現行の未確定正本**：[イベント処理17項目統合](P0_EVENT_PROCESSING_CONSOLIDATED.md)。①④⑤⑥は同統合案の循環・補償・再試行・セーブ課題を深掘り。②③は同時刻11項目および情報・帰属・会計に接続する。
- **矛盾の予防**：ロールバックで過去の書状到達やNPC認識を無かったことにしない。補償の一意性を守り、期限切れ・権限失効した未確定イベントを無条件に再実行しない。
- **共通と制度固有の責任**：共通基盤は因果・整合・重複防止を保証し、徴税の配分や落城の勝敗などは制度別裁定規則が判断する。
- **依存順**：循環の検出と解除 → 競合の境界 → 更新の確定境界 → 補償と再試行 → セーブ／ロード。
- **残るP0**：保留期限、タイブレーク、トランザクション境界、補償失敗の扱い、再試行時の効力時点、スナップショット方式。
