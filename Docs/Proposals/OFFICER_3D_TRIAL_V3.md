## 実装と検査

- Blender 5.2.2 LTS / Godot 4.5.2 .NET / .NET SDK 10.0.302、net8.0 / RTX 4060 Ti、GL Compatibility。
- 3LODとも1skin・73骨・35メッシュ。有限頂点、骨番号、非負重み、重み合計、元動作の長さと姿勢を検査。
- 3プリセット×近中遠×4方向×3動作、13部位の個別非表示、別具足10部位の交換×3動作、歩行・攻撃各12時点を実描画。
- 肌を4方向、布・漆・金属を2具足×4方向でRGB比較。対象領域は変わり、対象領域外の変化は全件0。照明なし検証と通常描画を区別している。
- 同一メッシュ共有、全材質インスタンス分離、別個体の保存外見と実際の色パラメーターの不変を検査。
- UIの操作先を内部シグナルで実行し、武将3人の名前・部品・色を原子的保存。別プロセスで一致復旧。未知の顔・装備ID・スキーマは一覧を部分変更せず拒否。
- Core単体テスト233件合格。依存する資料・設定・コード変更とstage不一致を拒否するゲート試験合格。同一環境で別フォルダへ作り直した3GLBのSHAがすべて一致。

## 実測

最新の計測表は別ファイル [V3実測表](OFFICER_3D_TRIAL_V3_MEASUREMENTS.md)。他のGodotプレビューを閉じ、1280×800の3D描画、影あり、歩行、近中遠を分けて15フレーム準備＋60フレームの完了待ち時間を測定した。VSync・上限FPSは試験ウィンドウだけ無効化。短時間の表示ループ実測であり、GPU単体時間やゲーム全体の持続FPSではない。

50体は保存した3人を部品・色違いで反復した混成表示で、50種類の完成武将を新規制作した意味ではない。LODはポリゴン数を減らすが、この構成では描画呼出数と骨・材質更新の削減が次の課題。最初の計測は旧プレビューが同時稼働していたため比較値には使わず、閉じた状態で再測定した。
