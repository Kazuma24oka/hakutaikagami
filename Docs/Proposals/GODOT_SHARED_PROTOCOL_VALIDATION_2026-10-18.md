## 1. 取消応答と配送失敗・再送

- 取消の効力評価で、Applied / AlreadyStopped / TooLate / Unauthorizedの結果を独立した応答書状として発送する。内部の取消状態と、発信者が応答から知った結果を別々に保持する。
- 取消本体、取消応答、配送失敗報告、代理人からの報告を共通の書状・物理配送試行で扱う。応答は通常1刻後に到達する試作条件。
- 紛失・配送拒否だけでは発信者へ自動通知しない。固定試験の観測者が失敗報告を送り、それを発信者本人が認識した後だけ再送できる。取消本体の再送時も取消権限を再評価する。
- 同じ論理書状に試行番号を付け、上限は原本込み3回。失敗報告の別コピーも3通まで。失敗報告自身にも共通の紛失・報告・再送処理を適用できる。
- 原本が紛失扱いの後に遅着し、再送分も到達しても、正式受領・個人認識は論理書状単位で重複させない。取消効力と米の更新を繰り返さない。
- 別の取消IDは別の命令であり、同じ取消IDの再呼出しと配送再送は異なる。再送には既存の本文・宛先・相関IDを使う。

## 2. 権限失効・担当交代・代理受領

| 境界 | 今回の試作動作 |
|---|---|
| 代理権限 | 本人・代理人・対象城・書状種別・根拠・有効期間を明示。受領権と開封権を分ける |
| 正式代理受領 | 到達条件を満たすが、本人の個人認識を作らない |
| 開封権なし | 正式受領しても代理人は本文を知らず、本人へ転送報告できない |
| 開封権あり | 代理人だけが内容を認識。別の報告が本人へ到達して初めて本人が認識 |
| 取消効力 | 指定効力時刻と**担当本人が内容を認識した時刻**の遅い方。代理受領だけでは担当の作業を停止しない |
| 権限の失効 | 到達時と追加開封時に再検査。有効期間は開始を含み終了を含まない |
| 既知の記憶 | 失効しても消去しない。既知内容の報告は許すが、新しい受領・開封権限にはしない |
| 担当交代 | 役職変更だけでは旧命令・個人認識・実行権限を新担当へ移さない |
| 明示的な再委任 | 旧担当の徴税権限を失効させ、新担当に根拠・期間付き権限を与え、新担当宛に新命令を発送 |

旧担当への命令は本人に届いても、実行時の権限がなく拒否される。新担当へ明示的に送った新命令だけが30俵を徴収し、鏡家の米は100→130となる。役職・本人認識・代理権限は保存復旧で保持する。

上記の代理取消の効力時点、既知内容の報告許可、担当交代の手順は今回の試作規則であり、全制度の取消・継承規則を確定するものではない。代理の返答権・実行代行権、重要書状の未開封停止、盗難・偽書は未実装。

## 3. 共通基盤への整理と別命令での再利用

- `Core/Common/SessionInfrastructure.cs`：厳格なJSON境界、コピー→操作→検査→公開、同一ボリューム内の一時保存と置換、権限判定、効力適用済み台帳。
- `Core/Messaging/MessageFlow.cs`：論理書状、物理配送試行、正式受領、個人認識、代理権限、配送失敗報告、再送、遅着、本人への報告。Godot・徴税型への依存なし。
- `TaxSimulation.Communication.cs`：取消と共通書状の接続、役職・権限変更。資源と取消効力は徴税側が担当する。
- `Core/Commands/InspectionSession.cs`：別の業務である「城の視察」を共通基盤へ接続。徴税モデルへの依存なし。命令到達→権限再検査→結果書状の配送→発信者の結果認識を検証。視察は固定城名を返す読取試験で、調査行動や新たな情報生成の正式実装ではない。
- 視察でも紛失・失敗報告・再送・遅着・取消・期限・失効・代理受領・保存復旧・公開直前の障害を検証。原本と再送の2回到達に対して業務効力は1回。

徴税の既存原本・結果報告と資源競合処理は、既存保存との互換性のため専用処理を残す。全命令を汎用基盤へ移し終えたとは扱わない。共通書状のDeliverByは到達期限であり、徴税のExecuteBy（徴収確定期限）と別である。共通基盤の効果台帳は視察で使用し、徴税の既存適用済み台帳も保持する。

## 保存・互換性

徴税保存はv5。共通書状、全配送試行、代理権限、正式受領、個人認識、取消応答、本人認識時刻を保存する。視察保存は別スキーマv1。Godotの検証画面用保存も別の包み形式v1で、項目と操作段階を業務保存と一緒に保持する。

v1〜v4をv5へメモリ内移行。今回の変更前v4コードから9件の実保存を固定化し、v1の5件・v2の8件・v3の8件と合わせ、計30件の実旧保存を回帰検証する。v4の取消配送・受領を実際の履歴から取り込む。既に解決済みの取消に、当時なかった応答配送・発信者の認識を捏造しない。必要なら応答者が現在時刻で初めて応答を発送できる。旧保存に新しい権限や代理委任を付与しない。

通常の徴税保存先は `user://tax-prototype-v5.json`。未作成時だけv4→v3→v2→v1を探す。書込先はv5で、旧ファイルを消去・上書きしない。新画面は `user://shared-protocol-v1.json`、自動試験は `user://shared-smoke-<GUID>.json` に隔離する。未知フィールド・不整合な受領/認識・失敗認識前の再送履歴等を拒否し、検査失敗時には現在状態を置き換えない。
