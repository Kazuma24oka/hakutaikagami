# 部隊・軍令配送・個人認識・小規模地図の統合

後続の通常Mainは [作戦線と連続地図](FORMATION_WORLD_V1.md)。この2部隊交戦検証は `Scripts/Show-MilitaryGrid.ps1` の明示入口で維持する。以下の302件等は初回実装時の記録で、現在の回帰結果はruntime-reportを参照。

2026-10-19。ユーザーの「4まですすめて」に対応した実装・検査記録。既存の3D外見を再生成せず、通常Mainと通常保存へ接続した。Confirmedを変更せず、軍事数値・視界・地形粒度は検証用の `military-grid-v1` に分離する。

## 4項目と実装の境界

|項目|実装|検証|
|---|---|---|
|部隊と指揮権|軍勢の所属組織・総指揮官、部隊の所属軍勢・現地指揮官、行為者別の指揮権を別定義|別部隊への越権、権限失効、指揮官変更、役職・所属の不変、同一指揮官の二重所在を検査|
|軍令と既存配送|既存MessageFlowへ移動・交戦許可付き進軍・撤退・取消、結果返書と戦場報告を接続|紛失、失敗報告の配送、再送、原本の遅着、期限・取消、代理受領、結果返書・情報報告の再送|
|戦場認識|真実・目撃・伝える報告・配送・個人の認識・描画用データを分離|未発見の相手を表示しない。古い報告を現在値へ更新しない。不在確認も個別に伝わる|
|小規模地図|11×7、街道・平地・林・川・橋・岩、経路探索・接敵・交戦・退路|川を泳いで抜けない、地形コストと経路進捗を保存、橋越えと撤退を実画面で確認|

これは通常ゲームへ接続した技術検証であり、全国規模の軍制・徴兵・軍事AI・戦争の最終設計が完成した意味ではない。

## 確認方法

入口は `Scripts/Show-MilitaryGrid.ps1`。通常Mainの「部隊・軍令・地図」タブを開く。

1. 「演習部隊を配置」。視点は太郎・次郎・三郎で切り替えられる。これは認識を検査する開発用操作で、正式ゲームの他人への閲覧権限を実装した意味ではない。
2. 行先を選び「移動命令」または「交戦許可付き進軍」を発送し、刻を進める。相手が見えていなくても、既知の地図上の地点へ進む命令は出せる。
3. 「配送試験の操作を表示」を開くと、相手側の明示的な進軍入力、軍令紛失、失敗報告、再送、原本遅着、期限の試験ができる。相手側操作は試験入力で、プレイヤーの通常権限ではない。
4. 目撃した情報を三郎へ報告し、三郎の視点で届く前後を比べる。金色の記憶マーカーは報告・記憶の場所を示し、現在の相手モデルではない。
5. 通常保存・復旧を使う。外見の既定変更・V3作成一覧からの割当も残している。保存は従来の `user://tax-prototype-v5.json`、V3の一覧ファイル自体は変更しない。

画面は既知の地形を全体表示し、選択武将から見通せる範囲を明るくする。未発見の部隊位置・兵数・士気は表示しない。地形全体が未知で探索される地図ではない。

## 1. 軍勢・部隊・指揮権

`ArmyDefinition` は軍勢ID・組織ID・軍勢指揮官・退路、`MilitaryUnit` は部隊ID・軍勢ID・現地指揮官・兵数・士気・位置・経路・行動を持つ。武将の政治上の所属・役職は既存Worldのまま。軍勢の所属、直属主君、軍事指揮、実際の服従を一括で書き換えない。

`MilitaryGrant` は行為者・対象部隊・対象軍勢・行為・管轄・権限根拠・期間 `[from,until)` を保持し、発送・到達・効力時に評価する。部隊の指揮官になっただけで委任を新設しない。軍勢指揮官と部隊指揮官は別に指定できる。今回の同時2部隊では同じ現地指揮官を二重に置けない。

赤青は同じ既存家中の武将を使った演習で、対抗関係を `MilitaryHostility` に明示している。軍勢IDが違うだけで自動的に敵対しない。所属や政治的離反を変更せず、総指揮官・現地指揮官の現実の就任・移動手続も今回実装していない。

## 2. 共通配送・認識・効力

別の軍令用配送エンジンは作っていない。通常セッションの同じ `MessageState` と既存 `MessageFlow` を使用する。

|段階|保持するもの|
|---|---|
|論理軍令|同一内容の命令ID、行為者・受領者・部隊・地点、期限、効力時刻、取消対象|
|物理配送|共通のmessage/attempt、紛失・再送・遅着、正式受領|
|個人認識|本人が軍令本文を知った時刻。正式代理受領だけでは本人の認識・履行を開始しない|
|判断・効力|指揮権・現地指揮官・検証用の服従意思・期限・競合を再評価|
|結果返書|担当者が知り得た判断結果を共通配送で発行者へ返す。結果返書の再送で命令を再実行しない|
|戦場報告|送り手が実際に知った観測を固定し、観測時刻を保持して共通配送する|

紛失の真実だけで発行者へ失敗を教えず、失敗報告を受領してから再送可能とする。失敗報告自体の紛失も知識を発生させない。再送と遅着原本は同じ論理ID・正式受領・適用台帳を共有し、1回だけ適用する。3試行の上限は既存共通配送に従う。

軍令の期限は今回**着手期限＝指示の効力を発生させる期限**で、期限刻ちょうどは有効。移動先へ着く期限ではない。着手後の経路移動を、期限経過だけで勝手に中断しない。指定効力時点が着手期限を過ぎる軍令は開始できない。

取消は受領者の認識と指定効力時点の両方を満たしてから作用する。発送だけでは部隊を止めない。同じ刻では取消を対象命令より先に因果評価し、過去の位置や損害は巻き戻さない。古い命令を取り消しても、別の新しい命令へ移った部隊を止めない。相反する同時刻の軍令は今回まとめて拒否し、登録順で先着優先を作らない。

命令の返書と戦場報告の再送もCore API・単体テストで検査した。画面の再送ボタンは直前の軍令に対応し、返書・戦場報告の詳細な配送管理UIは未実装。

## 3. 知識と表示を分ける契約

`MilitaryDiagnostic` は試験用の真実スナップショット。描画クラスはこれも `OfficerState` の生状態も読まず、`MilitaryViewFor(observer)` と `AppearanceFor(character)` を使う。検査スクリプトは描画コードの真実API参照を拒否する。これは現在の実装境界の検査で、任意の将来コードの情報漏洩を自動証明するセキュリティ機構ではない。

観測は `ObservedAt`、報告の受領は `LearnedAt` として分ける。相手の兵数・士気・位置・指揮官は認識記録から表示し、古い記録へ現在の真実を混ぜない。古い報告が遅れて到着しても、新しい目撃を上書きしない。

自分の部隊は本人の把握を更新する。他部隊は視界内の直接観測、または届いた報告だけ。軍勢や家中が同じでも全員へ転記しない。送り手が知らない観測を報告しようとすると拒否する。報告を再送しても観測日・当時の数値は変わらない。

直接見ていない過去の情報は、日付付きの記憶マーカーで表示する。真実側で部隊が退場しただけではマーカーを消さない。既知地点が見えるのに部隊がいない場合は「その地点に姿がない」という新しい観測を作り、相手の新しい位置や兵数は教えない。その不在報告が届けば受領者の記憶も更新する。

敵の滑らかな移動は、前刻にもその武将が見た位置があるときだけ補間する。初めて目撃した相手の、見ていなかった直前位置を真実から引いて描画しない。

## 4. 地図・移動・接敵・撤退

地図は11×7、1セル1.5mの表示用規格。街道・橋1、平地2、林3の移動コスト。川は橋以外通れず、岩も通れない。4近傍の重み付きDijkstraで安定した経路を求め、同じ入力なら同じ経路を返す。経路探索が隠れた相手の位置を読んで回避することはない。

移動コストの途中進捗、残経路、直前／現在位置を保存する。保存された経路は歩行可能・隣接・行先／自軍退路への一致・循環なし・最小費用を検査する。複数部隊が同じセルへ入る、または入れ替わる衝突は両者を待たせ、先に登録された方を勝たせない。狭路での譲り合い・隊列・追越しは未実装。

視界はマンハッタン距離3以内と簡易遮蔽判定。林と岩は見通しを遮り、川は見通しを遮らない。正確な高低差・地形輪郭・夜間・天候の視界ではない。

交戦は、明示した対抗関係、双方の交戦許可付き進軍、直接見通し、到達可能な近距離を満たすと接敵段階に入り、その次の刻から同時損害を計算する。単なる移動同士や別軍勢であるだけでは開戦しない。モデルは部隊を代表しており、刀先の接触で損害を判定しない。

損害と士気は第1統合と同じ検証条件。赤100人・青60人から、赤の攻撃12・士気圧15、青の攻撃8・士気圧8。士気20以下で敗走する。同じ損害前状態から双方の結果を出し、兵数＋損害台帳の整合を保持する。

撤退・敗走は所属軍勢の退路へ経路を作り、橋も使って移動する。退場地点に到達して初めて部隊の真実状態を退場にする。部隊、生存兵、指揮官、政治的所属は削除しない。情報がない他の武将に退場を瞬間通知しない。

## 保存と互換性

通常v5保存の `Officers.Military` にschema1で保持する。従来の外見・共通配送・徴税・乱数と同じコピー→検証→公開トランザクション。失敗した刻では軍事・配送・徴税・知識をまとめて巻き戻す。停止時は共通刻と表示位相がともに止まる。独立した戦闘時計はない。

Militaryがない過去の保存はそのまま読める。前回の `FieldBattle` を持つ保存を新しい地図へ勝手に変換せず、保持して案内する。旧表示は `Scripts/Show-OfficerWorld.ps1` で復旧できる。新しい演習を始める場合は世界初期化が必要で、保存ファイル自体は削除しない。旧Fieldと新Militaryの同時起動は拒否する。

未知のMap/Rules/Schema、武将・軍勢・権限参照の破損、負数・重複効果、兵数・士気台帳不一致、経路・着手時刻・報告の出所不一致を含む保存は、現在のセッションを部分変更せず拒否する。前方互換性は保証しない。
