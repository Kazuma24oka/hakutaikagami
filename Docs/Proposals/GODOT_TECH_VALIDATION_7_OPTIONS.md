- **依存**：Godot描画・カメラ・素材規格。
- **合格条件（案）**：武将とUIが背景に埋もれず、カメラ変更でも破綻しない。

## ⑦ セーブ・テスト
- **A**：現在画面だけ保存。例：徴税確定前後のセーブを読み戻し在庫・イベント一致の簡略版。
- **B（推奨）**：版付き保存＋未処理・適用記録・乱数を復元し自動／画面試験。例：徴税確定前後のセーブを読み戻し在庫・イベント一致。
- **C**：完成までセーブを後回し。例：徴税確定前後のセーブを読み戻し在庫・イベント一致を高度化。
- **D：その他（自由記載）**。D選択時のみ次のチャットで質問。
- **実装範囲**：徴税確定前後のセーブを読み戻し在庫・イベント一致。
- **依存**：①〜⑥の状態定義・保存境界・乱数。
- **合格条件（案）**：再ロードで二重適用ゼロ、同一入力で同一結果、破損時に安全失敗。
- **不合格時の代替方式**：テスト用の決定的スナップショット形式へ縮小。
- **保留**：計測環境・閾値・データ形式・細部のUI／例外処理。

## 検証順序と判定
1. **準備**：Godot 4 .NET対応版とSDK、Windows向け出力、採用素材のライセンスを確認。
2. **並行トラック**：描画①→パーツ②→アニメ③→会話④、およびドメイン⑥→時刻⑤→保存⑦。
3. **統合**：同じ武将IDで会話と徴税を表示し、セーブ／ロード後も状態が一致するか確認。
4. **採用ゲート**：①〜⑦の必須シナリオを実機検証し、致命的な表示・整合・復旧不具合がないこと。計測閾値・試験件数は別途決定。
5. **不合格時**：項目別に代替方式へ切り替えて再試験。Godot自体の正式採否は結果を比較して別途決定。

## P0/P1整合と責任分界
- F01/F04/P0-A01：身分・役職・委任と操作権限を分離。例：陪臣の越権試行と正規命令を混同しない。
- F02/P0-A02：共通時刻、因果・効力時点、世界停止と行動中断を分離。自動進行＋任意停止は**正式未決定**。
- F03/P0-A04：所有・引当・消費と数量整合を分離。例：米100を二重引当しない。
- F07/F08/P0-A06：NPC認識・命令配送・案件・履行・報告を分離。例：内応の打診と承諾を別管理。
