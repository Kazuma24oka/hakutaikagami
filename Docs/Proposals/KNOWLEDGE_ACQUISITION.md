# 未確定：情報を認識したと判定する条件

状態：検討中。すべて設計案であり、確定仕様ではない。

## 基本方向
閲覧権限を持つだけでは情報を知ったと判定しない。実際に「報告を受領」「資料を閲覧」「現場を目撃」した時点で、個人の認識情報へ登録する方式を優先検討する。

## 認識の契機
| 契機 | 認識時点の案 | 注意 |
|---|---|---|
| 報告受領 | 使者・書状・口頭報告が本人へ届き、内容を受領した時点 | 配達完了と本人の認識は区別する余地がある |
| 資料閲覧 | 本人が書状・記録・地図等を実際に確認した時点 | 閲覧権限のみでは認識しない |
| 現場目撃 | 本人が事件・軍勢・施設等を観測した時点 | 観測範囲外や隠蔽情報は認識しない |
| 噂を聞く | 本人に噂が伝わった時点 | 真実とは限らず情報源・確度を記録 |
| 組織共有 | 勢力・家臣団が情報を保有しても個人には自動付与しない | 明示的な閲覧・配布・会議参加などが必要 |

## データと処理の分離案
- AccessPolicy：現在、どの情報にアクセスできるか。
- Delivery/Observation：報告到達、閲覧、目撃などの実際の認識契機。
- KnowledgeRecord：本人がいつ何を知り、どの程度信じているか。
- EventTruth：実際の事実。本人の認識と混同しない。
- 所属変更でAccessPolicyが失効しても、過去に生成したKnowledgeRecordは保持する。
- 主人公への通知・自動停止は、情報の認識時点で重要度を再評価する。ただし直接の危険は現場イベントとして処理する。

## 実装・負荷の検討
- 全国の全武将へ組織共有情報を一括複製しない。
- 個人認識はイベント駆動で登録し、同一報告の重複認識を抑制する。
- 報告の受領時刻、認識時刻、情報の発生時刻を分ける。
- NPCが情報を読む・聞く行為をどの粒度でシミュレートするかは未決定。

## 未決定事項
1. 配達された書状は自動的に読んだと扱うか、開封操作を必要とするか。
2. 会議や軍議での一括伝達を参加者全員の認識とみなすか。
3. 部下への情報伝達の委任、伝達漏れ、誤解、偽情報の扱い。
4. NPCの認識イベントをどこまで詳細に処理するか。
5. 見聞きした情報の部分認識、曖昧さ、再確認、訂正の表現。
6. 情報到達時にプレイヤーが別画面・合戦中・一時停止中の場合の通知処理。

ユーザーが明示的に確定するまで Confirmed には反映しない。
