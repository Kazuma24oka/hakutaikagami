**状態：未確定（Proposals）／2026-10-17。** 6項目ともユーザーがB案を優先検討として選択済み。具体的な実装・例外は未確定。既存のF02・P0-A02/A04・P0-R01〜R04に整合する実装候補を比較する。**基本原則は既に確定しているため、今回の追加確定は行わない。**

## ① イベントIDの生成方式
- **A**：種別＋時刻だけでID生成。例：同時刻に二つの徴税があるとIDが衝突。
- **B（推奨）**：安定した発行主体・連番等を組み合わせて論理イベントを識別し、派生・再送を関連付ける。例：徴税命令の再送は元IDを参照し、別の徴税命令は新ID。
- **C**：毎回ランダムIDを作り再試行も新規扱い。例：ロード後の再試行で別イベントになり二重徴税。
- **保留**：発行主体の一意性・連番永続化・派生ID・複数端末相当の衝突。

## ② イベント処理状態と適用記録
- **A**：未処理／処理済みだけを管理。例：途中失敗の輸送が処理済みか判定できない。
- **B（推奨）**：受付・待機・実行中・確定・失敗／補償待ち等を区別し、効果の確定記録と対応付ける。例：米の引当後に中断しても確定済み出庫かどうか判定。
- **C**：状態を保存せずロード時に再計算。例：再ロード時に徴税を再実行してしまう。
- **保留**：状態遷移の厳密な定義・履歴圧縮・中断と取消。

## ③ 因果関係と循環依存
- **A**：登録順だけで解決。例：落城が先に登録され援軍が無効になる。
- **B（推奨）**：依存グラフで前提を評価し、循環や未解決依存は保留・検証エラー・制度別裁定へ分岐。例：援軍と開城が互いの成立を条件とするなら自動的に両方成功させない。
- **C**：循環時は全イベントを同時成立。例：城が開城済みかつ未開城になる。
- **保留**：循環検出の単位・保留期限・エラー時のゲーム進行。

## ④ 独立イベントの競合解決
- **A**：常に先着登録順で確定。例：二勢力の徴税が同時なら登録順で全額配分。
- **B（推奨）**：同じ状態に競合する更新を検出し、権限・効力時点・在庫引当など制度別の裁定規則に委ねる。例：米100俵への各80俵の請求を二重計上せず、優先権を別に判断。
- **C**：常にランダムに勝者を決める。例：開城と援軍の先後が毎回抽選になる。
- **保留**：タイブレーク・資源配分・開城効力・返答期限境界。

## ⑤ 途中失敗・復旧と補償
- **A**：失敗した処理は途中状態のまま続行。例：兵糧が出発地と到着地の両方にある。
- **B（推奨）**：整合単位の確定・再試行・補償を組み合わせ、補償自体も追跡可能にする。例：輸送が途中失敗したら二重出庫を防ぎ、必要な返還を記録。
- **C**：失敗を常に成功扱い。例：未到着の兵糧を到着済みにする。
- **保留**：トランザクション境界・補償の失敗・通知との同期。

## ⑥ セーブ再現性と乱数
- **A**：世界時刻と現在値だけ保存。例：未処理イベントと乱数状態が消える。
- **B（推奨）**：確定状態・未処理キュー・必要な乱数状態・適用記録を保存し、同じセーブから同じ条件で再開可能にする。例：ロードしても既に落城した城が二重に陥落しない。
- **C**：ロード時に全イベントを新規抽選。例：同じセーブを読むだけで処理済み結果が変わる。
- **保留**：乱数ストリーム・保存粒度・バージョン移行・再現性テスト。

## 確定済み原則との重複・整合性
- **確定済み**：イベントの一意性、適用状態、因果依存の優先評価、整合単位での復旧、必要な状態・乱数の保存は[イベント信頼性原則](../Confirmed/P0_EVENT_RELIABILITY_PRINCIPLES.md)に記載済み。
- **今回の新規比較**：IDの構成方法、処理状態の具体的段階、循環依存の扱い、制度別競合の接続方法、補償の追跡、乱数・保存の方式。
- **同時刻11項目**：[統合案](P0_SIMULTANEOUS_EVENTS_CONSOLIDATED.md)の期限・権限取消・落城／援軍・二重徴税の競合判定を尊重。③④のB案でも最終優先順位は未決定。
- **情報・外交・会計**：書状の再送と元の外交案件を区別し、引当・出庫・消費の二重計上を防ぐ。
- **帰属**：家督・独立・落城の複数状態更新を途中失敗後も整合させる。
- **判定**：B候補は既存Confirmedと直接矛盾しない。A/Cには一意性・復旧・再現性の確定要件に反する方式がある。採用には確定仕様変更が必要。
- **依存順**：①ID → ②処理状態 → ③因果依存 → ④競合裁定 → ⑤失敗復旧 → ⑥セーブ再現性。
- **未確定**：具体的なIDアルゴリズム、状態遷移表、循環依存の処理、競合の優先規則、トランザクション境界、補償方式、乱数ストリーム、セーブ互換。
