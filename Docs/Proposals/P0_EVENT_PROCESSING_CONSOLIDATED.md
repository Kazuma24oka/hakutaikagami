## 重複と設計責任
- **基本①＋詳細①**：イベントの論理同一性が確定原則。発行主体・連番・親子IDは未確定の生成方式。
- **基本②＋詳細②**：二重適用防止は確定。受付・待機・実行中・確定・失敗などの状態遷移は未確定。
- **基本③＋詳細③＋詳細④**：因果依存を先に評価し独立競合を制度別裁定に渡す契約は確定。依存グラフ、循環検出、競合の具体的な勝敗は未確定。
- **基本④＋詳細⑤**：整合単位の確定と安全な復旧は確定。補償の追跡、失敗時の具体的手順は未確定。
- **基本⑤＋詳細⑥**：再開整合性と必要な状態・乱数保存は確定。セーブ形式・乱数ストリーム・互換は未確定。

## 確定仕様との整合性・注意点
- F02/P0-A02：共通世界時刻と因果・効力時点・依存関係の評価を維持。登録順だけの競合裁定を採用しない。
- P0-A04：資源の二重計上を防止。再送書状や派生イベントの識別を誤ると、取引二重実行が起こるためIDと効果を別々に扱う。
- P0-R01〜R04：一意性、適用状態、依存評価、整合復旧、セーブ継続整合性は既に確定済み。**今回新たな基本原則は確定しない。**
- 同時刻イベント11項目：権限取消／代理受領、返答期限、落城／援軍、二重徴税、軍令／通知の具体的裁定は本書の共通機構に接続するが、最終優先順位は未決定。
- **注意すべき表現上の衝突**：先行比較には「B優先・未確定」と記されているが、Bの一部は後にConfirmedへ確定済み。現行の確定範囲はConfirmedを優先し、先行比較は選択履歴として扱う。
- **直接的な基本矛盾**：確認されない。ただし循環依存の保留が無期限になればゲーム停止を招くため、期限・エラー・裁定への移行条件が必要。

## 依存関係・残課題
1. **P0**：イベントIDの衝突防止、適用状態の整合と重複防止、循環依存の停止条件、競合裁定のインターフェース。
2. **P0**：更新単位と補償失敗時の復旧、セーブ中断と再ロード、適用記録の永続化。
3. **P1**：徴税・外交・落城・軍令等の制度別裁定、通知集約、遠方AIと合戦の同期。
4. **P2**：ID構成の最適化、履歴圧縮、セーブサイズ、性能、デバッグUI。
- **推奨順**：ID・状態 → 因果／循環 → 競合 → 整合更新／補償 → セーブ再現性 → 領域別のケーステスト。
