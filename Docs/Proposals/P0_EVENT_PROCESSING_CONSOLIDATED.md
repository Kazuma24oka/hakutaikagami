- **基本③＋詳細③④＋例外①②**：因果依存と制度別競合。循環検出と具体的な裁定規則は未確定。登録順のみで勝敗を決めない。

- **基本⑤＋詳細⑥＋例外⑥**：セーブ再現性。未処理・確定済み・補償待ちの区別を保存する。
- **基本①②＋詳細①②**：イベントID・処理状態。補償イベントにも識別子と適用記録が必要だが、具体的なID生成は未確定。
- **既存Confirmed**：F02、P0-A02/A04、P0-R01〜R04の一意性・因果評価・数量整合・復旧・保存の基本原則を維持。新たな独立基本原則の確定は不要。
- **潜在的な衝突**：①循環の保留を無期限にするとゲーム進行停止、②補償の再実行で二重返還、③確定済みの書状到達・NPC認識をロールバックで消すと情報設計と衝突。B案はこれらを回避する方向だが解除条件・補償境界は未決定。
- **依存順**：イベントID → 状態・適用記録 → 因果・循環 → 制度別競合 → 確定境界 → 補償・再試行 → セーブ継続。
- **優先課題（P0）**：循環解除・競合裁定インターフェース・更新確定境界・補償の一意性・再試行と保存の整合。
- **P1/P2**：P1＝外交／合戦／徴税等の具体的裁定、P2＝履歴圧縮・セーブサイズ・デバッグUI・性能。

## 23項目の横断レビュー・完了判定

### 重複・責任分界
- **基本①②＋詳細①②＋残④**：ID・適用記録・補償イベントの一意性。補償IDの構造は未決定。
- **基本③＋詳細③④＋例外①②＋残①②**：因果・循環・同時刻競合。共通基盤が整合を保証し、制度別裁定が徴税配分や落城結果を決める。
- **基本④＋詳細⑤＋例外③④⑤＋残③④⑤**：確定境界、ロールバック、補償、再試行。書状到達やNPC認識を過去へ遡って消さない。
- **基本⑤＋詳細⑥＋例外⑥＋残⑥**：セーブ整合と復旧。確定済み・未処理・補償待ちを区別する。

### 矛盾・未解決の境界
- **原則の直接矛盾なし**：F02、P0-A02/A04、P0-R01〜R04の基本原則と23項目のB優先案は整合する。
- **未解決①**：循環を保留し続けると停止する。保留解除期限・失敗への移行条件を要する。
- **未解決②**：権限や期限の再評価は、既に成立した効力まで取り消すことを意味しない。初回効力時点・再試行時点・追認の区別が必要。
- **未解決③**：補償不能・補償失敗の状態を無条件に成功としない。不可逆な情報伝達やNPC認識の扱いは別途検討する。
- **未解決④**：セーブ時の確定境界とイベント適用記録がずれると二重適用を招く。保存単位と復旧テストが必要。

### P0の完了条件と判定
- **基本方針の確定：完了**。共通時刻・因果評価・数量整合・イベント一意性・重複防止・整合復旧・セーブ継続はConfirmedで定義済み。
- **詳細設計の確定：未完了**。循環解除・競合インターフェース・確定境界・補償失敗・再試行効力・スナップショット方式は未確定。
- **実装準備完了：未達**。イベントID・状態遷移表・テストケース・セーブ互換・異常終了復旧の具体仕様が必要。
- **P1への並行移行：可能**。外交・徴税・落城等の制度別裁定を検討できるが、P0の上記未決定を「実装完了」と扱わない。

2. **P0**：補償失敗の状態管理、制度別裁定のインターフェースとテスト。
3. **P1**：徴税・外交・落城・軍令の個別裁定結果。
4. **P2**：セーブ容量・履歴圧縮・デバッグUI・性能最適化。
