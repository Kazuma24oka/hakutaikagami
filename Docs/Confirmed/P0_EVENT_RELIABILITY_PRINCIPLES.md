# P0イベント処理の信頼性：追加基本原則（確定）

**確定日：2026-10-17／design/foundationのみ。** ユーザーから委任された合理的な基本原則の確定権限に基づく。F02、P0-A02、P0-A04等の既存原則を変更せず、イベント処理の信頼性に固有の要件を追加する。実装方式は未確定。

## P0-R01 イベントの一意性と重複適用防止
同一の論理イベントを識別可能にし、**同じ効果を意図せず複数回適用しない**ことを共通要件とする。再送・再ロード・復旧を理由に現物や権利が重複生成されてはならない。
- **例**：年貢徴収の完了後にロードしても同じ徴収が二度適用されない。
- **保留**：IDの生成方式、重複判定の範囲、イベント分割と派生イベントの識別。

## P0-R02 整合した状態確定と失敗時復旧
イベントの途中で失敗・中断しても、**資源・帰属・権限・案件状態の整合性を損なわない**ように処理・復旧する。途中結果を無条件に確定しない。
- **例**：兵糧を輸送中に保存処理が失敗しても、出庫と入庫の両方に同じ米が存在しない。
- **保留**：原子的更新の単位、補償処理、チェックポイント、失敗時の再試行方針。

## P0-R03 セーブ・ロード後の継続整合性
セーブ・ロードによって、**既に確定したイベント効果と未処理イベントの区別**を失わず、ゲームの進行結果を不意に変更しないことを要件とする。
- **例**：落城直後のセーブを読み込んでも、落城処理が再発生して守備兵が二重移籍しない。
- **保留**：保存形式、乱数状態、イベントキューの保存粒度、バージョン移行。

## 確定範囲
