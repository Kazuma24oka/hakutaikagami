# P0イベント処理の信頼性：追加基本原則（確定）

**確定日：2026-10-17／design/foundationのみ。** ユーザーから委任された合理的な基本原則の確定権限に基づく。F02、P0-A02、P0-A04等の既存原則を変更せず、イベント処理の信頼性に固有の要件を追加する。実装方式は未確定。

## P0-R01 イベントの一意性と重複適用防止
同一の論理イベントを識別可能にし、**同じ効果を意図せず複数回適用しない**ことを共通要件とする。再送・再ロード・復旧を理由に現物や権利が重複生成されてはならない。
- **例**：年貢徴収の完了後にロードしても同じ徴収が二度適用されない。
- **保留**：IDの生成方式、重複判定の範囲、イベント分割と派生イベントの識別。

## P0-R02 整合した状態確定と失敗時復旧
イベントの途中で失敗・中断しても、**資源・帰属・権限・案件状態の整合性を損なわない**ように処理・復旧する。途中結果を無条件に確定しない。
- **例**：兵糧を輸送中に保存処理が失敗しても、出庫と入庫の両方に同じ米が存在しない。
- **保留**：原子的更新の単位、補償処理、チェックポイント、失敗時の再試行方針。

## P0-R03 セーブ・ロード後の継続整合性
セーブ・ロードによって、**既に確定したイベント効果と未処理イベントの区別**を失わず、ゲームの進行結果を不意に変更しないことを要件とする。
- **例**：落城直後のセーブを読み込んでも、落城処理が再発生して守備兵が二重移籍しない。
- **保留**：保存形式、乱数状態、イベントキューの保存粒度、バージョン移行。

## 確定範囲
- 既存の「因果・効力時点・依存関係の評価」「資源の数量整合」は再確定しない。今回追加するのは**イベントの重複適用防止、障害時の状態整合、ロード後の継続整合性**という共通品質要件。
- **未確定**：[ABC比較と詳細](../Archive/P0_EVENT_RELIABILITY_OPTIONS.md)に記載するイベントID方式、同時刻の厳密な優先順位、失敗復旧アルゴリズム、セーブ形式・乱数管理。
- mainは変更せず、資料内容の永久削除を行わない。

## P0-R04 信頼性を満たす共通処理契約（2026-10-17追加確定）

ユーザーが選択したB案5項目から、R01〜R03の品質要件を満たすための**実装方式に依存しない共通処理契約**のみを追加確定する。

1. **安定した論理イベントID**：一つの論理イベントには再送・再試行後も同一性を維持できる一意IDを付与する。**例**：徴税書状の再配送で同じ徴税要求を新規徴税と誤認しない。
2. **適用状態の追跡**：イベントIDと適用済み状態を対応付け、同じ効果を一度だけ確定する。**例**：年貢徴収後のロードで再徴収しない。
3. **依存解決後の競合裁定**：同時刻イベントは因果依存を先に評価し、独立した競合は明示的な制度別裁定規則に委ねる。**例**：援軍到着と開城の前提を照合した後に城内占有を判定する。
4. **整合単位での確定と安全な復旧**：関連する状態更新を整合した単位で確定し、失敗時は再試行または補償により整合状態へ復旧する。**例**：輸送中断後も米が出発地と到着地で二重計上されない。
5. **再開に必要な状態の保存**：確定済み効果・未処理イベント・進行に必要な乱数状態を保存し、ロード後の継続整合性を保つ。**例**：落城済みイベントがロード後に再実行されない。

**既存確定原則との関係**：R01〜R03、F02、P0-A02/A04を置き換えない。今回の追加はそれらの要件を満たす共通処理契約に限定する。

**未確定**：ID生成アルゴリズム、イベント状態のデータ構造、循環依存とタイブレーク、失敗復旧の具体的トランザクション・補償方式、乱数の保存形式、セーブデータのバージョン互換性。詳細とABC比較履歴は[Proposals](../Archive/P0_EVENT_RELIABILITY_OPTIONS.md)で管理する。mainは変更しない。
