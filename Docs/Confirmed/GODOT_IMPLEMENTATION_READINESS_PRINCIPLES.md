# Godot技術検証：実装準備7項目の確定基本方針

**決定日：2026-10-18。** ユーザーは7項目すべて推奨B案を採用。これは検証実装の準備方針の確定であり、Godotの実機合格・正式採用・製造開始の承認ではない。

1. **プロジェクト構成**：Godot本体と独立C#ゲームロジックを分離する。例：徴税判定をGodot画面なしでテストする。
2. **フォルダ構成**：機能別ディレクトリと共通基盤を併用する。例：Characters、Commands、Events、Coreを区分する。
3. **C#クラス**：世界状態・コマンド・イベントの責務を分離する。例：WorldState、CommandProcessor、EventSchedulerを独立させる。
4. **武将パーツ規格**：共通素体とパーツID・Pivot・レイヤー順を管理する。例：顔と兜を交換しても位置がずれない。
5. **テストデータ**：固定Seed・武将3人・城1つを基本とする。例：同じ徴税イベントを同条件で再現する。
6. **実装順序**：C#基盤と武将描画を並行検証し、後から会話・時間・保存を接続する。例：パーツ表示と徴税ロジックを別々に試験する。
7. **合格方針**：表示・操作・資源／権限整合・保存復旧を検証する。例：ロード後も徴税を二重計上しない。

## 整合性と未確定境界
