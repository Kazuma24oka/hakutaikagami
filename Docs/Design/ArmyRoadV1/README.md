# 自軍の拠点間行軍と現地調達

実装前基準：approval-baseline-v14.json。新規v16のみ。許可を得て引き受けた同じ部隊を本人が率い、共通の陸路・時計・通行止め判定で拠点間を移動する。貸与元/元の蔵/名簿/軍務原本は変えず、部隊の現在の集合地を別に持つ。到着は拠点周辺であり城の支配・入城権を自動生成しない。

既知経路の見込み兵糧を用意してから出発。迂回で次の区間の兵糧が不足する場合は、実際の区間始点で停止する。消費を道路行軍/帰還前の在外待機/既存の現地展開へ分け、二重消費・将来米の借用を防ぐ。元の拠点へ戻ってから貸与兵糧/返報/指揮返還を処理する。

到達した市場では本人の私財で自由在庫の米を実購入し、部隊の実容量へ移す。遠隔の家の財布や在庫は使わない。携行量2日分の現行試作値を保持し、長い行程は途中の拠点で現地調達する。海上の軍輸送・全国の補給隊・護衛/略奪・部隊と別れての広域個人行動は後続。旧v15以下は自動昇格せずバイト互換を保つ。

対象外：到着先での本人単独退避・広域別行動・局所伝令の一般化、城の占領と入城権の獲得。今回の到着先操作は本人と部隊が一緒に行う布陣・再集合・次の行軍・現地米購入。旧仕様の本人単独退避は元の拠点周辺の範囲検査を維持する。

## 操作と台帳

引受・元の軍用倉からの積載 → 行先選択/「部隊を率いて行先へ」 → 共通道路を実移動 → 到着先の周辺で布陣・再集合 → 必要なら「行軍の兵糧・現地購入」 → 次の行先/元の拠点 → 残米返納・返報・指揮返還。

元の家/集合地/倉/軍務caseは変更しない。現在の集合地点は、同じ軍務に属する最新の共通移動の実位置から導出する。途中停止ならその節点が集合地点となる。3隊の相対配置は本隊0m・左右±8m。行軍中も移動は既存の歩行速度と経路長、通行止め、途中の行先変更を使い、新しい独立時計を持たない。

試作用の兵糧は0.6kg/人/日、100人で60kg/日、携行上限120kg（既存の2日分）。行軍と帰還前の在外待機に消費し、現地展開中は既存の展開台帳だけで消費する。購入は整数kg、実市場の自由在庫/その時点の価格/本人の未引当私財/部隊の残容量を同時確認する。購入原本の再受付は再支払・再積載をしない。

出発前は知っている経路の見込み量を確認する。実際の道の閉鎖は進入時に初めて確認し、迂回・行先変更後に次の区間を賄えなければ始点で停止する。道中の位置を行先へ飛ばさず、残米と再出発可能な地点を保持する。

過去の行軍原本の再検査には、その時点までに観測・記録され、かつ本人が学習済みだった情報のみを使う。古い観測だからといって、後から学んだ情報を出発時点へ挿入しない。

## 検証方法

`python -X utf8 Scripts/verify_army_road.py` が関連Coreテスト、実世代保存と復旧後の将来一致、Gameビルド、画面なしGodotの実Node3D座標を同じソースで検査する。`--check-only` は保存した検証記録と現コード/実行ファイルの対応を照合する。GUI操作・描画品質・全国全機能の完成を示すものではない。
画面側だけの修正は、
python -X utf8 Docs/Design/ArmyRoadV1/refresh_game_verification.py
で、直前に成功したCore/Tests/参照データ/テスト実行ファイルが同一であることを全件照合してからGameのビルドと実Node3D検査を再実行できる。既存証拠のハッシュを先に検査し、Coreの実行記録を別の不変記録へ残す。Coreが変わった場合や、指定したUI以外の変更では再利用しない。この手順もGUI操作の合格を意味しない。
