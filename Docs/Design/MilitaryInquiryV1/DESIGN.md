# 軍務の物理照会・既知不達後再送

既存の created-career-military-v1 の初期世界/開始包/旧実物JSONを保持した追加操作。新しい開始世界へ切り替えて回復を装わない。仕官案件の本人照会を主君が物理受領したときだけ、その時点の主君自身の最新軍務記録と原本文を封じた military-status を発送する。主君の現在位置や他隊の真実を引用しない。未着返書は一覧に出さず、届いても開封前には引用を知れない。

開封済み返書の引用は本人の軍務認識に使えるが、原本の正式受領/PersonalKnowledge/原本の開封履歴を追加しない。条件期限は原条件の時刻のまま。許可を引用で知っても現地引受は別。原記録の出来事順で認識を選び、昔の許可/指揮中という返答の遅着・後開封で、新しい指揮返還認識を巻き戻さない。

本人の軍務申し出/回答/返還願いは直近試行の不達報告を本人が物理受領してからだけ再送可能。MessageFlow.Retryを使い最大3便、原本ID/本文/期限を維持。宛先は既知の清洲のまま、発送元と経路は再発送時の実所在。失敗試行IDごとに再操作は受付済みとなり、別便を増やさない。

## 原本回収の限定

道路伝令の timer-only 遅着禁止は維持。軍務書状だけ、診断/シミュレーション事象として、失敗便の実経路上の失敗地点→登録済み宛先への局所陸上回収を登録できる。プレイヤーの遠隔探索コマンドではない。CourierRecoveries は省略可能で、旧世界はnullのまま旧JSON形を保つ。地形経路と所要秒/原失敗位置/受令者の到達時の実所在を固定。本人不在や期限超過なら受領を拒否する。回収便の位置を出すのは80m内の実目撃だけ。

今回の実GPU4ケースでの回収は、清洲で見つかった原本の局所引渡し（移動距離0、処理1秒）。非ゼロ距離の回収経路の実証、長距離/海路回収、一般書状への適用、発見確率AIは未実施。任意の将来時刻を指定して遅着させるAPIへ置き換えていない。

## 検証

条件書不達・許可不達・返還通知不達・原本再送+回収二重到達の4ケース。各6点の保存から別プロセス復旧、同じ後続の軍務引受/出陣/配置/帰還/返還/辞去/街道移動を行い、全世界ハッシュと本人情報/3D領域の完全一致を確認する。旧軍務開始/引受済みの実物JSONはbd631baの検証済みCoreから採取し、初期世界の再生成ハッシュも一致させる。
