# 既知対象の選択：次工程案（未実装）

前工程のKnowledge投影だけを選択肢の根拠にする。実部隊一覧をそのまま読むドロップダウンにしない。

完成条件5件：
1. 現在視認/過去目撃/受領した返書に現れる部隊のみ選べる。名称・情報源・確認秒・人数の時点を表示する。遠隔真値により並び順や候補の表示を変えない。
2. 「最後に知った地点へ」は既存PersonalMoveへ記録Positionを固定して渡す。対象の真現在地を後から追尾しない。本人だけの移動で、部隊への命令にしない。
3. 本人と部隊が別行動でなければ、この個人移動は既存規則に従い使用不可。現地合流・兵糧引継ぎ・撤退命令の受信証拠を選択しただけで作らない。
4. 選択した対象ID/情報源/記録位置と本人の経路を、途中保存/別プロセス復旧/同じ未来/3D表示で照合する。対象を見失ったときも未知位置へ選択先を置換しない。
5. 必要なビルド/テスト/実画面/現行証拠照合後に同ブランチcommit/push。重大な新判断がなければ次へ。

既存PersonalMove(A=選択した既知Position)の再利用を優先。新しい追跡命令や物理配送機構を同時に追加しない。個別分隊への命令配送は後続工程で受信役/権限/不達/原期限を一式で接続する。

保存復旧で「なぜその行先か」まで検証する実装案：既存PersonalMoveに任意のKnownTargetReference（対象ID、確認秒、記録位置、安定した根拠ID）を付ける。Aは同じ記録位置で固定し、原判断の時点の本人向け投影に一致することをCoreで検証する。未指定の旧PersonalMoveは変えない。新しい移動シミュレーターは不要。

根拠は日本語表示文字列を識別子にしない。直接観測は保存フレームの確定番号、返書は認識済み原本IDで特定する。UIには既存の読みやすい情報源名と確認秒を表示する。選択IDは任意のSavePresentation項目で同じ世代に原子的に保存し、旧省略形を維持する。ロード後に現在の認識にないIDを候補へ足さない。

追加で必要になる検査：偽造した根拠/未認識の返書/別部隊の根拠/将来フレームを拒否すること、行先決定後に対象が移動してもAと本人経路は変わらないこと、観測開始前の保存と古いPresentationに新項目を要求しないこと。

併せて検討する運用改善（未適用）：CoreのIncludeSourceRevisionInInformationalVersion=false。現SDKのMicrosoft.NET.GenerateAssemblyInfo.targetsで既定trueとGitSHA追記を確認済み。Coreソースが同じなのにcommit後の再ビルドでDLLが変わる点を解消する。初回は全テストを再実行してから、以後はCore入力/DLL/TRX完全一致時のみUI変更のテスト再利用を認める。現行の検証中ソースは変更しない。
