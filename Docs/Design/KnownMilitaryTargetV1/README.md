# 既知部隊の選択と記録地点への個人移動 V1

[実装前計画](PLAN.md)に基づき、本人の目撃・認識した返書だけを対象一覧へ出す。確認時刻と情報源を表示し、本人だけがその記録地点へ向かう。

## 完成条件5件
1. KnownMilitary投影にある部隊だけを選べる。世界の実部隊一覧や真位置で候補を補完せず、現在視認/過去情報・確認秒・情報源を表示する。
2. 既存PersonalMoveに任意のKnownTarget根拠を付け、Aを記録位置へ固定する。対象が後で移動・再観測されても発行済みのA/根拠/経路終端を変えず、自動合流・追尾・軍への命令にしない。
3. 根拠は直接観測の確定番号または認識済み返書IDで検証する。未認識/偽造/別部隊/古い現在入力の根拠を拒否し、原判断の再実行でも照合する。旧未指定PersonalMove・旧Presentationの省略形を維持する。
4. 選択IDはSavePresentationの同じ世代へ原子的に保存する。二場面計32保存点を別プロセスで復旧し、全世界・選択/根拠/固定行先・人物/部隊/伝令・実3D画像と同じ未来を比較する。
5. 全Coreテスト・必要な実GPU回帰・実画像/動画・資源解放・現行ソース/実行ファイルの照合後、同ブランチcommit/pushする。完成判定はverification.jsonを参照する。

## 適用範囲
- 本人が部隊と別行動で停止中のときに使える。120mの既存演習範囲と通行判定、現地1mの合流・兵糧引継ぎ・指揮返還を変更しない。
- 受信役0の返書だけで左右分隊の知識を増やさない。選択しただけで古いTroopSightingや正式受領を作らない。
- 移動中に新しい目撃があれば一覧の情報は更新されるが、「今回の行先」は発行した時点の記録であることを表示する。移動済み部隊への自動合流はしない。
- 三隊へ個別の配置/保持命令を物理配送するUI、実在勢力の敵対・開戦、最終視界/全国性能/最終HUD品質は後続工程。
- CoreのGit識別情報だけによるDLL差分を避けるため、SourceRevisionのInformationalVersion追記とSourceLinkをCoreだけで無効化する。ローカルのPDB・ソースデバッグは保持し、実ソース/実バイナリ/実コミットの追跡は検証記録で行う。異なる識別情報の二ビルドでCoreDLL全バイト一致を確認し、実コミット後も再確認する。テスト再利用は入力/DLL/TRX完全一致時だけ。
- 18秒・固定60fps動画は実際の個人移動と時系列の保存画面であり、実時間性能の測定ではない。

次の5件：本工程の実画面/保存検証とpush、分隊への物理命令、保存操作の待ち時間、実在敵対/許可、全国負荷。重大な創作判断がなければ継続する。
