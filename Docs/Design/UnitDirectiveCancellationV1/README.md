# 分隊原本を指定した物理取消 V1

前工程UnitDirectiveHoldingV1はc305a86165b5675d93c1f532bc937d1ec50b644dで5/5。1858件、27GPU、202比較と32保存地点は当時の実績。変更後の現行判定は本工程verification.jsonだけとする。

## 完成条件5件
1. 本人が発行した現在案件の原本と同じ受信隊の既知固定地点を明示し、取消も実物として配送する。未知の現在地を追尾せず、旧本隊撤退の取消と混同しない。
2. 実受令と指定時刻の遅い方で効力を生じ、原本・再送・実物遅着が同時到着しても対象原本だけを抑止する。発送だけでは止まらず、取消期限切れや受信者不在では効力を追加しない。
3. 対象原本による移動中ならその隊だけを停止し、完了・新しい命令・他隊・兵・所有・指揮返還を巻き戻さない。取消の停止記録は対象原本の発行順に属し、後発原本を追い越さない。
4. 将来効力は初回の待機返書と別の物理通知で本人へ返す。不達通知は実在保持者から受け取り、未受領結果を表示しない。三場面24保存地点から別プロセス復旧し、世界・認識・原本選択・位置・3Dと同じ未来を照合する。
5. 追加27件を含む全1885件、関連する実Godot回帰、実画像/動画と現在ソース・実行ファイルの一致を検査し、同じ作業ブランチへcommit/pushする。

## 境界
原本を選んだ取消配送と未来時刻・結果通知の工程。取消原本自体の再送/実物遅着は次の小工程で扱う。旧保存に新台帳・書状を遡及追加しない。80m視認、120m演習範囲、600秒通常期限は試作値。全国負荷、背景品質、通常画面の最終整理の合格を意味しない。

次の5件：取消の検証/push、取消原本自体の不達回復、実在勢力の権限、全国負荷、通常操作。重要な判断が必要になるまで継続する。
