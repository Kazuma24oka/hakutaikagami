# 撤退命令を対象とする物理的な取消 V1

既存の本人退避・部隊撤退の分離を維持し、本人が発した特定の撤退原本だけを取り消す。取消の発送、部隊受令、効力、本人の結果認識を別々に記録する。これは既存共通時計と物理書状契約への接続であり、戦争・外交・傷病・捕縛の新仕様ではない。

## 完成条件（5件）
1. 発送では止めず、実受令と指定時刻の遅い方で効力を発生させる。同秒の原本・再送・遅着を取消より先に適用しない。
2. 実行前の対象は抑止し、実行途中はその時点の実位置で残りだけ止める。完了・損害・消費を巻き戻さず、新しい別の命令を止めない。
3. 取消にも同じ期限・既知不達・最大3便・実物保持・物理遅着・一度だけの効力を適用する。初回不達を後から成功に書き換えない。
4. 未来の効力結果は別の伝令で返報する。実際の本人受領前に結果を表示せず、返報を落とした伝令の実保持も描画する。旧保存には新モジュールを補わない。
5. 通常入口から即時抑止・移動途中の未来取消・実物遅着を実GPUで動かし、各保存点の全世界・本人・部隊・伝令・3D表示と同じ未来を別プロセス復旧で照合する。全Coreテストと既存代表回帰、実画像・復号動画、現行ソース照合の後に同ブランチcommit/push。

## 規則
- 対象IDは最初に発送した撤退原本の判断ID。再送は対象・原文・期限を変えない。通常画面は自分の直近原本を対象にする。
- 取消が届かなければ効力はない。期限は到着時刻を含む。通常の600秒は技術試作用。
- 未来効力は max(最初の正式受領時刻, 指定時刻)。同秒は取消を先に確定し、対象だけを抑止する。異なる対象の取消停止命令が新しい原本を上書きした扱いにはしない。
- Stopped は3部隊の実位置を記録した保持命令。複数の同時取消は同じ停止を共有する。AuthorityEnded は既存指揮権を復活させない。
- Suppressed / Stopped / AlreadyStopped / TooLate / Superseded / AuthorityEnded は事実の区別。本人には届いた時点の返書の内容だけを表示する。未知の現在位置の探索はしない。
- 未来時刻の設定は公開Core入力で検証する。通常UIは受令時点の取消を選ぶ。任意の予約時刻編集UIは未実装。

## 証拠
`verify_unit_cancellation.py` → 実画像/復号動画点検 → `--finalize` → `check_unit_cancellation_binding.py`。runtime-local は再生成可能なローカル証拠、verification.json はハッシュと検証範囲。過去工程の結果は過去の実績として保持する。

次は、取消結果返報の不達回収・期限境界・対象が異なる新原本との競合を追加で点検し、その後に既存の生活・軍務を繰り返した時の資源と指揮権の整合を検証する。未承認のゲーム方針変更や新たな課金は行わない。
