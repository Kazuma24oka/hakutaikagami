# 発送者が確認できた証拠に基づく再送

取消と遅着の競合を調査中、相手が受領したが返書は未着の間に、再送選択肢が消えることで未知の受領を察知できる条件を検出した。既存の情報分離方針を満たすため、取消より先にこの境界を補強する。

完成条件は5件。
1. 新しい明示TransportPolicyで、確認していない遠隔の受領を再送可否へ使わない。直近便の不達を物理報告で知った証拠は引き続き必要。
2. 受令返書・物理照会の引用・発送者自身が1m以内で確認した実受渡しを、相手の受領を確認できた証拠とする。本人と部隊受信役へ同じ接触基準を適用し、位置が変わっても過去の証拠を保存から再現する。
3. 最大3便、原文/期限/過去の不達/正式受領を維持する。未確認の実受領後に重複便が届いても、正式受領・知識・命令効果は一度だけ。
4. 旧原本を書換えず、新しい再送入力だけで方針を選べる。旧JSONの未指定項目と共通MessageFlow既存5引数APIの規則を保持し、過去の自動再送を遡及変更しない。
5. 実際の再送選択肢・独立保存復旧・同じ未来・数値姿勢・実画素と代表回帰を検査し、同ブランチへcommit/pushする。

共通配送へ追加した6引数APIは、版を宣言したアダプターが発送者の証拠を検査した後にだけ利用する。未確認の実受領と既知不達後の遅着が両立する場合、同じ原本の次便を許す。既存APIの受領済み再送拒否は変更しない。追加便も上限3・期限・業務側重複抑止を守る。

部隊発の返書について、遠隔の受取人の正式受領は部隊自身の知識ではない。現地での受渡しを確認できない場合、既知不達に対する追加便が生じ得るが最大3便まで。成功を知らせる別の往復書状は未実装であり、世界の真値をその代用にしない。1mの確認距離は既存の接触試作値で、最終の視野/遮蔽調整済み値ではない。

verify_unit_sender_evidence.py → 実画面/動画点検 → --finalize → check_unit_sender_evidence_binding.py。verification.jsonは現在のソース・DLL・テスト・実画像を結ぶ。固定60fps動画は性能測定ではない。全景の技術用部隊表示と重なるラベルは、最終の認識別可視範囲・HUD品質として未採用。

次の5件：1.取消命令の配送/効力/途中停止、2.軍務再任、3.複数案件の識別、4.認識/敵対に基づく対象、5.全国負荷。重要な未承認判断が発生するまで継続する。
