# 主家別の軍務台帳（地域試作の接続完了）

## 目的と範囲

同じ武将が別の主家へ仕官した後、旧主家の兵・兵糧・損耗・返納・返報を保持したまま、新主家から別の軍務を引き受ける。新しい兵を無条件に複製せず、主家ごとの元帳を再利用する。既存の世界時間、配送、開封、現地引受、指揮返還の契約を省略しない。

## 完成条件（工程全体）

1. 主家・拠点の組に安定した台帳IDを割り当てる。武将・仕官契約・案件番号を変えても同じ駐屯軍のIDを変えず、別主家/別拠点の軍・倉・携行兵糧・部隊は衝突させない。
2. 旧台帳と現行台帳を同時保持し、旧主家の兵数・損耗・兵糧・返報・原本を変更せず、新主家の軍務を発行・許可・現地引受・帰還返納まで完了できる。旧主家へ戻っても初期化しない。
3. 台帳をまたぐ二重受付、旧主家の権限流用、返納前の切替、遅着の誤配、保存データの台帳差替えを拒否する。既存保存も読み込める。
4. 途中保存・別プロセス復旧・同じ未来操作で世界と3D表示が一致する。本人の認識前に旧主家/新主家の真実を表示しない。

## 実装済みの識別基準

Core/Contracts/NewGameMilitary.LedgerIdentity.csで、所有勢力IDと拠点IDのJSON配列をハッシュ化し、台帳・軍・倉・携行兵糧・3部隊に別々のIDを導出する。文字列の単純連結による境界の曖昧さを避ける。

既存台帳のExistingLedgerIdentityは実際に保存された軍IDと既存の倉/部隊IDの結び付きを返す。新規方式のIDに黙って置き換えず、兵数・資源・履歴・JSON保存形式を変更しない。ArmyEntryの組立てはこの結び付きを参照する。

識別子だけでは権限も資源も生まれない。新しい申出は版付きLedgerPolicyを原本へ固定し、最初の許可と現地引受を経る。OtherMilitaryLedgersへ旧元帳を保持し、FromLedgerで切替元を固定する。既存元帳は旧IDのまま再任し、新規元帳のみ主家・拠点別IDを使う。

## 接続した境界（次の拡張でも維持）

- ContractWorld.NewMilitaryの単一台帳から、保持する台帳群と操作対象台帳を分離する。既存optional JSONは維持する。
- NewGameMilitary.Sync/Net/Armies、世界全体の資産保存則、部隊宛原本の登録、過去入力からの再生検査を台帳ごとに処理する。
- 返報/兵糧/指揮返還を実受領し、本人が終了を確認した条件で操作対象を切り替える。遅着の配送先は原本に固定された台帳と案件に従い、現在の主君へ読み替えない。
- NewGameRuntimeの主家相談、部隊識別、選択対象、兵糧運搬、認識済み部隊、姿勢・保存復旧検査を同じ台帳参照へそろえる。
- 再仕官/元の主家への復帰、損耗あり、旧配送の遅着、未返納の拒否をCoreと通常入口の実画面で確認する。
