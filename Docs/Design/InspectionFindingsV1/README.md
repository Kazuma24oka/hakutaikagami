# 陸路の点検結果と次の行先

## この工程の完成条件
1. 新規ゲームの明示した版のみ、実際に現地で点検を完了すると隣接陸路の観測を残す。遠方や海路の状況は取得しない。
2. 観測時刻・距離・通行状況を本人の記録から表示する。後日の開通/封鎖で昔の観測を書き換えない。
3. 依頼主への観測返書は実配送・開封後にだけ認識される。完了返報と別の書状で、一度だけ実行する。
4. 下部会話UIで結果を見て行先を指定できる。指定だけでは移動せず、既存の出発操作で同じ本人が歩く。
5. 旧保存を変更せず、途中保存・別プロセス復旧の世界・3D画像・数値表示を照合する。全Coreテストと実GPU動作を確認して同じブランチにcommit/pushする。

## 固定仕様
InspectionPolicy=completed-local-land-road-observation-v1 を新規定義ハッシュとプロフィールに含める。省略時は従来のまま。最終実行時の物理位置、当時の道路状態、既存の個人Evidence/Knowledge/Sightingsに記録する。返書は既存Outboxと封書配送を使う。結果の表示は本人向け投影から取り、現在の隠れた真値で更新しない。通行可は確認時点の記録であり、出発成功を保証しない。遠方拠点の軍備・兵糧を推測して表示しない。

## 検証
verify_inspection_findings.py → 実画像/動画の目視 → --finalize → check_inspection_findings_binding.py。全2143件（追加21）のCoreテストを今回実行。単体では観測前後・封書・重複開封・旧プロフィール・6保存点を検査。画面では通常/小画面、任意依頼/命令、結果選択と歩行復旧、既存仕事/移動を検査する。動画はGodotの固定30fps録画であり実時間の性能測定ではない。最終実績はverification.jsonを正とする。

## 次の5作業
1. 点検結果に基づいた報告内容と相手の返答を、本人が実際に受け取る流れへ接続する。
2. 報酬・評価の既存設計との接続を調べ、実際の資源移転と評価時点を決める。架空の加点やお金を発生させない。
3. 既存の仕事を追加して、選ぶ理由と違いを画面に出す。
4. 仕事の選択から実行・報告まで続けて遊べる導線を確認する。
5. 一連の途中保存・復旧と3D表示を再確認する。

この工程は上記の最初の足場であり、報酬・評価・複数仕事を完成したとは扱わない。
