# 仕官・離職後の同一人生

開始選択の追加項目「浪人・仕官と離職後の継続」。既存の入口/開始/保存は維持。1560年・清洲の同じ成人作成人物が、申し出→条件の封書→同意/辞退の発送→主君の受領→合意効力→封書通知→本人の認識を進める。通常の新規開始は募集する主君の架空の試用合意。実在の任命史料や包括的な採用AIではない。

所属と直属は別の期間付き関係。軍・役職・所領・私有物資を自動取得しない。給与/出世/懲罰的人事/他家への仕官/同一Career開始での軍務任命は未実装。平戦往復の既存開始は保持し、今回だけで製品の一人分の全人生や全基本設計の実装完了と扱わない。

有効な同意は、提示から120秒の排他的期限までに主君へ到達する必要がある。本文/期限は開封後だけ見せ、同意クリックだけでは身分を与えない。通知前や通知不達では実際の関係と本人の認識が異なり得る。身分照会を新しい物理返書にして、不達の原通知を正式受領したことにせず認識を回復できる。

辞去の合意は、主君が実受領した自分の任務返報で引継ぎ確認後。検証ケースだけの「任務返報後の担当解除」は宣言した初期条件と実受領報告に基づく。罰や評価AIではない。失職しても同じID・外見・世界・時計・Seed・記憶・任務履歴・位置が続き、街道で甲府へ移動し任意の点検依頼を受けられる。

履歴は要求/通知/効力/開封の時刻と保存した順序を保持。後の関係変更で昔の命令種別を変えず、古い通知を後から開いても新しい関係を巻き戻さない。面談中のNPCは、自分の提示/解決の履歴だけで依頼の重なりを避ける。古いNPC入力JSONの追加項目は省略時falseで、書戻しも同じ形。

検証：verify_career.py→実PNG点検→check_career_binding.py。旧浪人JSONの実物はlegacy-fixture.jsonから履歴の検証記録へ結合。5ケース/29保存点を独立プロセスで復旧・続行し、同じ操作と保存時停止を再現して全世界ハッシュも比較する。画像と全世界ハッシュはそれぞれ58比較。
