# 主家兵糧の携行・消費・返還

別の補給付き演習開始で、主家在庫から最大200人日相当を携行する。所有者は主家のままで、保管者の実位置へ結び付く。登録拠点でだけ受渡しでき、操作IDの再実行・数量改変・在庫/容量超過を拒否する。

消費単位は人秒。一人日=86400。実際の自隊兵数と経過秒で計算し、損耗時刻の前後を分ける。連続する同兵数の区間をまとめ、停止/復旧/表示倍率から独立する。物資不足だけで兵・人物を即消滅させない。輸送隊/不足による疲労/生産/最終物価は未実装。

既存ResourceLotsの同じ数量へ積載/返還・消費台帳を結ぶ。MobileHolderがあるロットはSiteを登録拠点、実位置を本人のLocationStateとする。旧ロットはMobileHolderを出力せず従来のSiteを使用。旧交戦開始の実物検体と内容ハッシュ一致を検査する。

検査：全1094件（追加26）、実GPU36プロセス/既存136+新10=146比較。積載後・野外・損耗後・返報/帰還中・返還前の保存点を別プロセスから復旧し、同じ操作列の続行まで比較する。verify_field_supply.py → 実画像点検 → check_field_supply_binding.py。未検査の成功を宣言しない。

回帰中にGodot 4.5.2のSwapGCHandleForTypeで未初期化Handleエラーを一度観測した。素材参照を有限カタログの強参照で保持する対策を追加。単独の変更前48位置更新では再現せず、厳密なエンジン競合原因は未確定。対策後3プロセス/144位置更新と強制GCを検査し、変更前画像と3比較する。全体は39実GPUプロセス、146保存/続行比較+3素材寿命比較。失敗ログを無視/自動合格扱いにはしない。根拠はlifetime-baseline.json、[公式Resource資料](https://docs.godotengine.org/en/4.5/classes/class_resource.html)。城在庫の表示は整数人日、携行分は小数2桁。台帳は人秒で厳密に保持する。
