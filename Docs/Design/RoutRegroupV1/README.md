# 敗走・到達・再集結

BD-32/37/38/39/40と共通配送契約を保つ。対象は既存の架空演習。新しい歴史敵対や人物の死亡/捕縛は作らない。

## 完成条件
1. 新しい通常画面の交戦入力に移動ルールの版を固定し、過去の保存/接触結果へ自動敗走を遡及適用しない。
2. 士気閾値25で生き残った部隊だけの自動撤退を記録し、共通地形/相互予約を通る。本人が別行動なら部隊と兵糧だけが動く。通れなければ理由付き待機にして、現地の帰還命令で回復可能にする。
3. 退避先への到達・再集結待ち・再集結完了を独立記録。試作値60秒/士気50を適用し、兵や資源を増やさず、再集結前の正式入城/指揮返還をしない。
4. 一部だけの敗走、退路待機、遅い旧命令、改ざん拒否、途中保存と同じ未来を検査する。返書/不達の認識は既存MessageFlowの実到達後。
5. 通常入口の甲府/小田原/浪人開始で、本人退避・部隊敗走・届かない旧宛先の命令・再集結・残兵返報まで実GPUで実行。12保存点ずつを別プロセスで世界/実数/画像比較し、旧機能・材質も回帰。動画を点検して同ブランチへcommit/pushする。

## 保存と処理
`NewMilitaryInput.MotionContract`と`NewMilitaryState.Rout`を省略可能にする。既存の原本入力はnullのまま解釈し、新規の交戦入力だけ版を記録する。定義パックは変更しない。自動退避Order、各部隊の初到達、再集結完了を時計とRevisionへ結ぶ。本人/運搬実体/主家所有/命令の受領と効力を維持する。

部隊が崩れたことは武将の負傷/捕縛/死亡/政治的離反ではない。兵数は損害台帳のまま、再集結で復活させない。自動退避より前に出された旧伝令で退避を巻き戻さない。命令が不在の旧地点へ届いた場合も、真の現在地へ宛先を補正しない。

数値は技術検証用で製品の戦闘バランスではない。反復交戦/攻城/健康/捕縛/全国戦争AIと最終外観は対象外。次は部隊宛の照会・既知不達後の再送、再任/複数案件、観測/敵対の対象、全国負荷を継続する。重要な未承認事項だけをユーザーへ確認する。
