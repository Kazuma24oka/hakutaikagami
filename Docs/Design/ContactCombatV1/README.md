# 同一人物の明示演習交戦 V1

BD-23/26/32/37/39/40、EngagementMissionV1の明示的な架空演習を新入口の同一人物へ接続する。既存開始・史実勢力の敵対・主家所有・兵の貸与元・世界時計を変更しない。

## 完成条件
1. 接触の同時損害を共通化し、旧式との250固定乱数例、境界、相打ち、整数限界を検査する。
2. 貸与許可と交戦許可を分離し、主君・本人・演習対象・根拠・期間を封書へ固定する。物理到達だけで認識を作らず、照会も原本の開封と分離する。
3. 同時損害から残兵・士気・兵糧消費・発送時点の自隊返報を再構成する。損害で武将のLifeや主家所有を変えない。
4. 途中復旧・同じ未来・改ざん拒否と旧保存互換をテストする。
5. 通常入口から3Dで演習・損害・帰還・物理返報・指揮返還を実行し、別プロセスの世界・表示・実画像を照合する。実画像を点検して現行ソースと証拠を固定する。

## 実装の境界
- 交戦相手は利用者が申し込む「架空演習」の3組だけ。史実の外交・敵対勢力や人物を生成しない。許可対象 exercise:local-contact、根拠は既存貸与案件、期限は許可効力から120秒、接触は最大30秒。旧来の検証敵と同じ技術検証用で、実際の調練被害率・戦闘速度の製品採用ではない。
- 接触計算は既存式を保持（4.5m以内、高低差3m以内）。全員の損害を同一の事前状態から求める。敵側のrouted/withdrawingは攻撃を出さないが、まだ接触中なら被害を受け得る。
- 損害は開始・終了入力と共通時刻から一意に再構成し、保存に別の可変損害キャッシュを増やさない。兵糧は各秒の損害適用前の残兵数で消費する。返報原本は発送後の損害で変化しない。
- 軍務返還は残兵を100へ戻さない。帰還・残量返納・帰還後報告の主君実受領が必要。入隊/攻撃動作の完了から命中を決めない。
- 新入口の自動敗走経路、個人と部隊を分ける撤退、捕縛/負傷/死亡、実在勢力との戦争AI、全国戦闘負荷、最終バランスは次工程。士気低下を武将死亡や即消滅と扱わない。
- 演習接触中の新しい配置線は保留し、接触終了/帰還ができる。これは短い接触検証の境界で、移動中戦闘の完成を意味しない。
- 旧MilitaryNoticeのCombatは省略可能。既存開始包とDefinitionPackは書換えず、旧保存に新しいキーを出さない。新しい列挙値を含む保存は旧バイナリで無断に解釈しない。

## 表示と旧テストの検査強化
- 新入口の人物・部隊・演習相手の名称は、同じ世界位置を画面へ投影し整数画素へ配置する共通ラベルを使用する。復旧時のLabel3D文字輪郭の7画素差を検出して修正した。また識別子による描画順を固定し、人物名と部隊名が重なる際の作成順依存の2画素差も検査する。比較の許容差を広げない。
- 旧交戦の撮影はImage/ViewportTextureを解放し、各保存点の全世界JSON/hashも記録する。再開側で途中の停止操作を省いていた検査を修正し、同じ操作列を比較する。
- この架空演習は製品の調練コマンドではなく、損害を伴う交戦の技術検証である。

## 現行検証
`Scripts/verify_contact_combat.py` → 実画像点検 → `--finalize` → `Scripts/check_contact_combat_binding.py`。旧verification.jsonは当時の履歴とし、今回再実行したケースだけを現行の実測として扱う。固定60fps動画は性能測定ではない。マウス操作ツール・OS入力設定変更は行わない。

次工程は個人/部隊の撤退と物理的な指揮連絡、敗走/再集結、再任・複数任務、観測に依存する交戦相手、全国規模負荷。ユーザーの創作判断が必要な変更以外は承認範囲で継続する。
