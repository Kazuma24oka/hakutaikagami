# 仕事の判断画面 V2

ユーザー指摘：会話/自分の返答/選択肢の区別が付かず、判断に必要な情報が散在している。承認された改修は情報の集約と場面分離。仕事や報酬などの新ルールは追加しない。

完成条件5件：
1. 相談/引受は右列に「話者＋台詞」「場所・期限・報酬の要点カード」「あなたの返答」を上から順に集約する。選択肢は高さ54px以上の縦並び。閉じる操作は右上に分離。背後の画面は暗くして操作の競合を防ぐ。
2. 開封は仕事欄の同じボタンから実行できる。未開封内容の漏洩、相談取消時の命令生成、自動受諾を禁止。任意の引受/辞退と主従による命令を維持する。
3. 引受後は会話を閉じて地図へ戻る。仕事欄に対象と次の操作を集約。報告時は自分の報告と短い結果カードを表示し、依頼条件/開発上の説明を積み重ねない。返報の発送と相手の確認を区別する。既存の報酬未設定は「提示なし」として判断時に明示。
4. 任意依頼/主従の実操作と2保存地点ずつの別プロセス復旧、全世界/会話骨格/外見/表示文/実画像の一致を確認。1280×900と1100×720で文字/カード/返答の切れ・重なりを実画像で確認。ログは履歴に保持。Core317入力/TRX/DLLの完全一致時だけ2122件の成功結果を再利用。
5. 既存操作の回帰と短い実動画を検査し、同ブランチへcommit/push。main/design、素材、旧保存を保護。過去の検証と今回の検証を混同しない。

## 限界と記録
現地の点検そのもの、所要時間、書状、返報のルールは従来どおり。点検で得る新しい内容、報酬/評価、専用巡回モーションは追加しない。会話は状況説明用の創作。相手不在時は対面モデルを出さない。会話人物はIDで再利用し、モデルの作り直しによる不安定化を避ける。
実行中に会話ウィンドウを保持せず、地図の既存操作で進める。履歴の操作通知はこの画面内の最大200件、認識済み用件/書状は保存から再構成。UI開閉自体は保存せず、保存した知識から同じ画面を再表示する。
録画は実コード/シーン/データ/DLLを照合したコピーでviewportだけ1280×900へ変更。固定30fpsのため実時間の速度測定ではない。

次の五件：判断UIの検証/push、ユーザーの視認性確認、点検情報の具体化、報酬/評価と仕事選択、他の仕事への再利用。後続を今回の完成とは扱わない。
