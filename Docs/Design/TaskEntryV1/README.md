# 通常起動の武将任務タブ

ユーザー「はい」で入口追加を承認済み。通常Mainの末尾タブ「武将の任務」を選ぶと既存AssessmentNoticeTrialを初めて読み込み、その後の往復では同じセッションを保持する。旧タブ番号と既存機能・独立入口を保持する。旧管理検証と新武将ループは別セッションであり、異なる世界を勝手に同期しない。新ループの時間・知識・権限・保存形式を変更しない。

当初3行の差分案は既存タブ番号をずらすため、その機能を末尾への遅延読込として実装した。Main.csの入口呼出しとMain.TaskEntry.csが実装。通常起動経由の実GPU検査では初期画面、遅延生成、タブ往復、任務と評価通知/訂正/応答、別プロセス復旧と続行を確認する。

Scripts/verify_task_entry.py→実PNG点検→check_task_entry_binding.py。既存ローカル素材が必要。runtime-localは生成証拠で非追跡。以前の検証書は共有コード変更で失効し、今回の新規記録と回帰実行を証拠にする。

通常起動の初回検査で、旧布陣試作のゲート停止時に初期化途中のノードが残り、NullReferenceExceptionを繰り返す不具合を確認した。Mainの例外処理でその初期化失敗ノードだけを取り外し、再検査待ち案内を残す。旧ゲートの判定・検証書・有効化条件を緩めない。旧布陣の成功を今回の成果とは扱わない。

旧徴税の描画なし表示端検査は失敗したため、その成功は主張しない（diagnostic-headless-tax.log）。表示を伴う旧基盤/徴税/応答の回帰は実GPU・1100×720で行う。既存の検証画像は実行前に内容を保持し、今回の画像をruntime-localへ複写後に元の内容を戻す。復元後の一致も検査する。
