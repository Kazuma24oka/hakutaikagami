# 返報・依頼主の返答・現地報酬・次の仕事

## 完成条件（5件）
1. 依頼主は到達した報告と陸路原本だけを認識する。必要な原本が揃ってから既存AssessmentNoticeで封書を返し、本人は実到達・開封後に会話で読む。不達の報告は既知の失敗から元の面会場所へだけ再送する。
2. 新しい版の開始設定に私財1000文と任意点検の報酬20文を固定する。受諾前に額・条件を表示し、返答開封と現地面会の後だけ既存ResourceLot/TransferEntryで依頼主の私財から本人へ移す。一任務一支払い、資金不足では未払い債務が残る。軍務・家財と混同しない。
3. 本人が自主点検と現地の依頼を選び、相談→引受→実行→返答→報酬→次の仕事→移動まで続けられる。既知の返答・未受領分は一覧から再表示できる。下部会話帯・選択時だけの小枠・左右話者を維持し、履歴を常時大きく出さない。
4. 全2183件（追加40）を新しい入力で実行し、旧版省略JSON・6地点の保存復旧・不達再送・未開封・二重請求・資金枯渇・改変・同秒の確定順・軍務履歴との同居を検査する。通常/小画面、命令/任意依頼、不達の実画面と別プロセス復旧の世界/3D/数値を照合する。
5. 実際の短いGodot録画を目視し、証跡・入力・DLLを一致させて同じ作業ブランチにcommit/pushする。保護ブランチ・既存保存・素材は変更しない。

## 既存仕様との対応
BD-29/CC-11の「実行、返報、認識した評価は別」、BD-34の「個人/家/組織の財布と現物を分離」を適用。受領確認を功績・責任・処分の最終裁定に読み替えない。既存のAssessmentNotice/RespondAssessment、共通封書・伝令、ResourceLot/TransferEntry/DebtState/AppliedEffectを再利用する。独立試作のEnabled連鎖は広げず、新入口ではAvailableを明示する。

WorkPolicy=local-work-physical-reply-fee20-wallet1000-mon-v1とWorkCycleを明示した新規開始だけ有効。省略した旧開始・旧保存のハッシュと振る舞いは維持する。初期私財と報酬は試作の調整値で、史実の価格や最終バランスを確定するものではない。無報酬の自主点検・主君の点検命令で別払いを作らない。

返答は相手が受け取った申告と陸路書状のスナップショット。未来の真値や隠れた封鎖を読まない。払えるかどうかでUIを先回りして変えず、支払の実操作で残金を再確認する。未払い・未受領は保存される。返答の不達は、依頼主が不達を知り、本人が元の面会場所に戻った時だけ同じ書状を最大3便の共通規則で再送する。受渡しの場所は確定順より後の同秒出陣で書き換えない。タイマーだけによる原本の遅着は既存の物理回収規則に反するため拒否し、再送は新しい実物の便と同じ原本IDを使う。

## 検証と限界
verify_work_cycle.py → 実画像/動画確認 → --finalize → check_work_cycle_binding.py。最終件数はverification.json。世界と3D描画領域/情報欄の画像、および会話・顔の骨格・私財・仕事状態の数値を復旧比較する。画面全体の一時的な行先ドロップダウンは保存対象ではない。動画はGodot固定30fpsの実操作記録で、実時間性能の測定ではない。

金銭はこの任意点検の契約に限定する。一般市場、買物、俸禄の定期支給、政治的な功績評価・昇進、全国の依頼生成は未実装。自主点検で知る内容は既存の地元陸路で、未観測の城内や物資を捏造しない。失敗原本のタイマー回収を追加していない。陸路が未設定の島の拠点では、有償点検を約束しない入口ガードを設け、未設定である旨を表示する。

## 次の5作業
1. 新しく一巡できる仕事の会話量・読み進め方を、実画面の手触りとして確認する。
2. その結果に沿って台詞・操作回数・所要時間の試作値を調整する。
3. 既存軍務の選び方を同じ仕事導線へ整理する。
4. 拠点の実際の需要から仕事が出る仕組みを、認識制約付きで検討・実装する。
5. 私財の使途と長めの旅を含む遊びへ拡張し、各段階で保存復旧と所有の分離を確認する。
