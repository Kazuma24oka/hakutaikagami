# 仕事の相談・引受・点検・返報 V1

ユーザー承認：ログを主画面に大きく出さず、既存の仕事を一つ使い、武将との会話から実行・報告まで見せる。同じprototype/godot-foundationへcommit/push。マウス操作は使わない。

完成条件5件：
1. 既存LocalWorkの相手・場所・主従区分を相談前に確認。会話を閉じても命令/時間/保存を変更しない。確定時に現在の相手/場所/区分を再確認し、既存Submitだけを実行。
2. 実際に届いた封書を開くまで内容を表示しない。本人認識済みの仕事だけ表示。任意依頼の引受/辞退と主従に基づく命令を区別し、既存Assent/時計/点検/返報を使う。
3. 左手前の本人・右奥の現地相手を既存3D外見で表示。対面していない相手を在席させない。地図脇に仕事の案内を小さく表示し、操作ログはスクロール可能な履歴へ。人物外見・背景は既存試作。
4. 任意/主従の2ケースで相談取消・開封・引受/辞退・点検・実返報、2地点ずつの別プロセス保存復旧と続行を全世界/3D実画像/数値で照合。Core317入力/TRX/DLL一致時だけ2122件を再利用。実画像と実操作録画を直接確認。
5. 完成した実装・証跡と同じバイトをcommit/push。main/designは維持、既存素材/保存を削除しない。過去工程のGPU成功を今回の再実行に読み替えない。

## 範囲
既存の現地の点検を一つの用件として扱う。新しい報酬、能力成長、相手の評価、会話分岐、点検対象の詳細情報は作っていない。完了画面は「本人の点検と返報の発送」を示し、相手の受領/開封を断定しない。作業は既存のその場の点検で、巡回経路や専用モーションは未実装。対面の台詞は状況説明用の創作で史料引用ではない。
履歴は保存に残る本人認識済み用件/書状から再構成し、この画面の操作通知だけ最大200件をメモリ保持。隠れたChronicle全量は出さない。会話ウィンドウの開閉は一時的な表示で、保存復旧時は内容ボタンで同じ認識内容を再構成する。
録画専用コピーはコード/シーン/データ/Game+Core DLL一致、viewport2値だけ変更。固定30fpsは実時間性能の証拠ではない。原本プロジェクト設定は変えない。

次の五件：本工程の動作確認/push、ユーザーによる見え方確認、点検で得る情報の具体化、報酬/評価と依頼の選択、他の仕事への再利用。後続を今回の完成と主張しない。

会話ごとのモデル再生成時に微小なラスタ差を確認。会話モデルを人物IDで保持・再利用する構成に改修し、保存復旧は通常起動同士10プロセスで厳密画像比較し、録画は別の11番目のプロセスで実施。画像許容差は設けない。会話人物の骨格/外見/カメラ/台詞も数値一致を確認する。

通常ログは履歴へ。失敗時の短い操作案内は見失わないよう主画面にも表示する。録画は通常の相談→引受→実行→報告の順で、検証用の辞退/途中復旧の枝は含めない。これらの検査は通常起動のQAで別に実施する。
