# 地域NPCの仕事 / 従来の検証を選ぶ入口候補

独立入口Game/Scenes/WorkHubTrial.tscn。通常起動のGame/project.godotと従来Mainは変更していない。新しい最初の画面を具体的に動かして確かめるための候補。

最初に「地域NPCの仕事」を開き、従来Mainは「従来の検証」の実タブを選ぶまで読込まない。旧Main内の既存タブ・初期画面・旧保存先はそのまま。タブを往復しても同じセッションを保持する。表示していない試作はGodotのProcessModeをDisabledにして自動進行を止め、戻すと再開する。Coreの時計やゲーム判定を別実装にせず、セッションの状態を書き換えて初期化しない。

両者は試作の異なる規則/世界であるため、共通世界の二つの表示と偽って同期しない。上部に別セッション/保存先と明示し、旧セーブは旧画面から開く。通常入口の選択を変えても旧セーブの移行や削除はしない。

新平時画面の操作案内を地域移動と時間進行へ合わせ、未実装の軍事操作を案内しない。平時の内部に試作戦力値を混ぜず、軍議/戦闘は従来の検証に残っていると案内する。

## 検証

verify_work_hub.py→実画像点検→check_work_hub_binding.py。新入口で5保存点の復旧/続行10比較、NPC独立入口10比較、旧通常Mainの訂正通知8比較、旧基盤/徴税/共通入口を実GPUで検査。候補入口に旧検証の起動指定が来た場合はSceneTreeで従来Mainそのものへ遷移し、旧Mainが実ルートとなる互換経路を追加。こちらも通知8比較と旧3入口を実GPUで確認する。タブ切替で同一セッション/旧基盤の状態を保持し、旧Main遅延読込と非表示時停止も確認する。

この段階ではCoreとTestsのソース集合/ハッシュは前段階a3fc3f1の933テスト合格版と同一。ただし再ビルドでコミット識別の付加情報が更新され、Core DLLハッシュが変わったため旧バイナリの結果は継承せず、今回のバイナリで933テストを再実行する。Gameも新しくビルドし、実GPUで検証する。後続の入口だけの修正では、同一Core/Tests集合・Core DLL・今回TRXが一致するときだけ933件の結果を再利用する。旧検証記録は履歴として保持。

Docs/Proposals/WorkHubEntry.patchはrun/main_sceneの1行だけをこの選択入口へ替える候補。独立候補の完成/検証とcommit/pushは行うが、切替はユーザー確認後に行う。

根拠：AGENTS.mdの「通常Main保持の例外はこの追加と必要な検証/修正に限る」は、既存の末尾任務タブ追加に対する限定承認。初期入口の切替を同じ例外と見なさない。切替の承認があれば例外を運用文書へ追記し、通常起動で再検査する。mainブランチへのマージは含まない。
