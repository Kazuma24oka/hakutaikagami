# 反復演習と生涯損耗 V1

[実装前計画](PLAN.md)の5条件を実装・検査する。旧一回分の解釈を保ちながら、版を宣言した反復許可と交戦入力で二回目へ進める。

## 完成条件（5件）
1. ExercisePolicyを明示した申出を物理受領した主君が、期限付き反復許可を与える。原通知またはその照会引用を開くまで開始できず、旧一回分の許可を反復へ拡張しない。
2. 実在する自隊のID・残兵・士気・兵糧消費を継続し、開始し直しても回復しない。士気50は既存の実到達・60秒・交戦終了を満たす再集結だけで適用する。
3. 交戦ごとの別IDで損害・敗走・到達・再集結を区別し、過去を残す。同秒の終了と開始で損害や消費を重ねず、前案件の許可で新案件を動かさない。
4. 通常画面で短い二回交戦と、再任後の二回目の野外敗走・再集結を動かす。二場面の計50保存点を別プロセスで復旧し、全世界・人物/部隊/演習相手/伝令・3D実画像と同じ未来を照合する。
5. 全Coreテスト・必要な実GPU回帰・実画像/動画・資源解放・現行ソース照合後、同ブランチcommit/pushを行う。未再実行ケースを現行成功数へ混ぜない。

## 版と境界
- NewMilitaryInput.ExercisePolicyは許可申出/開始にだけ指定できる。旧未指定入力・保存の一回分の結果、敵ID、JSON省略形を保つ。新しい開始入力は既存のRoutContractも明示する。
- 反復できるかは実際の許可本文の契約で判断する。本人の入力だけで旧許可をアップグレードしない。引用にも元許可の版を保ち、原通知の開封や認識を捏造しない。
- 自隊の兵と損耗は生涯集計。相手は各交戦の新たな架空演習対象で、その回の開始時の自隊残兵数に合わせる。相手のIDは開始判断IDで修飾し、描画用の三枠の再利用と論理IDの継続を混同しない。実在敵軍の復活や補充ではない。
- 敵の新規人数調整、30秒の演習上限、許可120秒、再集結60秒/士気50は技術試作条件で、製品バランスや史実人数を確定するものではない。
- 前の軍務の許可を新軍務へ流用しない。新しい軍務では新しい交戦許可が必要で、期限の自動延長はしない。旧版で士気が低下した保存にも、新しい入力なしの回復は追加しない。
- 全景表示と重なるラベルは技術用。認識に依存する可視範囲/HUD品質、実在勢力間の開戦、敵軍AI、傷病・捕縛・死亡は本工程の完成に含めない。
- 26秒・固定60fps動画は二回の実移動を含む動作確認で、実時間性能測定ではない。

検証：verify_repeated_exercise.py → 実画像/復号動画の目視 → --finalize → check_repeated_exercise_binding.py。旧結果は当時のソースの実績として保持する。

次の5件：1.本工程の検証/push、2.認識に応じた自隊/伝令/報告位置の表示、3.認識に基づく対象選択、4.実在勢力の敵対/許可への接続、5.全国規模の負荷。創作上の重要な新判断以外は既存承認範囲で継続する。
