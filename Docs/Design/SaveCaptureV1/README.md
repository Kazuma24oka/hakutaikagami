# 保存開始の画面応答 V1

前工程ResponsiveClockV1はcf43a45で5/5。本工程は手動保存の開始直後に残る画面側の世界コピーを別作業へ移す。Core・保存形式・保存の公開規則は変更しない。

## 完成条件5件
1. 実保存ボタンでは実際の私有世代の捕捉と表示のスカラー値だけを取る。取消した先行計算の終了を待ち、既存の不透明な停止準備と同一世代への一回確定を用いる。確定していない未来を保存の書込みへ渡さない。
2. 確定した停止世界を既存GenerationSaveStoreへ渡して検証・書込み・世代公開を行う。保存中は時刻・命令・ロード・メニュー等を拒否し、正常/保護による非上書き/失敗を区別する。従来の原子的保存規則を省略しない。
3. 1000人データの実自動進行中の保存、私有準備中の故障、ペイロード書込後の故障、旧公開世代の保持、再試行とロードを実画面で確認する。7追加保存地点と従来32保存地点を別プロセスで復旧し、同じ世界・本人・保存対象の表示・3Dと同じ未来を照合する。故障確認の保持ゲートを通常処理の描画性能の根拠にしない。
4. 304のCore/試験/データ入力、Core DLLと全2055試験TRXの完全一致時だけ直前の全体試験を再利用する。50回の現行実GPU起動・278世界画像/数値比較を確認する。9つの旧入口/材質/煙試験は今回再実行せず、共有描画/旧入口の入力が変われば限定再利用を拒否する。
5. 実画像を直接点検し、現行ソース・実行物・試験・証拠と実際のコミット内容を照合して同じブランチへcommit/pushする。

## 境界
新しい世界や別の時計を作らない。準備失敗なら元の世界と旧保存を保ち、停止確定後の書込み失敗ならその停止世界と旧公開保存を保つ。保存先の公開が保護された過去分岐は、現在の進行を将来の保存へ勝手に戻さない。終了時の私有準備取消と、確定済み世界のファイル書込みを分ける。

初回開始/ロード/QAチェックポイントの同期処理、通常判断、高速進行は別工程。1000人は静止した架空登録人物と選択本人の移動であり、全国自律NPCや多数同時合戦の性能保証ではない。クリック捕捉時間と完了時間、計測/PNG出力の負荷を区別する。

次の五件：本工程の検証/push、通常判断/高速進行の待ち時間、全国人物/役職、同時処理負荷、実プレイ体験確認。判断不要なら継続する。
