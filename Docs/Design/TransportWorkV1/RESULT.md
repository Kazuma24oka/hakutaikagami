# 運搬接続の実測結果

小口送金100文の相談→受諾→現地引受→経路移動→指定相手への受渡し→荷主への報告→運賃20文の受領を、通常の下部会話から接続した。額は試作値。所有は荷主、預り中の保管は本人、受渡し後の保管は受取人。本人の財布や主家の兵糧と混ぜない。

同じ受渡しの再送は一度だけ。取消後は実返却まで現物を保持する。通行止めによる現地停止を運搬導入した新入口へ接続し、本人の観測を存在しない旧試作用人物へ自動送信しない。予定到着時刻を経過しても実際に着いていない場所では渡せない。

全2273件は位置判定補強前の入力とDLLを保存して実行し成功。その後の差分を運搬の位置復元・導入時の既存停止接続・旧試作宛先の除外・専用3テストに限定し、実ゲームと同じ最終Coreで重点358件が成功。現在のケース総数は2276だが、最終バイナリで全2276件を再実行したという報告ではない。件数は合算しない。

実GPUは12プロセス。通常/小画面/軍務同居/取消返却で各7保存点、既存兵糧で6点、既存軍務で17点を別プロセス復旧。合計102組について世界状態・3D/情報欄の画素・全姿勢/表示数値が一致した。新しい荷袋メッシュは作っていない。

受取人は同じ勢力の開始時指定先。現在地へ自動追尾しない。該当する依頼主と別拠点の受取人が配置されている場合だけ相談でき、各依頼主の依頼は一度。実画面検証には通常の武将グループ登録から架空の受取人を明示投入した。史実の武将配置・需要の追加採録を完了した意味ではない。

旧保存の省略形を検査。運搬を始めた世界にのみ追加台帳と既存の交通制御を設ける。main/design/foundation・既存素材・ユーザー保存は保持する。次の旅費方針「金欠でも徒歩移動できる」は承認済みで、TravelExpenseV1の完成条件へ続く。
