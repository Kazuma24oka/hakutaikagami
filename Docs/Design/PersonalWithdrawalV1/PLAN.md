# 次工程：本人退避と部隊撤退の分離（未実装）

BD-02/23/26/32/37/39/40と新入口の貸与/運搬/返報契約を維持する。人物の描画位置だけを分離する実装は禁止する。

## 推奨する実装順
1. 個人の移動、部隊の移動、物資を運ぶ実体、指揮の担当、最後に認識した状態を別々に保存する。既存の人物随伴兵糧は無断に部隊追随へ変更せず、明示的な現地受渡しで分離する。
2. 本人だけの退避と部隊への撤退指示を別の入力にする。退避は歩ける地形の経路を通り、部隊の位置・既存任務・資源を瞬間移転させない。
3. 本人不在時の隊は受領済みの任務を継続する。新たな命令は相手・既知宛先・配送・効力・認識・実行を区別する。画面外の真の部隊位置から宛先や判断理由を作らない。
4. 本人の帰還、部隊の帰還、物資の返納、残兵の返報を個別に満たす。本人が拠点に着いたことだけで指揮や兵糧を返還しない。再合流も現地で確認する。
5. 個人移動中・命令配送中・部隊撤退中・合流待ちの各点を別プロセス復旧し、続行後の全世界・物資・伝令経路・3D表示を照合する。

## 現状の制約と対処
- `ResourceLot.MobileHolder`は現行では人物IDで、`FieldSupply.Location`も人物のLocationを引く。部隊に残す物資は、部隊/荷駄等の運搬実体を明示する拡張と検査が先に必要。所有者や処分権は別に維持する。
- 新入口の本人は現状本隊位置を参照している。`NewGameMilitary.BranchView/Sync`、`RegionalCampaign.ActorPointAt`、伝令の発送位置、保存時点の過去再構成、表示補間を同じ正本へ接続する。
- 新しい配下人物を根拠なく生成したり、同じ人物を遠隔部隊の受取人として二重配置しない。現地指揮の受任者と受信地点を明示する。
- 個人退避で所属・主従・債務・主家所有・兵の損害を消さない。敗走と負傷/捕縛/死亡は別。健康/捕縛が未実装である間、退避成功をそれら全制度の実装済みとは扱わない。
