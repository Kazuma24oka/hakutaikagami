# 軍務の兵糧準備を仕事欄へ接続

前工程の「必要な時だけ点検を依頼し、完了後は消える」流れはユーザーが2026-10-25に承認した。次の対象は既存の軍務の兵糧引受とする。

## 完成条件
1. 実引受済みで現地Loadが可能、携行兵糧が100人換算1日分未満のときだけ仕事欄へ準備を表示する。未開封許可・指揮未引受・出陣中・返還中・終了後に案内しない。
2. 既存Loadと同じ量・所有・権限判定を使う。新しい有償依頼を作らず、主家兵糧の携行と私財/点検報酬を分離する。
3. 本人の返答は続けるまで未確定。取消/ロードで在庫を動かさず、実引受後だけ完了を表示。未確定中の世代変更を拒否する。
4. 家臣/当主/小画面、引受前後/返納/返還/移動の保存復旧を実Godotで比較し、在庫と私財の保存を検査する。既存の点検・需要・野外軍務も回帰確認する。
5. Coreの2208件は完全一致する入力/実行ファイル/TRXの前結果だけ再利用。実画像と短い動画を確認して同じ作業ブランチへcommit/pushする。

## 範囲と次の5作業
兵糧の現地引受を仕事として案内する画面接続であり、新たな徴発・購入・有償運送契約は追加しない。100人1日分は既存Loadの引受量で、必要兵力の自動積算ではない。補充後の配置や出陣は既存軍務地図で行う。

1. この準備導線の検証と反映。
2. 必要な軍務準備と通常依頼の見分けやすさを確認。
3. 書状・物資を運ぶ仕事の受渡し条件を既存保持原本/所有ルールで設計。
4. 正当な依頼と引当のある運搬へ段階的に接続。
5. 私財の使途と旅費へ展開。
