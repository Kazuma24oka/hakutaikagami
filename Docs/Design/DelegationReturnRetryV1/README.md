# 既知不達後の原返報再送

通常の照会は原本を再送しない。本人が別操作「原返報の再送も依頼」で物理照会を送った場合だけ、相手が自分宛の不達報告を受領済みの受令返書/到達報告を共通MessageFlow.Retryで再送する。自律的な全書状の常時再送ではなく、受領した依頼ごとの限定処理。失敗報告自体が不達なら再送不可。最大3便で、同じ照会の二重操作は新たな便を作らない。

元の論理ID/本文/報告時刻を変えず、各便に実際の発送元・既知返書先・地形経路を保存。返書先は相手が実受領した本人の命令/照会のうち発送時刻が最新のもの。同時刻なら保存済み発送台帳の順。遅く届いた古い便で新しい宛先を戻さない。相手が移動済みなら、届かないこともある。真の現在地では追尾しない。

照会返答の再送受付数は発送時の採用件数。返答到達前は表示しない。引用で到達を知ることと、原本の再送便が到達して正式受領されることを別に検査。兵や行動の再実行は起こさない。受令許可の期限が過ぎても既存返報の返送は別に扱う。

旧照会のResendなしはfalse、旧返答のRetriedなしはnullとして読み、書き戻しも同一形。旧開始・旧保存・通常照会の動作は保持。既知の拒否/権限拒否/未認識または照会不達の受領後は、UIの照会先を通知済み営地に切り替え、ラベルへ明示する。

返答そのもの/失敗報告の再送や一般の代理開封・転送の完全統合は未実装。未認識の遠方状態を理由へ混ぜず、責任・処罰は未審査。
