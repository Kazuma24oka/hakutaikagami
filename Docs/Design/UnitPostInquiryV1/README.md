# 部隊受信役への物理照会

UnitPostRecoveryV1は6e02405でpush済み。本工程はその同じ原本/追加便/役割受信/物理経路を使い、照会を別の原本として追加する。現在の完成条件と検証対象を以下に固定する。

完成条件は5つ。
1. 明示した既知所在地/帰還拠点へ新しい照会原本を運び、実受領後だけ受信役が自分の記録を返書へ固定する。架空武将や別の配送時計を作らない。
2. 元命令の受領/未受領/適用を引用できるが、引用だけで元原本の正式受領や失敗報告の認識を追加しない。照会は兵の命令を実行しない。
3. 返書は受信役自身の兵数/位置/移動/帰還/敗走段階を記した過去時点の報告であり、現在地追跡ではない。ほかの部隊や敵や未確認の封鎖を混ぜない。宛先選択は本人が既に持つ根拠だけを使う。
4. 返書も固定宛先への物理復路を持ち、不在なら届かない。原本再送のFailureKnownは実際の不達報告の受領だけから判定する。
5. 省略可能なUnitInquiry台帳、旧保存/初回不達/再送の維持、原判断からの再計算、改ざん拒否、同じ未来と実3D画像を検査して同ブランチへpushする。

実装の注意：UnitDispatches/Receipts/Repliesに新台帳を合流。MessageParticipantsは初回撤退命令が0通でも照会便が存在すれば匿名受信役/伝令を登録。Receipt/Reply記録の行き先を台帳別にする。UpdateWithdrawalは照会ではOrderを作らず、別型の固定返書を作る。BeforeState/ValidateWithdrawalの全再現比較へUnitInquiryを加える。照会原本自体の本文も入力再生から比較する。PersonalStatusは撤退命令だけを選び、照会に旧命令不適用という文言を出さない。表示は実際に届いた返書だけを読む。引用でSightings（本人の目撃）を捏造しない。

試験重点：命令が0通の照会、失敗返書より先に届く未受領の回答、引用してもRetry不可、元原本の受領と引用の分離、作成後に本隊が移動しても返書本文固定、本人不在の返書不達、自部隊0の兵数だけの報告、復旧の同じ未来、原文/返書/時点/位置の改ざん拒否。
