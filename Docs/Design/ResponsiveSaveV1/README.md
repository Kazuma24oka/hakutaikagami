# 保存中の画面応答 V1

前工程KnownMilitaryTargetV1はc9371537f41358734d2a0961054ded9a5063ef0aで5/5、1775件/29GPU/378世界画像比較の当時実績。分隊別命令の調査中、長い履歴の同期保存が描画を止めるため、追加の軍務操作を広げる前に手動保存の画面応答を小工程で改善する。

## 完成条件5件
1. 実保存ボタンで世界を停止し、その時点の独立スナップショットと表示設定を一緒に確定する。検証・書き込み・世代公開には既存WorldSession/GenerationSaveStoreを使い、検証の省略や未完了の成功表示をしない。Core/旧保存形式は変更しない。
2. 保存中も実Godot描画が3フレーム以上進むことを、実処理・遅延注入なしで確認する。保存中表示を更新し、世界の時刻/版・兵・認識・経路を変えない。キャプチャ時間/フレーム数を計測するが、計測とPNG出力による負荷があるため性能ベンチマークとは扱わない。
3. 二重保存・ロード・メニュー・時刻進行を含む競合操作を拒否し、完了/失敗後に元の操作可否を戻す。UIのボタンと配置線入力を同じ待機判定で守る。過去点からの保存が新しい公開版を上書きしなかった場合は、失敗や保存成功と混同せず、保護により上書きしなかったことを明示する。
4. ペイロード書込後の意図的なIOExceptionでも旧公開世代を保持し、実ボタンで再試行とロードを成功させる。正常/失敗二場面32保存点を別プロセスで復旧し、全世界・固定行先・選択/表示・3D画像と同じ未来を確認する。
5. Coreテストは入力/DLL/TRXの完全一致を確認した場合だけ前工程1775件を再利用し、再実行した画面ケースを明記する。現行ソース/バイナリ/実画像/資源解放を照合して同ブランチcommit/pushする。判定はverification.jsonで行う。

## 境界と未実施
- 改善対象は通常ゲーム画面の手動保存。初回開始/ロード/QA用チェックポイントの同期処理は別工程。読み込み全体や全国性能、最終UI品質の完成とはしない。
- 失敗ケースの障害注入はQAの内部コールバックだけ。人工的な処理待ちを入れて描画継続の成功を作らない。未公開世代は既存方針どおり保持し、自動削除しない。
- 保存中の入力制限はゲーム内部のみ。OSのマウス権限・ポインター・ネイティブ操作ツールには触れない。
- 既存の画面テストも実UI保存の完了を待つ。同期の別経路に差し替えて成功扱いにしない。
- 復旧検証の過去分岐では、新しいmanual公開版を巻き戻さない。保存処理そのものは実ボタンで待ち、対象が古ければ保護表示を確認する。正常/失敗の実UI保存・再試行・ロードは最初の途中場面と、別プロセスで同じ未来へ到達した後の現行版でそれぞれ確認する。
- ソースが変われば前工程の現行一致保証は履歴になる。Coreの実コミット後再ビルド一致は前工程runtime-local/postcommit-core-reproduction.jsonに実測がある。

次の5件：本工程の実画面/復旧とpush、分隊宛の物理命令、分隊別期限/取消/再送、実在敵対/許可、全国負荷。重要な創作判断が必要になるまでは継続する。
