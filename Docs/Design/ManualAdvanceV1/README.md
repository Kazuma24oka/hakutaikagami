# 手動時間操作の画面応答 V1

地形改善は9edc312で5/5。別環境で10秒/次拠点の同期操作は約1.1秒UIを占有した。既存の不透明な停止準備→時間進行→停止準備と同一世代の一回確定を利用し、計算中も画面を描画する。計算そのものの短縮や一定fpsは主張しない。

完成条件5件：
1. 可視10秒/次拠点ボタンを非同期受付にし、既存Coreの同じ入力結果を使う。私有未来を表示せず、同一世代だけ一回確定。重要通知では指定時刻より前でも止まり、開封は別操作。
2. 一runtimeに私有workerは一つ。取消済みworkerを回収するまで次の停止/進行/保存workerを開始しない。待ち中は通常操作/重複要求/保存を無効化し、停止・メニュー・視点・手引きは利用可能。保存は停止後に行う。
3. 1000静止人物+本人移動で10秒/次拠点、重要通知、保持中の停止/メニュー離脱、故障/再試行と自動からの切替の7ケース14地点を別プロセスで復旧し、28組の世界・画像・3Dが同じ未来へ戻る。既存到着試験も実完了を待って判定する。
4. 40現行GPU起動で116組の世界画像/数値を照合。変更した入口/到着、既存の開始停止・保存・先行進行・高速との競合を選んで再実行。Core2055試験は304入力/TRX/DLL完全一致時だけ再利用。過去62/24回を今回再実行したと数えず、共有renderer/旧入口の9試験は入力不変のため今回対象外。
5. 実画像を直接点検し、現行ソース/実行物/証拠/コミット実体を照合して同枝commit/push。主枝/設計枝と無関係な素材を維持する。

完了時間とクリック受付時間を分ける。準備用のコピー/検査で同期操作より確定が遅い場合もあり、待ち中の画面応答が目的。手動指定は選択倍率と独立の明示要求で、未確定の整数境界を補間しない。予算で途中確定した場合のみ残りを進め、重要出来事を越えて再開しない。内部QA用の同期Advance helperは別に保持する。
