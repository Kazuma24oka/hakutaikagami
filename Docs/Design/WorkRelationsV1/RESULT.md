# 仕事で生まれた縁から仕官・役目・軍務へ

4条件達成。V3開始で、点検の履行を認めた相手→本人と、約束の報酬を実受領した本人→相手の仕事上の信頼の根拠を分けた。運搬も荷主による現地報告の確認と、本人による運賃受領を別の根拠にする。第三者や主家全員への一律更新、再開封による重複、取消/返却からの自動的な好悪/敵意を作らない。

画面には本人が開封した返答や参加した現地受渡しと、出来事/確認の時刻だけを表示する。NPC側の判断材料をそのまま公開しない。現地で縁のある相手と相談し、浪人は仕官の申出と返書条件への回答、家臣は担当や軍務の相談へ進める。仕官の物理的成立・通知開封や軍務の許可/兵の引受は従来どおり別の手続きを経る。一般の仕官入口は保持した。

関連47件成功（新規14、失敗・スキップ0）。通常の武将作成/新規開始から、同じ浪人の点検→未開封の評価→開封→相手との相談→仕官申出→条件書開封→本人の回答→実成立→通知開封→点検担当の引受→軍務の条件を相談するところまで実行。軍務条件の提示を見ただけで兵を引き受けられないことも確認。

実Godot2プロセス、5保存地点の復旧と続行後10組で、世界状態・3D/情報画像・全表示姿勢が一致。仕事の縁の会話と軍務条件の画面を実画像で確認。原本と実受渡しから再構成するため、独立した関係点の保存を重複させていない。全件テストは今回は未実行。

これは仕事を通じた関係の一部接続。好意/敬意/恐れ/敵意、派閥参加/脱退、訂正報が関係へ及ぼす影響の全実装ではない。現地では既知の主君を優先し、なければ直近の相手を案内する限定入口。全人物の関係一覧・相手選択は後続の画面整理で扱う。

再実行は通常Godot入口へ --new-game-case=relations-normal と新しい --new-game-test-key を指定し、同じキーに --new-game-restore を付けた別プロセスで復旧する。
