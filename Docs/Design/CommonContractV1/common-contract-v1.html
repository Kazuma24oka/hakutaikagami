既存を活かして、共通の約束へ揃える

独立C#、明示的な権限、命令の一意性、配送と本人認識の分離、変更後の整合検査は継続します。徴税中心の試作状態を、人物・任務・軍事・経済が共有できるWorldSessionへ段階的に拡張します。

今回固定する重要な境界
受付は成功、でも命令はまだ届いていない。任務は完了、でも主君はまだ知らない。取消は届いた、でも過去の徴収は消えない。このような状態を矛盾なく保存できる構造にします。

詳細設計DD-01の共通部分と、時間・保存・検証との接続が対象です。制度ごとの係数、史料・全国地形、個別コマンドの全業務遷移、実行性能は後続です。

構造を説明する図です。新WorldSession等の実装画面ではありません。

「命令の状態」は一列にしない

運送・正式受領・開封・成立・実行・報告・評価を分けます。これにより、遅着や再送があっても実行をやり直さず、本人だけが古い情報を持つ状況を表せます。

状態の軸遷移成立条件・禁止終端と履歴
配送試行InTransit → Delivered / Lost / Rejected。Lost → Deliveredは遅着の到達証拠付きだけ。再送は新Attempt、同じ本文。Lostの過去観測は別履歴に残す。試行の終わりは案件・命令の終わりではない。
正式受領と開封ReceiptAbsent → FormallyReceived。Sealed → Openedは受領後の独立操作。重要書状は手元到達で自動開封しない。ReceiveとOpenの代理権を別検査。受領は一度、開封・本人認識は人物ごとに記録。
命令履行の成立BindingOrder: Issued → AwaitingReceipt → AwaitingRecognition → ReadyForDecision → Authorized / Refused / Expired。Authorizedは履行判断を許す状態で、本人の服従や実行完了とは別。違法行為の試行は別の実行意図と責任記録。不受領・期限失効・拒否で運送履歴を消さない。
任意依頼の成立VoluntaryRequest: Offered → AwaitingAssent → AgreementActive / Declined / Expired。権限ある当事者の同一版の合意と、制度で定めた同意到達が必要。外交条約は双方への適法到達で成立。受領や発送だけで契約成立としない。
実行NotStarted → Waiting → Running → Suspended / PartiallyCompleted / Completed / Stopped / Failed。Suspended・PartiallyCompleted → Runningは再開条件付き。Waitingからの未着手取消はStopped。Runningからの中断は安全停止点へ。Completed/Stopped/Failedから旧IDで再実行しない。進捗・消費・部分成果を保持。再依頼は別ID。
報告と評価Report: NotRequired / NotCreated → Queued → InTransit → KnownByRecipient。Assessment: Pending → Provisional / Confirmed / Disputed。配送失敗・再送は別Attempt。評価は評価者の証拠受領後。訂正は新EvidenceとAssessmentRevision。実行完了でも報告・評価は未完了になり得る。
引当・補償Reservation: Active → PartiallyConsumed / Consumed / Released。Compensation: Pending → PartlySettled / Settled / Disputed。消費済みの引当を解放しない。補償は元効果と一意キーで結ぶ。部分返還後の再送で同じ部分を二度返さない。
取消・差替えCreated → InTransit → Received → AwaitingRecognitionOrEffect → Applied / AlreadyStopped / TooLate / Unauthorized / Expired。再送可能な運送失敗は取消の業務終端と分ける。明示したTargetIdと未確定効果だけに作用。返報は取消結果と別配送。取消が成功した真実を発送者へ即時公開しない。
例：実行＝完了、返報＝紛失、主君の認識＝履行中のまま。この三つは矛盾せず同時に成立します。

同じ時刻に起きても、登録順で決めない

時刻Tの状態と因果依存を揃え、対象を明示した取消・差替え、制度ごとの競合規則で裁定します。期限のTは有効、権限の終了Tは無効です。

保存は「正常な一世代」を公開する

01 / 取得確定状態を切り出す

同じRevisionの世界・イベント・効果・乱数・知識を、不変スナップショットにする。

02 / 検証新しい世代へ書く

一時書込、flush要求、再読込、長さとSHA検査。現在の正常保存には触れない。

03 / 公開最後に参照を切り替える

検査済み世代へcurrentを切り替える。過去3正常世代も保持。失敗は明示する。

読込は 隔離検証 → 依存・不変条件検査 → 一度だけ置換 → 全体停止で再開

破損時は正常な過去世代と復旧時刻を提示し、勝手に巻き戻しません。実際の電源断・異常終了耐性は、新実装と実機障害試験の後に確認します。

旧セーブはどうする？
試作Version1〜5は旧入口で保持します。製品の秒基準世界への自動移行は現段階では非対応です。旧1刻の正当な換算や架空地図の地理対応がないため、数値をそのままコピーして移行済みにはしません。

安全なスロットIDと現在世界ID。任意絶対パスを通常UIから渡さない。
出力
SaveJobId、CapturedRevision、完了後GenerationIdまたはIO_FAILURE。
更新境界
正本の確定Revisionを取得。背景ファイル保存は進行中の世界を変更しない。

PrepareLoad(SlotId, GenerationId)

入力
指定世代、許可保存ルート。原本を読み取り専用で扱う。
出力
隔離LoadCandidateまたは公開可能な理由付き失敗。復旧候補と時刻を提示可。
更新境界
現在の世界を変更しない。旧系ならMIGRATION_REQUIREDと旧入口案内。

CommitLoad(CandidateId, ExpectedCurrentWorldRevision)

入力
PrepareLoad済みの候補と現在セッションの版。
出力
新しい停止中セッションの識別子・Revision、またはSTATE_CHANGED。
更新境界
実行直前に候補の依存SHAと期限・対象版を再照合し、一度だけ置換。古い候補をロード中の進行へ黙って適用しない。

製品の保存は独立した形式へ

符号化
UTF-8 without BOM; LF; strict JSON, duplicate properties rejected
ハッシュと数値
PayloadHashはファイルpayload.jsonの生UTF-8 bytesのSHA-256（小文字64桁）。業務本文のCanonicalPayloadは契約版付きJSON：オブジェクトkeyはOrdinal順、順序あり配列は保存順、集合は契約で定めたID順、文字列は値を正規化せず標準JSONエスケープ。整数は符号・桁を正規化、浮動小数はCore業務本文に禁止。Amount・時刻・uint64はwire上10進文字列に統一し先頭ゼロを許さない（0のみ例外）。bool/nullはJSONの型。ローカル表示の小数位相は有限doubleかつ0以上1未満で別Presentationへ。
版と必須検査
EnvelopeVersion・各SchemaVersion・RulesetId/Versionを別照合。読める版は明示登録した組だけ。未知フィールド、重複key、型違い、未知enum、未登録版は拒否。任意拡張を暗黙に読み飛ばさない。
欠損と空欄
空配列・空オブジェクトを明記し省略しない。各SchemaVersionが各項目の必須・nullableを定義。未実装制度を既定値の補完で実装済みに見せない。
履歴の保持
正当な履歴はゲーム内に保持。UI向けの要約・索引は再構築可だが、未処理参照、同一性墓石、効果一意キー、抽選根拠、移行情報、知識出典は落とさない。物理圧縮や分割は後続の版変更と負荷検証後。

  1. 型・定義・不変条件：ID・関係・全体状態と検証器を追加。既存DTOとの対応を確認。
