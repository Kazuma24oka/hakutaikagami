# 同じ主君・同じ守備隊への軍務再任（実装前計画）

## 目的と範囲

一回分の軍務で終わる現在の制約を外し、同じ武将が実際に指揮を返還した後、同じ主君のゲーム内に既に存在する同じ守備隊について新たな軍務を申し出る。最初の履歴を消して初期状態から作り直す方式は使わない。複数主君からの同時貸与や、他勢力の兵・在庫の交換は別工程とする。

## 完成条件（5件）

1. 本人が前案件の終了を返書で確認し、実際の指揮・兵糧返納が終わった時だけ、新案件を申し出られる。新しい承諾・許可・現地引受が必要で、古い通知の開封を新案件へ流用しない。
2. 兵・兵糧の生涯履歴を保ち、二回目に兵数・損耗・消費を初期化しない。守備隊・貸与元・所有者のIDを維持し、案件IDだけを区別する。
3. 前案件の原本・取消・返書・保持者の実在を維持する。古い命令が遅れて正式受領されても、新しい軍務を動かさない。前案件の未来取消で新しい指揮権を止めない。
4. 新旧案件をまたぐ保存復旧、同じ未来、通常画面の選択肢と3D表示を実際に検査する。旧一案件保存に新しい状態を遡及追加せず、改ざん・重複効果を拒否する。
5. 全テストと必要な実GPU回帰・実画像・資源解放・現行ソース照合を終えて、同ブランチへcommit/pushする。未完成の機能を成功扱いしない。

## 実装方針

NewMilitaryの入力・効果・移動・出陣・受渡し・消費・書状を一つの生涯台帳に保つ。新しいRequestのIDを案件の起点とし、許可・承諾・返還・返報の参照は起点と時刻・更新順序で区切る。兵糧の計算や損耗の計算は過去分を含めて継続する。

追加する再任入力は任意の版付きCycleContractを明示する。初回・旧保存の未指定形は保つ。既知の終了通知と、実際の権限終了・携行ゼロ・出陣終了を別に検査する。新しい軍務の返還条件を、前案件の返報で満たした扱いにしない。

過去の伝令は実経路の更新を継続し、書状や保持者を廃棄しない。受領できる物理条件と、その原本が現案件を動かす権限を分ける。前案件の取消は、現時点で別案件の指揮権を持っていても権限終了として扱う。

演習は現在の一人生一交戦の制約を残し、反復交戦の完成とは扱わない。前の演習で失った兵は再任時にも減ったままにする。補充・治療・士気回復の新規制度を、この実装の都合で暗黙に追加しない。

## 受入予定

二回の平時軍務、演習損耗後の再引受、未開封の終了通知、古い保持原本の遅着、古い未来取消、新旧許可通知の開封、旧返報の流用拒否、終了前後から二回目の引受・出陣までの保存復旧を検査する。本計画の記載時点では未実装・未実施。

守備隊100人などの初期人数・在庫は既存の技術試作条件であり、史料で確定した史実人数として扱わない。
