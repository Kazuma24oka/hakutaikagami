# 同じ主君・同じ守備隊への再任 V1

[実装前計画](PLAN.md)の5条件を実装・検査する。独立した新案件の承諾・許可・現地引受を必要とし、兵・在庫・損耗・全書状の生涯台帳を継続する。

## 完成条件（5件）
1. 終了の実効力と本人の通知開封を分け、元通知または照会の引用で知った終了と実際の返還後だけ、同じ主君に新案件を申し出られる。新しい許可を開かないまま旧許可で兵を受け取らない。
2. 案件IDを区別し、同じ兵・守備隊・所有者・在庫・消費・損耗を引き継ぐ。二回目や三回目で100人・初期兵糧へ戻さない。前案件の返報で新案件を返還済みにしない。
3. 旧原本や未来取消が届いても新案件を動かさない。古い照会にも元案件の状況を返答し、その開封が新案件を閉じない。旧書状・保持者・実経路を廃棄しない。
4. 通常入口から二回の軍務を実際に行い、古い原本と照会の遅着を含む二場面・計42保存点から別プロセスで復旧する。全世界・人物/部隊/伝令・数値姿勢・3D実画像と同じ未来を照合する。
5. 全Coreテスト・代表回帰・実画像と動画・資源解放・現行ソース照合後、同ブランチcommit/pushを行う。未実施を成功に含めない。

## 境界
- CycleContractを新たな再任入力にだけ明示する。旧入力/一案件保存では任意項目を省略し、過去を再解釈しない。
- NewMilitaryTermsの貸与元・所有者・拠点・軍IDは保持する。各RequestのIDを別の案件の起点とする。許可・終了・問い合わせの所属は発生時刻だけでなく、元入力/書状の出典から識別する。
- 資源と兵の計算は全案件の台帳を使い、現在の権限・承諾・返報は現案件だけを使う。古い書状の正式受領と、新案件へ命令を実行する権限は別である。
- 同じ主君/拠点の再任に限定する。別主君からの同時貸与、補充・治療、反復交戦は未実装。演習は一人生一交戦の制約を残し、前の損耗を再任で回復しない。
- 守備隊100人と初期在庫は既存の技術試作条件で、史実人数ではない。全景と重なるラベルは技術用で、最終の認識別可視範囲/HUD品質ではない。
- 22秒・固定60fps動画は二回の軍務と一部の実移動を確認するもので、実時間性能測定ではない。

検証：verify_military_renewal.py → 実画像/復号動画の目視 → --finalize → check_military_renewal_binding.py。過去工程の記録は当時のソースに対する実績。

次の5件：1.本工程の検証/push、2.反復演習を案件と損耗の生涯履歴へ接続、3.認識に応じた表示と対象、4.実在勢力の敵対/許可の接続、5.全国規模の負荷。既存承認範囲で進め、創作上の重要な新判断だけをユーザーへ求める。

未開封書状の選択欄は本人へ提示された差出人と一覧番号だけを使う。内容や結果を開封前に表示しない。照会引用だけを開く検証でも、元通知の開封・認識は追加しない。
