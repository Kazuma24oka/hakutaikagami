## 完成条件5件
1. 版付きInquiryTargetに、本人が知る自隊ID・記録位置・確認時刻・根拠を固定する。選択した本隊/左分隊/右分隊へ共通配送で照会し、その隊が実際に1m以内にいる時だけ正式受領する。現在の真位置へ追尾せず、別隊がいても代わりに受領しない。偽の根拠/版/対象/他操作への流用は原子的に拒否する。
2. 返書は受信した当該隊の兵・位置・状態と、その隊宛の原本記録だけを発送時に固定する。本人が物理的に受け取るまでは知識/普通の表示を更新しない。受領後も当該隊だけを更新し、他二隊の情報を作らない。新しい直接目撃を古い返書で上書きしない。
3. 返書不達の報告は当該隊の既知発送点へ持ち帰り、その隊が実受領してから既存の最大3便/送信者受領証拠で再送する。本隊へ誤送したり、80mの目撃を1mの受渡し証拠に変えたり、原本・保持者・兵を作り直さない。
4. 任意の新項目を省略した旧JSON/旧本隊操作を維持し、入力原判断・配送台帳・観測記録を全ロード時に再計算する。左右と不達の三場面48保存点を別プロセスで復旧し、全世界・人物・宛先/認識・実3D画像と同じ未来を照合する。
5. 追加20件を含む全1795テストと必要な実Godot回帰、実画像/動画、資源解放、ソース/実行ファイルの一致を確認して同ブランチcommit/pushする。完成判定はverification.jsonによる。

## 今回の境界
- 分隊への移動/保持/帰還命令を安全に追加するため、先に受信先と返書の基盤を分けた工程。分隊の移動命令自体や、その取消/再送UIは次工程であり、本工程で完成扱いにしない。
- 新たな名付き武将や兵を生成せず、既存借用部隊の現地受信役を使う。自軍以外の既知対象には照会ボタンを許可しない。
- 保持された不達報告を「本隊の帰還拠点へ戻す」既存操作は本隊向けのまま。分隊向け報告をこの操作で本隊へ移動させない。分隊が元の発送点を離れ、報告自体が不達になった場合の新しい手動転送UIは後続。
- 80m視認/120m演習範囲/600秒の通常原期限は既存の技術係数。最終地形遮蔽・全国負荷・密集ラベルの最終品質の完成を意味しない。
- 新しい録画は試行キー別のフォルダに保存し、以前の試行画像を削除しない。固定60fpsの実移動部分と保存時点のカットは確認用で、実時間性能の測定ではない。

次の5件：本工程の検証とpush、分隊だけへの移動/保持/帰還、分隊別の期限・取消・再送、実在勢力の権限接続、全国負荷。重要な創作判断が必要になるまで継続する。
