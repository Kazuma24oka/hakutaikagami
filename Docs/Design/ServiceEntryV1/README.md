# 通常起動と同一人物の仕官・辞去

ユーザーの入口採用承認を受け、通常起動をNewGameFrontEndへ変更する。旧WorkHub/Mainと旧保存を保持し、明示した旧検証引数は旧入口へ送る。

## 完成条件
1. 通常起動から作成武将・実在武将の既存開始経路が動作する。
2. 現地での申し出、封書の開封、本人回答、相手の物理受領、本人への通知を区別して仕官できる。所属だけで兵・資源・権限を付与しない。
3. 任務の返報が主君に届くまで辞去を待ち、同一人物のまま浪人として移動できる。照会で未開封通知の情報を回復でき、遅着で所属を巻き戻さない。
4. 甲府・小田原・初期家臣の18保存点からの復旧・同じ将来操作で全世界、本人表示、3D画像が一致する。
5. 全単体テスト、既存新規ゲーム7条件、旧軍務の保存復旧を現行実行物で検査し、実画像を確認する。

## 境界
現地の成人勢力代表による募集は試作条件。提示期限120秒は製品調整済み値ではない。役職・領土を持つ人物の単純辞去は不可。主従と所属、個人的随行者、兵・兵糧・役職・領土を分離する。全国の人事AI、給与、出世、新入口での軍務貸与・交戦は次段階。旧軍務は旧入口で維持する。

## 検証の正本
この工程のverification.jsonを現行コードの証拠とする。旧MotionResponseV1等の報告はcommit4856026時点の歴史的証拠として保持し、現行バイナリで全旧77画面を再検査したとは扱わない。今回の範囲は全Coreテスト、既存開始7条件、新仕官3条件、旧軍務の保存画像比較を直接実行する。実測・画像・コードのハッシュを結び、Scripts/check_service_entry_binding.pyで陳腐化を拒否する。
