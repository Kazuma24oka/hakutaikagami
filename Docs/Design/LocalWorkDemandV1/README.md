# 既知の陸路記録に基づく点検の需要

## 完成条件
1. 新DemandPolicyでだけ、依頼主の既知陸路記録がない・古い場合に既存点検を提示する。未知の通行止めや世界の現在真値を読まない。
2. 同じ依頼主・拠点の点検で返報待ちなら重複発注しない。自己点検を既に頼んだ点検と重ねてNPCが新たに開始しない。本人は明示的に相談してから依頼の有無を知る。
3. 記録/報告の認識は前秒までに限り、同秒の後続知識で過去の発注理由を変更しない。記録更新は3600秒の試作値。返報待ちはタイマーだけで失敗扱いにしない。
4. 新旧省略JSON・需要の再発生・失敗返報・不達・改変・保存復旧と実3Dを検査する。旧WorkPolicyの任意反復依頼は旧プロフィールで維持する。
5. Core全試験と実画面/画像/数値の照合後、同じ作業ブランチにcommit/pushする。既存素材/保存と保護枝を維持する。

## 範囲
既存の点検・返報・受領・報酬を再利用する。仕事の種類/報酬/期限・別時計・別配送器は追加しない。NPCの一般戦略AIではない。開いた相談は依頼条件の確認で、相手の通行状況や未受領の記録の内容を本人へ開示しない。依頼主自身の新しい記録が既に揃う場合、仕事が出ないことがある。自主点検/移動/軍務は独立して続けられる。

新しい通常開始だけDemandPolicyを固定。既存QAの旧開始は省略プロフィールを明示的に使い、新需要の実画面QAでは新通常設定を使う。既存保存へ遡及適用しない。

## 次の5作業
1. 現地相談から他拠点への実移動・別の相手への相談まで検証。
2. 需要に沿った仕事数・更新間隔の遊びの感触を確認。
3. 他拠点へ移動して相談する一巡へ展開。
4. 既存の配送/軍務を使う別の需要を段階的に設計。
5. 私財の使途と旅費を扱う段階へ進む。
