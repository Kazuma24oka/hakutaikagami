# 撤退命令原本の保持・実物遅着・受令返書

新規発送時のOriginalPolicyだけで明示保持方式を選ぶ。原命令が不達なら、同じ使者が原本と不達報告を発送元へ持ち帰る。報告が届いたか、原本を保持したか、部隊が原本を正式受領したか、本人が受令返書を知ったかを別々に保存する。旧保存に保持方針や遅着を遡及しない。

完成条件は5件。
1. 実際の往復経路・保持者・紙を記録し、不在時の不達報告も同じ使者の手元に残る。
2. 現地の保持者から、明示した帰還拠点へ原命令を実配送し、部隊の実在所でだけ正式受領する。
3. 原本先着/再送先着/同時到着でも命令効果は一度だけ。新しい現地命令を古い原本で上書きしない。初回不達と本文は不変。
4. 受令返書も同じ使者が実経路で届ける。不達なら保持し、近くで受渡しできる。他の所持紙も同じ使者と移動する。返書前に本人へ実行結果を漏らさない。
5. 保存復旧の同じ未来・実描画座標・実画像の一致、改ざん拒否、旧保存・代表既存回帰を実測し、同ブランチへcommit/pushする。

書状ごとの遅着は共通規則どおり1試行1回。部隊宛先は明示帰還先で、真の現在地を追跡しない。1000mm/最短1秒、士気や再集結係数は試作値。広域ラベルの重なりは表示改善の残課題。今回の入力には撤退命令の期限/取消を追加しない。健康/捕縛/死亡、複数軍務再任、史実の敵対AI、全国負荷は未完了。

verify_unit_command_holding.py → 実画像/動画点検 → --finalize → check_unit_command_holding_binding.py。現行ソース・DLL・全テスト・実画像はverification.jsonへ結び付ける。過去工程は当時の実績。固定60fps録画は性能測定ではない。

次の5件：1.新入口の期限/取消配送と原本遅着、2.軍務再任、3.複数案件の識別、4.観測/敵対に基づく対象、5.全国負荷。判断不要なら段階間で止めない。

実画像で、受領前の使者ラベルから返書の種類を推測できる問題を検出。内容・不達・受令・再送を明かさない中立ラベルへ変更し、実際に未受領/未認識の状態で漏らさない試験を追加。修正前1625件のTRX・DLL・実画像と中断記録はruntime-local/corrections/labels-beforeへ保持し、修正後は全検証をやり直す。3D全景の部隊表示は技術試作で、認識に基づく最終の可視範囲制御は別工程。
