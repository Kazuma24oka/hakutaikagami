# 新規ゲーム・登録武将管理：採用設計と配置契約

2026-10-22。ユーザーは説明画像の6画面、城/町/滞在地点からの操作武将選択、旧大名の明示取り込み、配下を伴う浪人を採用し「進めてください」。画像は見た目の構想で、実装済み画面ではない。

## 採用した画面の順序

1. スタート：新規ゲーム / ロード / 武将作成 / 設定。
2. 新規ゲーム：開始年・シナリオを指定。初回製品1560年、追加年代は後続版を維持。
3. 登録武将：登場なし / グループなしから複数選択 / 一つのグループを選択。
4. 配置：登場場所・立場を照合。大名は新勢力名・本拠・追加の城・旧大名の処遇を確認。競合は修正してから進む。
5. 世界確定：登録武将・勢力・領土・所属・主従を反映。操作人物の選択より先。
6. 操作人物選択：全国から拡大して城/町/滞在地点を選び、そこにいる武将から一人を選択。一覧から名前/能力等でも探し、地図と連動。実在/登録は同じ住人として扱う。選択可能な成人等の条件は既存開始契約に従う。

## 独立した武将管理

武将作成はゲーム開始とは独立。未分類の登録を左約6割、改名可能なグループを右へ縦配置する。登録時に生年（表示上はシナリオ年に応じた年齢）、能力、立場、場所、直属相手、大名なら勢力名の初期値を保存。所属勢力は開始年月日時点の配置から解決する。

グループへは独立IDで複製し、複製元IDは出自情報にする。元の編集/削除にコピーを追随させない。グループごとに能力/年齢/登場城を編集できる。インポートでIDが重複する場合は勝手に上書きしない。外見/画像素材は従来の3D規格を維持し、この契約では能力や外見の製品バランスを決めない。

## 勢力作成と衝突

登録時は希望条件。開始シナリオの城所有者を読み、配置確認で新勢力を組み、世界確定で初期状態に反映する。プレイ中の独立・落城とは別の開始前編集であり、既存I06（一括移転禁止）を緩めない。登録人物は既存人物IDを上書きしない。

大名は一城以上、本拠をその中に含める。複数の登録大名が同じ城を要求したら拒否し、選択順による勝者を作らない。複数城を割り当てた独立勢力にも対応する。

旧勢力に城が残れば旧大名は大名のまま。元本拠が残れば維持、失う場合は残る城から安定したID順で仮の移転先を提案する（戦略AIの最適な本拠選定ではない）。直属随行家臣も移し、一般の城付き家臣はその城の新勢力へ移す。単にLordが同じだけで随行を決めず、PersonalRetainerで城付き/個人随行の関係を明示する。

全領土を失った場合、初期値は旧大名と個人随行の家臣・陪臣が所属勢力なしで残る。主従関係と人物IDは維持。城を失ったことは死亡・消滅を意味しない。「旧大名も家臣として取り込む」を明示した場合は、旧本拠を取得する登録大名へ旧大名が仕え、随行の主従階層は保持。複数新勢力が旧領を分割する場合も、旧大名の受入先は旧本拠の新所有者に一意にする。

客将など他勢力の人物は、その場所にいるだけでは移籍させない。未解決の城外家臣や所属の矛盾は拒否して配置修正へ戻す。捕虜の権利・移送、債務・部隊・外交の移管はこの人物配置だけで自動実行しない。

## 今回の実装境界

Core/Contracts/NewGameSetup.cs は登録ライブラリの検査・独立複製・複数/グループ選択と、開始前の人物/城/勢力の投影を提供する。SetupScenarioはContractWorldではない。Preview→Confirmで元シナリオ/選択内容/確認結果のハッシュを再照合し、設定変更後の古い確認を拒否する。入力は変更せず、結果は独立したコピー。選択0件では元の順序も保持する。

生年と能力は結果にも保持する。登場時点で未出生は拒否するが、成人選択や能力の予算/上限は後続のStartConfigurationとシナリオ方針へ接続する。18歳等の新しい成人年齢を勝手に正式採用しない。任意開始年のこの純粋計算が成功しても、追加年代の史料や製品対応が完成した意味ではない。

現時点では配置GUI/マップ選択/実在人物開始/ContractWorld変換は未接続。管理GUIとライブラリ保存/インポートは後述の独立画面で実装。既存WorldSession/ContractJson/通常起動と旧保存形式は変更しない。この段階の保存復旧とは配置定義のJSON往復であり、3Dゲームの新配置復旧を実証したとは言わない。

## 独立管理画面の追加実装

Game/Scenes/OfficerLibraryTrial.tscn は通常入口とは別の実画面。左6:右4の元登録/グループ一覧、新規登録、生年/能力/立場/候補地/勢力名の編集、グループ追加/改名/独立複製、保存、JSON読込/書出しを実装。外見・直属相手の編集、全国の候補地、開始世界との接続は未接続。現在の候補地3件は著名拠点のラベルで、年代別の支配関係を確定するデータではない。

保存先user://officer-library-v1は既存ゲーム保存と独立。OfficerLibraryStoreは全体を検査し、保存済み内容のハッシュが一致する編集だけを排他ロックと一時ファイル→置換で保存。不正・古い編集・既存ID衝突は元ファイルを維持。ディスク書込失敗の各段階を強制する障害注入は未実施。書き出しは新しいファイルのみ。インポートは原本を移動/削除せず、ID衝突を拒否する。

実Godotのボタン信号で登録→グループ作成→複製→複製の名前/能力を変更→不正入力の拒否、別GPUプロセスで読み戻しを検査。ユーザーのライブラリ/旧保存は試験先に使わない。現状は機能確認用のGodot標準外観で、承認された和紙風の最終画面デザインの完成ではない。

開始前の武将一覧や地図はシナリオ編集用。表示した人物の所在を、開始後の操作人物の知識へ自動登録しない。
