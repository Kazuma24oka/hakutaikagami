# 次工程：本人が知る軍務表示（実装前）

既存の INFORMATION_SYSTEM と RegionalBattle.Sync/View の観測・古い報告の区別を再利用する。80mは既存の地域戦試作係数で、森林・起伏を含む最終視界の確定ではない。新入口に真値の部隊全景を常時表示しない。

完成条件は5件：
1. 表示専用の本人向け投影をCoreに設け、現在の直接観測と、記録済みの過去目撃・本人が開いた照会返書を区別する。
2. 見えなくなった部隊の実座標・残兵・士気・敗走・次秒位置を過去表示から漏らさず、報告時刻・情報源を表示する。古い照会で新しい目撃を上書きしない。
3. 伝令の実位置は既存の近傍視認範囲内だけを描く。未開封の内容や遠隔の実受領結果をラベルへ出さず、技術QA真値と通常画面の表示値を分離する。
4. 新観測保存は明示版だけで有効化し、旧省略形・旧保存を遡及変更しない。途中復旧と同秒の順序・再任・複数交戦の論理IDを保つ。
5. 視認内→視認外→届いた過去報告→再視認を実Godot画面と別プロセス復旧で比較し、単体テスト・必要な回帰・実画像を照合して同じブランチへcommit/pushする。

実装前の注意：現在のTroopSightingは本隊の明示観測と命令宛先証拠である。他分隊や演習相手の観測を同じ配列に混ぜない。新しい表示観測を命令の宛先権限に自動転用しない。全知のCourierFramesやExerciseStateはシミュレーション/診断用に保持し、通常表示用の観測投影からは露出しない。

新しい観測を履歴として残す場合は入力版・JSON省略・BeforeState・再実行検証・trustedPriorの全経路に組み込む。UIだけのキャッシュを保存復旧の根拠にしない。観測開始前の架空の記憶は補完しない。

次の5件：反復演習を検証確定・push／本人向け表示投影／既知対象選択／実在勢力の敵対・許可／全国負荷。
