# 本人の目撃・返書による軍務表示 V1

[実装前計画](PLAN.md)と[漏れ点の調査](implementation-notes.md)を踏まえる。真の位置/損耗と、本人が実際に知った位置/人数を分ける。

## 完成条件5件
1. 明示したObservationPolicyの開始以後、本人が直接観測した部隊だけを記録し、現在視認・時刻付きの過去目撃・本人が認識した本隊返書を区別する。通常返書の受領認識と重要書状の開封認識を既存MessageFlowで扱う。
2. 非視認の部隊の真位置/次秒位置/人数/士気/行動を通常表示へ漏らさない。遠い部隊は最後に知った静止位置の印にし、古い返書で新しい直接目撃を上書きしない。受信役0の返書を左右分隊へ転記しない。
3. 近傍の使者だけを不透明IDと中立名で描く。本隊モデル/兵糧/演習相手にも同じ可視判定を用いる。全隊の正確な即時報告・配置/保持・演習開始は現在三隊を確認できるときに限定し、未知の真士気から操作候補を漏らさない。帰還伝令・現地1m受渡し・既知宛先証拠を視認と混同しない。
4. 観測を状態確定と同じ番号で保存し、旧任意項目の省略・観測開始以前の旧保存を維持する。欠落/改ざんを拒否し、32保存点を別プロセスで復旧して全世界・投影/実モデル/3D画像と同じ未来を照合する。
5. 全Coreテスト・適切な実GPU回帰・動画/実画像・資源解放・現行ソースと実行ファイルの照合後、同ブランチcommit/pushする。

## 既存規則との接続
- 80mはRegionalBattleの既存試作係数で、山/森林の遮蔽や製品視界の確定ではない。カメラの位置/全国表示から観測記録を増やさない。
- 自動観測はWorldSession.Changeの位置同期後・検証前に記録する。画面内だけのキャッシュを保存の根拠にしない。全ロードは各記録時点の世界から再計算し、観測専用の分岐で書換対象のMessagingだけを複製する。従来の完全複製と同じ観測になり元世界を変えないことを比較検査する。実行中は検証済み履歴の接頭一致を要求する。
- 新規申出は版を明示。旧進行は「現地の部隊観測を開始」でその時点から移行できる。以前の架空の記憶を補完しない。未開始の旧表示は技術表示と明記する。
- 新しい観測を元のTroopSightingや受令の証拠にしない。受領/不達/返書の前工程の物理規則を保持する。
- 視認できない隊を含む曖昧な現況返報や、分隊へ個別の配置命令を物理配送するUIは次工程。正確な全隊返報は現地で確認後に行える。最終の指揮自由度/数値バランスをこの制限で確定しない。
- 保存量・観測履歴の長期保持と全国規模の負荷は後続の実測対象。近傍の二場面が動くことだけで全国性能を合格にしない。

次の5件：本工程の実画面/保存検証とpush、既知対象選択、分隊への物理命令、実在敵対/許可への接続、全国負荷。
