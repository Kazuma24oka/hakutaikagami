# 交戦任務の配送と本人開封（2026-10-26）

## 今回の作業単位：4/4

1. 通常の軍務で、実在の主君の発令根拠と同じ主家/軍/部隊/対象勢力/期限を固定した交戦任務の原本を発行する。
2. 相談、主君への実配送、許可通知、本人の開封、取消通知を区別し、未開封や他案件から許可を借用しない。
3. 通常画面から対象勢力を選び、書状で条件と取消を確認できる。未確認の許可/取消内容を先に表示しない。
4. 配送中・未開封から世代保存を復旧・続行し、世界と実際の画面が一致する。

この部分は実装/確認済み。BD-39の任務→実戦→撤退→返報という工程全体は0/3のまま。敵対関係の世界状態、敵軍の実移動、実戦の損害/撤退/返報への接続は未完了。条件付き許可を開戦や戦勝と読み替えない。

## 実装

- `RequestEngagement`は相談を既存の伝令経路で送る。主君は受領時点の所属/役職/現地支配/主従/貸与指揮/期限を照合して許可または拒否を返信する。
- 条件は通知原本に固定する。既存の移動/待機/撤退用の指揮権に攻撃を混入しない。部隊や兵数を生成しない。
- 発令判定は、主君が権限を持つ拠点にいる既存の基準を使う。戦地の大名本人による新しい発令などは今回の確認範囲外で、将来の野戦指揮権と現地引受の権限を混同して広げない。
- 本版は本人開封が効力条件。配送の正式受領だけでは本人の攻撃許可にならない。効力は指定時刻・発令時刻・本人開封のすべてを満たした時点から、期限未満で成立する。
- 取消も主君への相談→取消通知→本人開封を経る。同一案件の原本だけを対象にし、取消より後に原本を開いても攻撃許可は復活しない。不達だった元の相談が取消後に再送されても、新しい許可を発行しない。
- 照会への返書は原本条件を引用する。許可/取消の原通知を開けなくても、届いた照会返書を本人が開封すれば確認できる。
- 再入力は同一IDなら重複受理、同一IDで条件が異なる場合は拒否。既存の保存には新しい任意項目を書き込まない。
- 通常の軍務欄から対象勢力の小窓（540×260）を開く。許可と取消は既存の下部会話へ表示する。

## 続く実装

対象勢力の名前や同じ城の所属だけで敵対を決めない。まず実際の敵対関係と、それを本人が知っているかを分けて世界へ持たせる。次にNPC軍が所有拠点から同じ地図の経路を移動し、実際に接触して損害/撤退/返報へつながるようにする。現在の120mの配置試行を、全国遠征や既存の演習敵の改名で代用しない。

基本設計の終了条件と順序は維持する。最小の実戦一巡がつながったら地域経済へ渡し、攻城/兵種/全国補給/全面的な政治処分に横展開しない。mainへの新規統合は別承認。
