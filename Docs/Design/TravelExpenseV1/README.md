# 旅費と徒歩移動の維持（L3）

2026-10-25、ユーザーは「金欠でも徒歩移動できる」を採用。金欠で徒歩や仕事探しを禁止しない。以下の完成条件で実装・検証する。実測はverification.jsonとRESULT.mdへ記録する。

## 完成条件（5）

1. 新しい開始プロフィールだけに版付き船賃規則を持たせ、旧開始・旧保存の省略形と無課金動作を保つ。
2. 船賃は実際の出航時に一航程一回だけ支払う。港待機・出航前取消・運休には課金しない。不足なら現地の港に留まり、徒歩での移動や別の仕事を妨げない。
3. 船を使わない陸路を選べる。経路選択は既知の道路情報と本人の所持金だけから行い、遠方の封鎖を漏らさない。
4. 本人の私財、預り金、軍務資産を分け、支払先の受取勘定も履歴に残す。未収録の運航者の経営を実装済みとは呼ばず、受取額を外部勘定として数量保存へ含める。
5. 仕事の収入→移動/船賃→次の仕事/軍務→帰還の流れと、出航前後・金欠停止・取消の保存復旧と実3D表示を検証して同枝pushする。

初期の船賃は調整可能な試作値。歴史的な料金の確定ではない。宿泊・市場・疲労・負傷回復をこの段階で完成済みにしない。まず海路の有料サービスを接続する。料金のためにUIの時間操作を有料化せず、徒歩を裏で減速・禁止する規則も追加しない。


## 今回の実装範囲

標準の試作船賃は1航程10文。新規開始のVoyageRulesで版と料金を固定する。金欠検査だけは明示したテスト用1000文のプロフィールを使う。通常プレイの新規開始は10文であり、高額テストを既定値へ混入しない。

実出航の時刻に本人の財布から支払う。未収録の運航者は航路ごとの受取勘定IDを持ち、金額を保存する。本人・他人の財布/預り金と受取勘定の合計を検査し、消えた支出や二重徴収を認めない。運航者の経営・船モデル・宿泊・市場・軍勢/使者の運賃は今回の完成対象ではない。

陸路限定の指定は元の移動原本に記録し、途中の行先変更・迂回でも海路へ勝手に変えない。通行止めの情報と「船を使わない」という本人の選択は別に保持する。海を徒歩で渡れる扱いにはしない。
