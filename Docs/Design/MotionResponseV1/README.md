# 動作の滑らかさ・操作応答 V1

2026-10-22。Godotを維持し、エンジンの変更を前提にせず実測して調整する承認。

## 完成条件
1. 同じ1280×900/RTX4060Ti/OpenGLの近距離・同じ開始人物/経路で、変更前3回、変更後3回、60fps制限3回を記録。録画速度と実測を混同しない。
2. 60fps制限で各10秒以上、描画間隔p95が20ms以下・p99が33.34ms以下、12回のボタン信号から描画完了まで50ms以下を目安とする。製品全体の保証/業界共通基準ではない。
3. 地形区画の境界と保存復旧を検査。Coreの移動速度・時刻・知識・保存形式は変えず、世界と3Dが一致する。足運びは表示上の移動距離と素材の歩幅へ結合する。
4. 現行テストと旧入口/新入口の復旧比較を通し、実際の60fps描画フレームから作った動画を目視確認する。

## 調整
新入口NewGameRuntimeだけを変更。80m区画の地形頂点を固定原点で再利用し、追従中は地形ルートだけを移動。隣区画/表示幅変更時に更新する。選択用の地形面は新入口では使用していない。共有地形判定/旧入口は変えない。

表示用世界コピーと本人のViewを、同じSession/Revision/秒/停止状態で再利用。別保存への切替は同じRevisionでも別Sessionとして必ず無効化する。内部コピーをCoreへ書き戻さない。位置は既存の次秒への補間を維持。

足運びは元アニメーションの測定歩幅×モデル倍率に合わせ、経路の画面上の累積距離から位相を算出。世界の移動所要時間やキャラクターのゲーム上の速度は変えない。高速時間倍率ではその倍率で動く。

## 計測の意味と限界
計測は読み込み/素材生成の2秒の予熱後、各10秒。無制限の計測は処理余裕を見るため、VSyncを試験プロセスだけ無効化。60fps制限は同じ試験プロセスだけに設定し、通常の起動設定は変更しない。UI反応は実Button信号→次のFramePostDrawであり、物理マウス/液晶までの総入力遅延ではない。OSポインター/権限は操作しない。

baseline-runtime.cs.txtはf43e1eeの調整前Runtime、baseline-harness.cs.txtは当初の計測コード。調整前バイナリそのものは保存していないため、完全なバイナリ再現比較とはしない。変更後の計測はmeasurement-manifest.jsonで実行DLL/ソースを記録。Performance.TimeProcessは今回の壁時計フレーム間隔と異なる値を示すため、CPU専用時間と解釈しない。判断は実際のFramePostDraw間隔を使う。

短時間の最大値と50ms超過も隠さず記録する。平均/中央値だけで無停止や全国負荷を保証しない。全国大量人物、別GPU、製品版の背景品質、長時間の入出力/GC負荷は別段階。今回の合格はこの局所場面でGodotを変更する必要が認められない、という範囲。

動画は--fixed-fps60で480枚を取得し60fps/8秒で符号化。実測FPSの証拠は別の無制限/60制限のJSON。動画の撮影自体にかかる実時間を性能値に使わない。

## 今回の実測（同じPC・局所場面）

| 条件 | 描画間隔の中央値（3回の中央値） | 補足 |
|---|---:|---|
| 調整前・無制限 | 15.2011ms | 約8.46MB/描画の一時割当 |
| 地形再利用後・無制限 | 約6.51ms | 表示コピーの毎フレーム生成は残る |
| 両対策後・無制限 | 1.2105ms | 約0.485MB/描画、一時割当は約94%減 |
| 両対策後・60fps制限 | 平均16.70ms前後 | p95=17.00～17.10ms、p99=29.31～29.55ms |

60制限のボタン→描画は全36回で最大16.87ms。1797描画中、50ms超過は3回、各試行の最大65.95～71.82ms。停止のない製品性能を達成したとはしない。高負荷になる世界進行処理や入出力の長時間計測は後段で必要。今回の近距離表示ではGodotを維持して改善できた。
