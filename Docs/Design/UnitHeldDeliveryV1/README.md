# 保持原本の実物受渡し

本人退避・部隊撤退の分離を維持し、使者が保持した返書と未受領不達報告を現地から届け直す。近くの本人が静止している場合だけ操作でき、本人用の返書受取と、受信役のいる明示帰還先への報告移送を分ける。同じ使者の紙は全て同じ実経路で動く。報告の移送だけで本人は返書を知らない。

完成条件は次の5件。
1. 実保持者・紙・現在地を根拠にし、遠隔の紙や未知の現位置から受渡しを捏造しない。
2. 原本と再送分のどちらが先でも正式受領・知識・命令効果は一度だけ。初回不達と本文は変更しない。
3. 不在なら受渡しを拒否し紙は残る。不達報告は受信役への実到達後にだけ再送根拠になる。
4. 入力直後・移送中・到達後の保存復旧と同じ未来、実3D座標・表示が一致し、改ざんは拒否する。
5. 全単体テストと代表的な既存画面・地形回帰を実行し、画像確認後に同じブランチへcommit/pushする。

共通配送の既存規則に合わせ、1試行の実物遅着は1回だけ。受渡し失敗後の無制限な再予約、原命令の物理保持回収、一般人物の捕縛/死亡、複数軍務の再任はこの工程の実装済み範囲ではない。旧保存へ自動遅着を遡及しない。試作の1000mm受渡し距離・最短1秒は調整済み値ではない。

検証手順：verify_unit_held_delivery.py → 実PNGと動画の点検 → --finalize → check_unit_held_delivery_binding.py。実測とソース・DLL・テスト・画像の対応はverification.json。過去工程の成功数を現在の実行物の成功と読み替えない。動画は固定60fpsの動作確認で性能測定ではない。

次の5件：1.原命令自身の保持と遅着回収、2.新旧命令・取消・期限との競合、3.軍務再任と複数案件、4.認識/敵対に基づく対象、5.全国規模の負荷。技術的な検証は判断不要なら継続する。
