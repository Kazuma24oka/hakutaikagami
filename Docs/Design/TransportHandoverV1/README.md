# 運搬の受渡し条件 V1（L1）

## 固定する境界

荷主・運ぶ本人・受取人・元拠点・先拠点・元の在庫ID・資源と単位・数量・所有者・受諾期限・受渡し期限・報酬を原契約で固定する。第三者所有物の権限と売買による所有権移転はこの契約へ混ぜない。所有は荷主のまま、保管だけ荷主→本人→受取人へ動く。

受諾→現地引受→現地受渡し→荷主への報告→報酬受領を別処理にする。報酬債務は報告を荷主が認識してから。期限の瞬間まで受渡し可、超過後は返却。期限切れで現物を消さない。引受前の取消は終了、引受後の現地取消は返却義務を残す。遠隔取消・損失・死亡・部分運搬・数量変更・売却は専用の後続契約まで不可。

現地引受/受渡し/返却/支払には現物台帳の一意な取引IDが必要。同ID同内容の再送は履歴を増やさず、内容違い・同取引の再利用・古い版での新操作を拒否する。時刻が同じなら保存された版順で確定する。

## 完成条件（5）

1. 固定契約と各段階、数量・所有・保管・債務の意味が機械検査できる。
2. 期限境界と取消・返却が現物を消さず一意に遷移する。
3. 再送・古い操作・別人/別拠点・履歴改変を拒否する。
4. 全段階を実ファイルへ保存し、復旧後の履歴と続行結果が一致する。
5. 証跡と進捗表を更新し同枝へcommit/pushする。

## L1の検証範囲

TransportHandoverは契約の純粋な状態遷移器。受渡し入力は現地性や在庫取引の宣言であり、この単体だけでは本物の取引と認証しない。L2のWorldSession接続で現世界から位置・人物・在庫・権限を検査し、一つの原子的変更として現物台帳と同時記録する必要がある。現段階で有償運搬がゲームから遊べるとは扱わない。旧ゲーム世界・セーブ形式・兵糧引受・点検報酬は変更していない。

ContractJsonの厳密形式で全受渡し履歴を保存し、復旧時は先頭から再生して検証する。保存ファイルのチェックサムを置き換えた敵対的な全履歴の再捏造への認証ではない。既存GenerationSaveStoreとの世界全体保存・3D照合はL2の完成条件。
