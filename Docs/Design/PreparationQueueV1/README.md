# 私有計算の直列実行 V1

通常命令のCore基盤の次に、画面接続前の競合を固める。開始停止の私有計算を取り消してメニューへ出た後、古いworkerがまだ終了していないうちに再入場できる。結果の世代判定は維持しつつ、実行中の私有計算も一runtime一つに限定する。

完成条件5件：
1. 先行進行・開始停止・手動進行・保存準備と、受入済み世界の既存保存writerを同じ管理キューに通す。取消済みの待機処理は実行せず、古い計算が残っていても次のCore処理を同時実行しない。worker内でGodotを操作しない。
2. メニューで切り離した処理も追跡し、runtime破棄後は全処理の終了を待って管理資源を解放する。受入済み保存writerの既存原子公開は途中取消しない。公開先の世代一致や既存入力ロックを変えない。
3. 古い計算を保持したまま即再入場し、開始停止/手動進行/保存を要求する3ケースと、別の実runtimeを保持workerの途中で破棄するケースを検証。最大同時実行1、現在世界/旧保存不変、待ち解除直後の最初の公開結果、終了後解放を実測する。8追加保存点を別プロセスで復旧。
4. 42現行GPUプロセス/118世界画像・数値比較。旧workerの取消・失敗・保存書込失敗・速度変更・重要通知・通常入口も選んで再実行。Core不変306入力/TRX/DLL完全一致時だけ全2076試験を再利用。過去8/40回や共有renderer/旧入口9回を今回再実行と数えない。
5. 実画面と実ログを点検し、現行ソース/バイナリ/証拠/実コミットを照合して同枝commit/push。主枝/設計枝と既存素材を維持する。

4新ケース8プロセスのうち破棄試験の2プロセスは、保持中に実Nodeを破棄する別runtimeも作る。試験プロセス数とruntime数を混同しない。1000静止人物+本人が対象で、全国同時行動や固定fpsを保証しない。UI通常命令の非同期接続は次工程。
