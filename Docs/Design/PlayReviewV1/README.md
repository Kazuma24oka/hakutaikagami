# 連続操作と確認映像 V1

技術確認の次に、操作のまとまり・情報量・一人の武将としての見え方をユーザーが判断できる材料を用意する。通常ゲームの処理やCoreを変更せず、QA用の連続操作と録画・照合を追加する。

完成条件5件：
1. 通常の新規ゲーム入口から信繁を選び、現地相談→封書到着による停止→開封→仕事/返報→保存/ロード→出発→全国/近景→歩行を実コントロールで続ける。全体停止・同じ人物・自分の履行を検査する。
2. 最後の実保存を別プロセスで開き、記録した実際の自動進行対象時刻を同じ順に与える。全世界/説明/3D画像2組と数値2組を完全一致させる。保存前に作った未来の私有結果を動画やロードへ混ぜない。
3. Godot内蔵の固定30fps録画を使い、実時間同期が無効であることを字幕・記録に明記する。実時間のfps/受付時間/エンジン比較の測定とはしない。全フレームをデコード検査し、主要フレームを直接目視する。
4. 録画専用の複製は実コード/シーン/データ/Game+Core DLLをバイト照合し、viewport幅/高さだけ1280x900へ変更する。実プロジェクトの設定は維持する。Core317入力/TRX/DLLが完全一致する時だけ直前の2122件を再利用。今回GPUは録画・復旧の2プロセスで、以前の46回を再実行と数えない。
5. 実映像・証跡・実コミットの一致後に同じ枝commit/push。main/designと既存素材/保存を保護し、次のユーザー判断は技術設定でなく、操作のまとまり・情報量・好みの確認とする。

## 録画方法と限界

PNG連続保存は録画自体の負荷で低フレームになったため、Godot --write-movie/--fixed-fps30を使用する。MovieMakerは設定上のviewport寸法を使うため、元設定1100x720のまま1280x900のウィンドウを録ると画面が切れた。実設定を変えず、実行物を照合した録画用コピーでviewportだけ合わせる。マウス/OS設定は操作しない。

MP4はGodotのAVIから補間・速度変更なしで符号化する。録画用の固定時刻映像なので、処理の速さを示すものではない。実時間のフレーム観測や受付・確定の別測定は以前の工程の別証跡を参照する。

通常入口の実装には、TestKey付きの検査時だけ使う分岐を追加する。新しいゲーム機能やCoreの変更は行わない。録画コピーのソース/バイナリ/設定差分と、元設定が変わらないことを検査する。

次の五件：映像/復旧照合とpush、ユーザーによる操作のまとまり確認、情報量/案内の調整、NPCの認識した必要に基づく次の判断、全国データと負荷の拡張。技術判断はCodexが担当し、創作上の確認だけユーザーに残す。
